# 6.4 Memory 三层架构（Agent 的记忆系统）

> **为什么重要**：小米的 JD 直接把"Agent Memory"单独列为研究方向；百度/DJI 的 JD 都要求长期记忆。
> **你的处境**：你有**任务内的结构化工作记忆（证据状态）**，但**没有跨会话长期记忆** —— 这篇会给你"能讲体系 + 诚实划边界"的组合。
> **标注**：`★★★`

---

## 1. 30 秒口述版

:::card 30 秒版
「LLM 的上下文窗口不是记忆 —— 它会满、会被截断、跨会话就没了。所以 Agent 需要**外置记忆**。

我按三个层次理解：

**① 工作记忆**：当前任务内的状态（做到哪了、已知什么）。**必须是结构化的**，因为调度逻辑要能查询它。
**② 语义记忆**：从交互中抽取的**事实**（用户偏好、项目背景、领域知识）。可检索、可更新。
**③ 情景记忆**：历史事件与轨迹（"上次这个任务是怎么做的、在哪儿失败的"）。用于复盘和复用。
（有些体系还会加**程序性记忆**：可复用的流程/skill，本质是"把成功轨迹固化成模板"。）

核心难题有四个：**什么时候写**（不能什么都记）、**怎么检索**（相关性与时效）、**怎么冲突**（新旧矛盾听谁的）、**怎么忘**（容量有上限）。

我的项目里有**任务内的工作记忆**（证据状态：覆盖率、冲突、预算），但**没有跨会话长期记忆** —— 这是我要补的。」
:::

---

## 2. 为什么"上下文"不等于"记忆"

:::card 三个结构性差异
| 维度 | 上下文窗口 | 外置记忆 |
|---|---|---|
| 容量 | 有限（且越用越贵） | 可扩展到磁盘/向量库 |
| 生命周期 | **随会话结束消失** | 跨会话持久 |
| 可查询性 | 只能"读全文"，不能结构化查询 | 可按字段/时间/相似度检索 |
| 可更新 | 只能追加/截断 | 可修改、可删除、可合并 |

**一句话**：「把历史全塞进 context 是**假记忆** —— 它既贵又不可查询，还会因为 lost in the middle 而失效。」
:::

---

## 3. 四种记忆类型（三层 + 程序性）

:::card 逐层说清"存什么、怎么用"
| 类型 | 存什么 | 典型实现 | 用在哪 |
|---|---|---|---|
| **工作记忆**（working） | 当前任务状态：子目标、进度、预算 | 结构化对象 / 黑板 | 循环控制的依据 |
| **语义记忆**（semantic） | 事实：用户偏好、实体属性、领域知识 | 向量库 + 结构化字段 | 回答时补充背景 |
| **情景记忆**（episodic） | 事件与轨迹：某次任务怎么做的、失败原因 | 向量库（带时间戳）+ 事件日志 | 复盘、相似任务复用 |
| **程序性记忆**（procedural） | 可复用的流程/skill | 提示模板 / 子图 / 代码化 skill | 直接复用成功路径 |
:::

:::card 为什么这个分类有用（面试加分）
因为它回答了"**该把东西存在哪**"这个工程问题：
- 「用户说他偏好简洁回答」→ **语义**（一条事实，要能被检索到）
- 「上次修复这个 bug 时，先查日志再改配置成功了」→ **情景**（一条轨迹，用于复用）
- 「我们的部署流程是 A→B→C」→ **程序性**（一个流程，可以固化成 skill）
- 「当前任务已经查完了 3 个子目标」→ **工作记忆**（状态，任务结束就丢）
:::

## 4. 写入策略（**最容易被忽略、也最容易翻车**）

:::card 什么时候写、写什么
| 策略 | 做法 | 风险 |
|---|---|---|
| **每轮都写** | 把每次对话压缩成事实入库 | 噪声爆炸、检索质量崩 |
| **会话结束写** | 结束时统一抽取摘要 + 事实 | 会丢失过程中的关键决策 |
| **事件触发写**（推荐） | 只在"发生重要变化"时写：用户明确说了偏好、任务失败且找到原因、出现纠正 | 需要定义"什么算重要" |
| **模型主动写**（tool 化） | 给模型一个 `save_memory` 工具，让它自己决定 | 模型可能滥用/漏记 |
:::

:::card 写入时必做的三件事
1. **去重与合并**：同一条事实不要存 10 遍（用相似度阈值 + 覆盖）
2. **带元数据**：时间戳、来源（哪次对话）、置信度、作用域（用户级/项目级/全局）
3. **可撤销**：写错了要能删（用户在意的"隐私与纠错"能力）

**面试话术**：「记忆系统最大的坑不是"记不住"，而是"**记错了还一直用**"。所以写入必须带去重、置信度和可撤销机制。」
:::

## 5. 检索策略（不是纯向量就够）

:::card 四种信号组合
| 信号 | 作用 |
|---|---|
| **语义相似**（向量） | 找到"相关"的记忆 |
| **时间衰减** | 越久远权重越低（很多偏好会过时） |
| **结构化过滤** | 按用户/项目/类型过滤（不能把 A 用户的偏好给 B 用） |
| **重要度 / 引用频次** | 常被用到的记忆权重更高 |

**常见错误**：只用向量检索 → 召回了"语义相关但已经过时"或"属于别人"的记忆。
**正确做法**：`score = 相似度 × 时间衰减 × 类型权重`，并且**先做权限/作用域过滤，再做相似度排序**。
:::

## 6. 冲突处理（记忆系统的真难点）

:::card 新旧记忆矛盾时听谁的
| 策略 | 适用 |
|---|---|
| **时间优先**（新的覆盖旧的） | 偏好类（用户口味会变） |
| **置信度优先** | 有明确来源可信度时 |
| **版本化保留 + 检索时按需选** | 事实类（不知道哪个对，先都留着，让模型看到冲突） |
| **显式询问用户** | 高价值、冲突明显时（最安全） |

**加分句**：「我会**保留冲突而不是静默覆盖** —— 因为记忆冲突本身是有信息的（说明这件事不稳定）。检索时把两条都放进上下文并标注时间，让模型知道存在矛盾，比悄悄选一个更安全。」
:::

## 7. 压缩与遗忘

:::card 三种手段
1. **摘要**：多条相关记忆合并成一条概括（降低存储与噪声）
2. **分层摘要**：单条 → 每日/每周汇总 → 主题级，检索时按需下钻
3. **遗忘曲线**：长期未被检索且低置信度的记忆降权/淘汰

**为什么必须遗忘**：容量、成本、以及**噪声** —— 记忆越多，检索准确率越低（和 RAG 一样，信噪比问题）。
:::

## 8. 两个代表性方案（知道思路就够）

| 方案 | 核心思想 |
|---|---|
| **MemGPT / Letta** | 把记忆做成**分层（主上下文 / 外部存储）+ 分页**，模型通过工具主动"换页"（像 OS 的虚拟内存） |
| **A-MEM** | 记忆之间**建链接**（Zettelkasten 式笔记网络），检索时沿链接扩展，而不是纯向量 |

**面试一句话**：「MemGPT 的思路是"**把上下文当内存、把外部存储当磁盘**，用工具换页"；A-MEM 的思路是"**记忆不是孤立条目，而是有链接的网络**"。」
:::

## 9. 记忆系统的评估（很少有人答得上，答了是加分）

:::card 四个指标
| 指标 | 量什么 |
|---|---|
| **命中率（Recall）** | 需要某条记忆时，检索能召回吗 |
| **精度（Precision）** | 召回的记忆里有多少真的相关（噪声比例） |
| **写入精度** | 存进去的事实是否正确（错的记忆比没有更糟） |
| **污染率** | 错误记忆被复用的比例 —— **最关键** |

**怎么测**：构造一批"需要用到历史信息"的任务，人工检查模型是否用对了记忆；并且**故意注入错误记忆**看它会不会照用（这是记忆系统最重要的鲁棒性测试）。
:::

## 10. 【挂点】你的证据状态怎么映射成 Memory

:::card 映射表
| Memory 概念 | 你的实现 |
|---|---|
| **工作记忆** | **证据状态**（子目标覆盖、证据池、冲突表、预算） |
| **程序性记忆** | 你的**策略层**（直接检索/改写/对抗/消解，是可复用的流程模板） |
| 语义记忆 | ⚠️ 你**没有**跨会话事实库 |
| 情景记忆 | ⚠️ 你只记录任务内证据，不保存跨任务轨迹 |

**诚实话术（背下来）**：
> 「我有**任务内的结构化工作记忆**（证据状态），并且把"可复用流程"固化成了策略层，这部分相当于程序性记忆。
> 但**跨会话的语义/情景记忆我没有做** —— 我没有记忆写入策略、没有冲突处理、没有遗忘机制。这是我和生产级 Memory 系统的主要差距。」
:::

## 11. 十个追问预答

:::qa 为什么不能把历史对话全塞进 context
三个原因：容量有限且成本线性增长；**lost in the middle** 导致中间信息利用率低；**跨会话就丢了**。所以需要外置 + 结构化 + 可检索。
:::

:::qa 三层记忆分别存什么
工作记忆（任务状态，任务结束即弃）、语义记忆（事实，可检索更新）、情景记忆（事件与轨迹，用于复盘复用）。部分体系还有程序性记忆（可复用流程）。
:::

:::qa 什么时候该写记忆
**事件触发**最稳：用户明确表达偏好、任务失败并找到原因、出现纠正。不要每轮都写（噪声爆炸），也不要只在会话结束写（丢关键决策）。
:::

:::qa 记忆冲突怎么处理
四条按场景选：时间优先（偏好类）、置信度优先（来源可靠时）、**版本化保留 + 检索时呈现冲突**（事实类，最安全）、高价值时直接问用户。关键是**不要静默覆盖**。
:::

:::qa 记忆检索和普通 RAG 检索有什么不同
多了三个维度：**时间衰减**（偏好会过时）、**作用域过滤**（必须是当前用户/项目的）、**重要度权重**（常被用到的更重要）。而且**过滤要在排序前做**。
:::

:::qa 记忆污染了怎么办
三层：① 写入时去重 + 置信度 + 来源标注；② 检索时呈现冲突而非静默选一个；③ **提供撤销/纠正入口**（用户能改），并定期抽检。
:::

:::qa 怎么评估一个记忆系统
命中率、精度、**写入精度**、**污染率**。最关键的测试是"注入错误记忆看它会不会照用"。
:::

:::qa MemGPT 的核心思想
把上下文当"内存"、外部存储当"磁盘"，通过工具**主动换页**（把不常用的摘要化/移出，需要时再取回）。本质是 OS 虚拟内存思想。
:::

:::qa 记忆会不会拖慢 Agent
会。检索本身有延迟，而且加进上下文会增加 token。所以要：**按需检索**（不是每轮都查）、**控制条数**、**缓存高频记忆**、**异步写入**。
:::

:::qa 【挂点】你没有跨会话记忆，怎么答
按 §10 的话术：说清你有**任务内工作记忆 + 程序性记忆（策略层）**，但没有语义/情景记忆、没有写入策略与冲突处理。**然后补一句你知道难点在哪**（写入时机、冲突、遗忘、污染），显示不是没想过。
:::

## 12. 陷阱

| ❌ 别这么说 | ✅ 换成这么说 |
|---|---|
| 「记忆就是把历史存下来」 | 「记忆要**结构化、可检索、可更新、可遗忘**，否则就是噪声」 |
| 「有上下文窗口就够了」 | 「窗口不是记忆：会满、会丢、跨会话消失、不可查询」 |
| 「记忆越多越好」 | 「记忆越多信噪比越低，**遗忘是必需功能**」 |
| 「冲突时用新的覆盖旧的」 | 「事实类冲突应**版本化保留**，让模型看到矛盾更安全」 |
| 「我有长期记忆」 | 「我有任务内工作记忆（证据状态），跨会话记忆没做」 |

## 13. 自测（6 题）

:::qa 为什么上下文窗口不是记忆
容量有限且贵、随会话消失、不可结构化查询、受 lost in the middle 影响。
:::

:::qa 四种记忆类型各存什么
工作（任务状态）、语义（事实）、情景（事件轨迹）、程序性（可复用流程）。
:::

:::qa 推荐的写入策略是什么，为什么
**事件触发**（重要变化时写）：避免每轮写的噪声爆炸，也避免只在会话结束写而丢失关键决策。
:::

:::qa 记忆检索比普通 RAG 多了哪些信号
时间衰减、作用域过滤、重要度/引用频次；且过滤要在排序前。
:::

:::qa 记忆冲突的四条处理策略
时间优先、置信度优先、版本化保留并呈现冲突、直接询问用户。
:::

:::qa 评估记忆系统最关键的测试
**注入错误记忆，看它会不会照用**（污染率）—— 错的记忆比没有记忆更危险。
:::
