# 4.6 采样与解码策略（temperature / top-k / top-p / 约束解码）

> **为什么单独一篇**：采样参数是"最常被问、最容易答错"的一类问题（比如"top-p 和 top-k 的区别"、"temperature 调 0 是不是确定性"）；而且**约束解码**直接决定工具调用能不能稳定输出 JSON。
> **和第 9 号新高频的关系**：§9.3 提过"结构化输出"，这篇展开讲实现原理。
> **标注**：`★★☆`

---

## 1. 30 秒口述版

:::card 30 秒版
「解码就是在每一步从一个概率分布里选下一个 token，策略分两大类：**确定性**（贪心、beam search）和**随机性**（采样）。

采样有三个常用旋钮，作用对象不同：
- **temperature**：先把 logits 除以 `T` 再 softmax —— `T<1` 让分布更尖（更保守），`T>1` 让分布更平（更发散）
- **top-k**：只保留概率最高的 **k 个**候选
- **top-p（nucleus）**：保留**累积概率达到 p** 的最小候选集合 —— 它的候选数是**动态的**，分布尖时候选少、平时候选多

工程上一般**组合使用**：先 temperature 调分布形状，再 top-k/top-p 截断。顺序很重要（先截断再调温度会改变语义）。

另外还有个高频考点是**约束解码**：通过**给非法 token 的 logits 打 `-inf`**，强制输出符合语法（如 JSON schema），这是 Function Calling 能稳定工作的底层保证。」
:::

---

## 2. 贪心 vs 采样

:::card 两类策略
| 策略 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **贪心（greedy）** | 每步取 argmax | 确定、可复现 | 容易重复、死板、错过更好的整体序列 |
| **Beam Search** | 保留 `k` 条最优前缀 | 序列级更优（适合翻译） | 计算 `k` 倍、输出保守/单调、缺乏多样性 |
| **采样** | 按概率随机抽 | 多样、自然 | 不可复现（要固定 seed）、可能跑偏 |

**为什么开放生成少用 beam search**：
1. 它是**最大化整体概率**，而"概率最高的句子"往往是**最平庸/最重复**的（"我不知道我不知道…"这类）
2. 成本 ×k
3. 对话/创意写作需要多样性，beam 会收敛到同一个答案

> **一句话**：「Beam search 适合**答案相对确定**的任务（翻译、摘要），开放生成用采样。」
:::

## 3. Temperature（温度）

:::card 公式与效果
```
p_i = softmax(z_i / T)
```
- `T = 1`：原始分布
- `T < 1`：分布更**尖**（高概率 token 更高）→ 更保守、更确定
- `T > 1`：分布更**平** → 更随机、更容易出意外
- `T → 0`：退化为**贪心**（argmax）

**直觉**：温度是"概率的锐度旋钮"。它不是"删除候选"，而是**改变相对权重**（这点和 top-k/top-p 有本质区别）。

**常见取值**：事实性任务 0–0.3；对话 0.7；创意写作 0.9–1.2。
:::

:::card 一个必须澄清的坑（面试常问）
**`temperature = 0` 是不是等价于"确定性"？**
- 数学上 `T→0` 是 argmax，**是的**
- 但工程上**不保证**：浮点误差、batch 内不同序列的 kernel 差异、并行归约顺序都可能让 argmax 出现并列时结果不同
- **真正要复现**：`do_sample=False`（或 greedy）+ 固定 seed + 固定 batch/并行配置

**一句话**：「`temperature=0` 在实现上常被特殊处理成贪心，但**严格的确定性要靠 greedy + 固定环境**。」
:::

## 4. Top-k

:::card 做法
保留概率最高的 `k` 个 token，其余置 0（重新归一化），然后在这 k 个里采样。

**特点**：
- **固定候选数量** → 不管分布尖还是平，都是 k 个
- **问题**：分布很尖时，k=50 里可能有一堆极低概率的垃圾 token（因为只有前几个有意义）；分布很平时，k=50 又截掉了太多可能性
- 所以固定 k 是"**一刀切**"，不够自适应

**典型取值**：k = 20–50（也有用 0 表示关闭）
:::

---

## 5. Top-p（nucleus sampling）

:::card 做法
把 token 按概率从高到低排序，**累积概率首次达到 `p` 就截断**，保留这个集合。

**关键特性**：**候选数量是动态的**
| 分布形态 | top-p=0.9 保留的候选数 |
|---|---|
| 很尖（模型很确定） | 可能只有 2–3 个 |
| 很平（模型不确定） | 可能几十上百个 |

**这就是它优于 top-k 的原因**：它**自适应**地匹配了模型当前的确信程度。

**典型取值**：p = 0.9–0.95
:::

:::card top-k vs top-p 的核心区别（一句话答法）
> 「top-k 是**按数量截断**（固定 k 个候选），top-p 是**按概率质量截断**（累积到 p 就停）。所以 top-p 能自适应分布的尖锐程度，通常更合理。」
:::

## 6. 组合顺序（容易答错的细节）

:::card 正确的顺序
```
logits → (repetition/penalty) → temperature 缩放 → top-k → top-p → softmax → 采样
```

**为什么这个顺序**：
1. **penalty 先做**（它要改 logits 本身）
2. **temperature 缩放要在截断之前**：因为它改变的是相对分布形状，先截断再缩放会得到不同的截断结果
3. **top-k 和 top-p 可以叠加**：先 k 限个数，再 p 限概率质量（两者取交集）
4. **softmax 放最后**（前面的操作都在 logits 域做，数值更稳）

**面试加分**：「顺序不是"随便调"，**先截断再调温度**会得到不同分布 —— 这也是为什么不同框架同一组参数可能表现略有差异。」
:::

## 7. 三类惩罚项（不要混）

| 参数 | 作用对象 | 效果 |
|---|---|---|
| **repetition_penalty** | 已出现过的 token | 把它们的 logit **除以**系数（>1 则抑制） |
| **presence_penalty** | 已出现过的 token | logit **减去**一个常数（出现即罚，与次数无关） |
| **frequency_penalty** | 已出现过的 token | 按**出现次数**成比例地减 |

**什么时候用**：
- 长文生成容易重复 → repetition_penalty 1.05–1.2
- **代码/结构化输出慎用**：重复的 `{`、`,`、字段名是必要的，惩罚会让模型输出坏 JSON

**这句话很实用**：「**结构化输出场景要把 repetition penalty 调低甚至关掉** —— 否则模型会因为怕重复而破坏语法。」
:::

## 8. 约束解码（Structured Output）——**工程高频**

:::card 核心思想
**在每一步，把"会导致语法非法"的 token 的 logit 设成 `-inf`**，然后正常采样。

这样模型只能在**合法 token** 里选，**输出必然符合语法** —— 不是靠 prompt 祈祷，而是靠**硬约束**。
:::

:::card 三种实现方式
| 方式 | 做法 | 特点 |
|---|---|---|
| **有限状态机（FSM）** | 把目标语言（如 JSON schema）编译成状态机，每步根据当前状态计算可接受 token 集合 | 主流做法，快 |
| **正则/CFG 语法约束** | 用 BNF 文法描述合法输出（如 GBNF） | 表达力强（能约束嵌套结构） |
| **后处理修复** | 生成后用解析器修复/重试 | 简单但不可靠，会浪费 token |

**主流库**：Outlines、llguidance、XGrammar、vLLM 的 guided decoding（原理都是 FSM + logits mask）。
:::

:::card 为什么这对 Agent 特别重要
**Function Calling 的本质就是"生成一个符合 schema 的 JSON"**。如果没有约束解码：
- 模型可能输出多余的解释文字（"好的，我来调用…{...}"）
- 可能漏字段、类型错、引号不闭合
- 一旦解析失败，整个工具调用链条断掉

**有约束解码后**：格式正确性是**结构性保证**，模型只需要负责"填什么内容"，不需要负责"格式对不对"。这大幅降低了工具调用的失败率。
:::

:::card 一个重要的取舍（面试会问）
**约束解码会让效果变差吗？**
- 它**改变了采样分布**（把非法的概率质量重新分配），所以严格说它是**有偏**的
- 但实践中收益远大于代价：格式正确率从 ~90% 提到接近 100%
- **副作用**：如果 schema 太严格（比如强制某个字段必须从枚举里选），模型可能被"逼"着给出错误答案 → **schema 设计要留余地**

**一句话**：「约束解码是'**用一点点分布偏移换格式确定性**'，对 Agent 场景几乎总是值得的。」
:::

## 9. 采样参数与评测（实践中的一个坑）

:::card 评测必须固定采样配置
- **可复现性**：同一模型、同一 prompt，`temperature=0.7` 每次结果不同 → 指标会抖
- **标准做法**：评测用 **greedy（do_sample=False）**，或固定 seed + 固定 temperature
- **报告要求**：写清 `temperature / top_p / max_tokens / 是否 greedy`，否则结果无法比较

**面试话术**：「评测不固定采样配置是常见的方法论问题 —— 我自己的实验里，所有对比都用同一套解码参数，否则提升可能只是采样噪声。」
:::

## 10. 十个追问预答

:::qa temperature / top-k / top-p 分别改什么
- temperature：**改变分布形状**（logits 除以 T 再 softmax），不删候选
- top-k：**按数量截断**（保留 k 个）
- top-p：**按概率质量截断**（累积到 p），候选数动态
:::

:::qa top-k 和 top-p 哪个好？为什么
top-p 通常更好，因为它**自适应**：模型确定时候选少（避免垃圾 token），模型不确定时候选多（保留可能性）。top-k 是一刀切。
两者可以叠加。
:::

:::qa temperature 调 0 是确定性输出吗
数学上 T→0 等价 argmax；但工程上浮点误差、并行归约顺序、batch 组成都可能影响结果。**要严格复现必须用 greedy + 固定 seed 与固定并行配置。**
:::

:::qa 为什么开放生成不用 beam search
它最大化整体概率 → 倾向输出**最平庸/最重复**的句子；成本 ×k；且缺乏多样性。beam 适合翻译/摘要这类答案相对确定的任务。
:::

:::qa repetition_penalty 什么时候要关掉
**结构化输出/代码生成时**：重复的 `{`、`,`、字段名是语法必需的，惩罚会让模型破坏 JSON。
:::

:::qa 约束解码（structured output）的原理
把目标语法（JSON schema/正则/CFG）编译成状态机，每步根据当前状态把**非法 token 的 logit 置 -inf**，模型只能在合法 token 里选 → 输出必然合规。
:::

:::qa 约束解码会让效果变差吗
它是**有偏**的（重新分配了概率质量），但收益远大于代价（格式正确率接近 100%）。风险是 schema 太严会把模型"逼"到错误答案 → schema 要留余地。
:::

:::qa Function Calling 为什么依赖约束解码
工具调用本质是"生成符合 schema 的 JSON"。没有约束时会出现多余文字、漏字段、引号不闭合 → 解析失败、链条断掉。约束解码把"格式正确"变成结构性保证，模型只管填内容。
:::

:::qa presence_penalty 和 frequency_penalty 的区别
presence：出现过就罚一个固定常数（与次数无关）；frequency：按出现次数成比例罚。
:::

:::qa 评测时采样参数怎么设
用 greedy（do_sample=False）或固定 seed+固定 temperature，并在报告里写清所有解码参数；否则指标抖动、对比不可信。
:::

## 11. 陷阱

| ❌ 别这么说 | ✅ 换成这么说 |
|---|---|
| 「temperature 决定候选数量」 | 「temperature 改变**分布形状**，候选数量由 top-k/top-p 决定」 |
| 「top-k 比 top-p 好」 | 「top-p **自适应**分布尖锐程度，通常更合理」 |
| 「temperature=0 一定可复现」 | 「数学上是 argmax，但工程上要 greedy + 固定环境才严格可复现」 |
| 「beam search 是最优解码」 | 「它最大化整体概率，但开放生成会退化到平庸/重复」 |
| 「约束解码无损」 | 「它会重新分配概率质量，是**有偏**的，但格式收益远大于代价」 |
| 「repetition_penalty 越大越好」 | 「结构化输出/代码里要调低甚至关掉，否则破坏语法」 |

## 12. 自测（6 题）

:::qa 三个采样旋钮各改什么，一句话
temperature 改分布形状；top-k 按数量截断；top-p 按累积概率截断（候选数动态）。
:::

:::qa 为什么 top-p 通常优于 top-k
因为它自适应：模型确定时候选少、不确定时候选多；top-k 固定 k 是一刀切。
:::

:::qa 正确的采样顺序，以及为什么
penalty → temperature → top-k → top-p → softmax。先截断再调温度会得到不同分布，所以 temperature 必须在截断前。
:::

:::qa 约束解码的原理，以及它在 Agent 里的价值
语法编译成状态机 + 非法 token logit 置 -inf。它让 Function Calling 的 JSON 格式成为结构性保证，大幅降低解析失败率。
:::

:::qa 为什么代码生成要关掉 repetition penalty
代码里重复的花括号、逗号、字段名是必需的，惩罚会诱导模型"避免重复"从而破坏语法。
:::

:::qa temperature 与确定性输出的关系
T→0 数学上等价 argmax，但工程上受浮点/并行/batch 影响；严格复现要用 greedy + 固定 seed 与配置。
:::
