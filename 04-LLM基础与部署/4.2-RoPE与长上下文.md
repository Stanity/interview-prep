# 4.2 RoPE 与长上下文（旋转位置编码和外推）

> **为什么单独一篇**：RoPE 是现代 LLM 的默认位置编码，"为什么能表达相对位置"是高频推导题；而"长上下文怎么做外推"是工程必问。
> **前置**：4.1 里说过 attention 是**置换不变**的，所以位置信息必须显式注入 —— 这篇讲"怎么注入"。
> **标注**：`★★☆` 能讲清原理与取舍即可，不需要背全部公式

---

## 1. 30 秒口述版

:::card 30 秒版
「Self-attention 本身不知道顺序（打乱输入只是输出同样打乱），所以必须注入位置信息。

传统做法是**绝对位置编码**（sinusoidal 或可学习的 position embedding，直接加到词向量上）。问题是：它只告诉模型"我在第几个位置"，**并没有直接表达"两个 token 相距多远"**，而且长度一变就得重训。

**RoPE 的做法更聪明**：不把位置加进去，而是**对 Q 和 K 做旋转**。旋转角度由位置决定，这样 `q_mᵀk_n` 的内积**只依赖相对位置 (n−m)** —— 相对位置信息是"乘"进去的，不是"加"进去的。

具体实现是：把 `d` 维向量切成 `d/2` 个二维子空间，每个子空间按不同频率旋转（低频旋转慢、高频旋转快）。

长上下文要外推时，主流有三类方法：**位置插值（PI）**把新位置压缩回训练范围、**NTK-aware** 改 base 让波长变长、**YaRN** 分段处理 + 温度修正。」
:::

---

## 2. 为什么需要位置编码（一句话说透）

:::card 核心事实
Self-attention 的计算是 `softmax(QKᵀ/√d)V`，其中 Q/K/V 都来自输入的线性变换 —— **整个过程对 token 的顺序完全无感**。

数学上：如果对输入做置换 `P`，则 `X → PX`，那么 `Q → PQ`、`K → PK`，得到 `(PQ)(PK)ᵀ = P(KKᵀ)Pᵀ` —— 注意力矩阵只是被**同样置换**了，输出也跟着置换。**信息内容完全不变。**

所以："Attention is all you need" 这句话本身是不完整的，必须配位置编码。
:::

---

## 3. 绝对位置编码的两个问题

:::card 传统方案
**① Sinusoidal（原始 Transformer）**
```
PE(pos, 2i)   = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
```
直接**加到**词向量上。

**② 可学习 position embedding**（BERT/GPT-2 用）
一个 `max_len × d` 的查找表。

**两个问题**：
1. **只编码绝对位置**：模型要从"我在 pos=5、你在 pos=8"里**自己推导**出"相距 3"，而这个推导要在注意力里完成，不直接
2. **不能外推**：超出训练长度时，可学习的表根本没有对应行；sinusoidal 虽然能算，但模型没见过那些值 → 效果崩
:::

## 4. RoPE 的核心推导（能推出来是加分项）

### 4.1 二维情形：为什么旋转能得到相对位置

:::card 推导（三步）
设二维向量 `q = (q₁, q₂)`，位置为 `m`；`k = (k₁, k₂)`，位置为 `n`。

**① 定义旋转矩阵**
```
R(θ) = [ cosθ  −sinθ ]
       [ sinθ   cosθ ]
```
对位置 `m` 的向量施加角度 `mθ` 的旋转：`q' = R(mθ) q`。

**② 计算内积**
```
q'ᵀ k' = (R(mθ)q)ᵀ (R(nθ)k) = qᵀ R(mθ)ᵀ R(nθ) k
```
利用旋转矩阵的正交性 `R(α)ᵀ = R(−α)`：
```
R(mθ)ᵀ R(nθ) = R(−mθ) R(nθ) = R((n−m)θ)
```
所以：
```
q'ᵀ k' = qᵀ R((n−m)θ) k
```

**③ 结论**
内积**只依赖相对位置 `(n−m)`**，与绝对位置 `m`、`n` 无关。
:::

**这就是 RoPE 的全部魔法**：把位置信息变成"旋转角度"，让相对位置在**内积层面**自然出现。

### 4.2 高维：切成 d/2 个二维子空间

:::card 做法
把 `d` 维向量按相邻两维分组：`(x₀,x₁), (x₂,x₃), …, (x_{d−2},x_{d−1})`，共 `d/2` 组。
第 `i` 组的旋转频率：
```
θ_i = base^(−2i/d) ,  i = 0, 1, …, d/2 − 1 ,   base 通常 = 10000
```
即**不同子空间用不同频率**：`i=0` 频率最高（旋转最快），`i` 越大频率越低（旋转越慢，波长越长）。

**为什么需要多频率**：
- **高频**（短波长）：区分**近距离** token（相邻几个位置）
- **低频**（长波长）：编码**远距离**关系（几百上千的位置差）

类比：像时钟的秒针、分针、时针 —— 不同精度组合起来才能表达任意时间差。
:::

:::card 一个重要的实现细节
实际实现里不是逐个构造旋转矩阵（太慢），而是用**等价的分量重排**：
```
x_rot[2i]   = x[2i]·cos(mθ_i) − x[2i+1]·sin(mθ_i)
x_rot[2i+1] = x[2i]·sin(mθ_i) + x[2i+1]·cos(mθ_i)
```
并且为了缓存友好，很多实现会把 `d` 维按"前半后半"交错（`x_i` 与 `x_{i+d/2}` 配对），效果等价但访存更好。
:::

## 5. 三类外推方法（长上下文必问）

:::card 问题出在哪
用 `base=10000` 在 4k 上训练，直接拿去跑 32k，会出现：
- **高频维度**：旋转太快，位置差太大时角度"绕圈"，远处的位置差**互相混叠**
- **低频维度**：波长本来能覆盖长距离，但模型**没在训练时见过这么大的角度** → 分布外

所以外推的核心思路是：**让模型见到"熟悉的"旋转角度范围**。
:::

:::card ① 位置插值（PI, Position Interpolation）
**做法**：把位置索引**压缩**
```
m' = m × (L_train / L_target)
```
例如训练 4k、要用 32k，就把位置乘 `1/8` —— 32k 的位置被映射回 4k 的范围内。

**优点**：简单，只需少量微调就能恢复效果
**缺点**：**所有维度一起压缩**，导致近距离的区分度下降（因为高频也被压慢了）
:::

:::card ② NTK-aware
**做法**：**不改位置，改 base**
```
base' = base × s^(d / (d−2))     （s 是扩展倍数）
```
**直觉**：增大 base 会让所有 `θ_i` 变小 → 波长变长 → **低频维度被拉长到能覆盖新长度，而高频维度受影响相对小**。

**优点**：不需要微调也能有一定外推能力
**缺点**：是"一刀切"的调整，高低频的处理不够精细
:::

:::card ③ YaRN（目前主流）
**做法**：**分段处理 + 温度修正**
1. **NTK-by-parts**：按波长分三档
   - 波长很短的维度（高频）→ **不插值**（保留近距区分度）
   - 波长很长的维度（低频）→ **插值**（拉长覆盖）
   - 中间的 → 平滑过渡
2. **注意力温度缩放**：长序列下注意力分布会变"平"，用温度系数补偿熵的变化
3. 少量微调（几百步）即可适应

**为什么 YaRN 效果好**：它承认"不同频率的维度需求不同"，而不是一刀切。
:::

:::card 三类方法对比表
| 方法 | 改什么 | 需要微调 | 优劣 |
|---|---|---|---|
| **PI** | 位置索引（缩小） | 少量即可 | 简单，但近距区分度受损 |
| **NTK-aware** | base（放大） | 可以不用 | 免微调可用，但不够精细 |
| **YaRN** | 分段 + 温度 | 少量 | 效果最好，实现复杂 |

**一句话总结**：「PI 是"**把位置压回训练范围**"，NTK-aware 是"**把波长拉长**"，YaRN 是"**按频率分别处理 + 温度修正**"。」
:::

## 6. 长上下文的真正难点（**不是位置编码**）

:::card 三个现象（面试很喜欢问"为什么 128k 效果不如宣传"）
**① 注意力稀释（attention dilution）**
序列变长后 softmax 分布更"平"，**有效注意力被分散到更多 token 上**。原本聚焦 3 个关键 token 的注意力，现在可能摊到 30 个 → 信噪比下降。

**② Lost in the Middle**
信息位置影响利用率：**开头和结尾**的信息利用得好，**中间**的信息容易被忽略。所以"把关键证据放在 context 中间"是最差的选择。

**③ Attention Sink**
模型会把大量注意力集中在**开头几个 token**（尤其是 BOS）上 —— 这是为了"有个地方放多余注意力"，维持 softmax 的归一化。
- 好处：这是 StreamingLLM 能做"滑动窗口 + 保留开头几个 token"的基础
- 坏处：真正有用的信息可能抢不到注意力
:::

:::card 面试话术
「长上下文的效果瓶颈，**位置编码只是一部分**。更麻烦的是注意力的信噪比问题：序列越长，有效信息被稀释、中间位置被忽略、开头 token 变成注意力垃圾桶。所以工程上常做的是**不是把窗口做更大，而是把该给模型看的东西放对位置**（这也正是 context engineering 的核心）。」
:::

## 7. 十个追问预答

:::qa RoPE 为什么能表达相对位置？一句话 + 一句推导
因为它是对 Q/K 做**旋转**而非加法，而旋转矩阵正交：`R(mθ)ᵀ R(nθ) = R((n−m)θ)`，所以 `q_mᵀk_n` 只依赖 `(n−m)`。
:::

:::qa 为什么 RoPE 要切成多个不同频率的子空间
单一频率无法同时兼顾近距与远距：高频区分相邻 token，低频编码长距离。多频率组合才能表达任意位置差（像时钟的秒针/分针/时针）。
:::

:::qa base 的作用是什么？调大 base 会怎样
`θ_i = base^(−2i/d)`。base 越大，所有频率越小、波长越长 → 能覆盖更长的距离，但**近距区分度下降**。这也是 NTK-aware 外推的思路。
:::

:::qa 位置插值（PI）的原理和缺点
把位置索引乘 `L_train/L_target`，把新长度压回训练范围。缺点：**所有维度一起压**，高频也被压慢 → 近距离区分度下降。
:::

:::qa NTK-aware 和 PI 的区别
PI **改位置**（缩小索引），NTK-aware **改 base**（拉长波长）。NTK-aware 对高频维度影响较小，还能免微调。
:::

:::qa YaRN 相比前两者好在哪
**分段处理**：高频不插值（保近距）、低频插值（保覆盖）、中间平滑过渡，再加**注意力温度修正**补偿长序列下熵的变化。承认"不同频率需求不同"。
:::

:::qa 长上下文效果不好，除了位置编码还有什么原因
三个：注意力稀释（softmax 变平、信噪比降）、lost in the middle（中间信息利用率低）、attention sink（注意力堆在开头 token）。
:::

:::qa 什么是 attention sink
模型把大量注意力集中在开头几个 token（尤其 BOS），本质是"给多余注意力找个去处"以维持 softmax 归一化。StreamingLLM 利用这一点做滑窗 + 保留开头 token。
:::

:::qa 为什么说"把证据放在 context 中间最差"
因为 lost in the middle：模型对**开头和结尾**的利用最好，中间最差。所以 RAG 拼上下文时应把最关键的证据放在**结尾附近**（也可以在开头强调一次）。
:::

:::qa RoPE 能不能用于线性注意力 / 状态空间模型
不能直接套用 —— 那些结构不显式算 `QKᵀ`，没有"内积只依赖相对位置"的机制。它们通常用别的位置处理方式（如卷积、或显式衰减）。
:::

## 8. 陷阱

| ❌ 别这么说 | ✅ 换成这么说 |
|---|---|
| 「RoPE 是把位置信息加到向量里」 | 「RoPE 是对 Q/K 做**旋转**，位置以角度形式乘进去」 |
| 「RoPE 直接编码相对位置」 | 「RoPE 编码**绝对位置的角度**，但因为旋转矩阵正交，**内积表现为相对位置**」 |
| 「位置插值只是把位置缩放一下」 | 「缩放的代价是**高频维度被一起压慢**，近距区分度下降」 |
| 「长上下文做不了是因为位置编码不行」 | 「位置编码只是一部分，更关键的是**注意力稀释和 lost in the middle**」 |
| 「base 越大越好」 | 「base 大 = 波长长 = 覆盖远，但近距区分度下降，要权衡」 |

## 9. 自测（6 题）

:::qa 用一句话说清 attention 为什么需要位置编码
`softmax(QKᵀ/√d)V` 对输入置换是**等变**的（打乱输入只是同样打乱输出），所以本身不含顺序信息。
:::

:::qa 写出 RoPE 能表达相对位置的关键一步
`R(mθ)ᵀR(nθ) = R(−mθ)R(nθ) = R((n−m)θ)`，所以 `q_mᵀk_n = qᵀR((n−m)θ)k` 只依赖相对位置。
:::

:::qa 为什么要用多个不同频率
单一频率不能兼顾近距（需高频）与远距（需低频）；多频率组合像时钟的秒针/分针/时针。
:::

:::qa PI / NTK-aware / YaRN 各改了什么
PI 改位置索引（缩小）；NTK-aware 改 base（放大，拉长波长）；YaRN 分段（高频不插值、低频插值）+ 注意力温度修正。
:::

:::qa 长上下文效果差的三个非位置编码原因
注意力稀释、lost in the middle、attention sink。
:::

:::qa 如果 RAG 要把 10 段证据塞进 context，你会怎么排
**最关键的放结尾附近**（利用首尾优势），开头用一句指令强调重点；把次要证据放中间。这就是 lost in the middle 的直接应用。
:::
