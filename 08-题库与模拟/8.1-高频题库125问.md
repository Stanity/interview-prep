## A. LLM 基础与架构（25 问）

| # | 问题 | 答案 |
|---|---|---|
| 1 | Attention 为什么除以 √d_k | 点积方差是 `d_k`，不缩放会让 softmax 饱和、梯度趋零 |
| 2 | Self-Attention 复杂度 | 时间 `O(n²d)`、空间 `O(n²)`；FFN 是 `O(nd²)`，`n>d` 时注意力主导 |
| 3 | Q/K/V 各是什么 | Q 我要找什么、K 我能被怎么匹配、V 我贡献的内容；分开是为了匹配与内容解耦 |
| 4 | 多头注意力的"多"有什么用 | 各自独立的 Q/K/V 投影，学不同子空间关系；总计算量不变（切分维度） |
| 5 | 位置编码为什么必须有 | attention 对输入置换等变，本身不含顺序信息 |
| 6 | RoPE 为什么能表达相对位置 | 旋转矩阵正交：`R(mθ)^TR(nθ)=R((n−m)θ)`，内积只依赖相对位置 |
| 7 | RoPE 为什么要多频率 | 高频管近距、低频管远距（像秒针/分针/时针） |
| 8 | Pre-LN 与 Post-LN | Pre-LN 残差路径干净、梯度直通、训练稳；代价是要 final norm |
| 9 | RMSNorm 与 LayerNorm | RMS 不减均值、只有缩放，更快、参数更少，效果相当 |
| 10 | FFN 的作用 | 提供非线性（attention 是线性加权）；承载大部分参数/知识 |
| 11 | SwiGLU 为什么主流 | 门控结构效果优于 ReLU/GELU；为保参数量把 hidden 降到约 8d/3 |
| 12 | Decoder-only 为什么主流 | 训练目标统一、in-context 强、KV cache 友好、scaling 简单 |
| 13 | MHA/MQA/GQA/MLA 的 KV cache 相对大小 | 1×、1/h、g/h（Llama-3 是 1/4）、MLA 约 1/10 量级 |
| 14 | GQA 是什么 | 把 Q 头分组，每组共享 K/V；Llama-3 是 32 Q 头 / 8 KV 头 |
| 15 | MLA 和 GQA 思路差在哪 | GQA 减少 KV 头数（损表达力）；MLA 压缩 KV 表示为低秩 latent |
| 16 | KV cache 大小公式 | `2×layers×n_kv_heads×d_head×seq×batch×bytes` |
| 17 | 8B/GQA-8头/8k/batch1 的 KV 约多少 | 约 1 GB |
| 18 | FlashAttention 是近似吗 | 不是，是**精确**注意力；快在减少 HBM 读写（分块+在线 softmax+重算） |
| 19 | 长上下文为什么效果会掉 | 注意力稀释、lost in the middle、attention sink（不只是位置编码） |
| 20 | PI/NTK-aware/YaRN 的区别 | PI 缩位置；NTK 改 base（拉长波长）；YaRN 分段插值 + 温度修正 |
| 21 | MoE 省什么不省什么 | **省算力（FLOPs），不省显存**；带宽压力反而更大 |
| 22 | 总参数 vs 激活参数 | 总参数决定显存，激活参数决定计算量（DeepSeek-V3：671B / 37B） |
| 23 | 路由塌缩怎么解决 | 辅助损失 / 容量因子 / 专家选 token / 偏置调整（DeepSeek 无 aux loss） |
| 24 | 专家并行为什么贵 | 前向两次 all-to-all（分发 token + 收回结果），依赖高速互联 |
| 25 | BF16 与 FP16 的关键区别 | BF16 指数 8 位（动态范围同 FP32，不易溢出）、尾数 7；训练选 BF16 |

| 31 | PPO 显存大头 | Adam 的 fp32 状态（8 bytes/参数）→ 8B 全参约 64 GB |
| 32 | DPO 为什么不需要 RM | RLHF 目标有闭式解，反解隐式奖励后 `Z(x)` 在相减时抵消 |
| 33 | 写出 DPO loss | `−log σ(β[(logπ_θ(y_w)/π_ref(y_w)) − (logπ_θ(y_l)/π_ref(y_l))])` |
| 34 | DPO 的梯度说明什么 | 权重 `σ(r_l − r_w)`：判错时梯度大 → **自带难例挖掘** |
| 35 | β 的物理意义 | 温度 + KL 系数：大→接近 π_ref，小→激进；常用 0.1 |
| 36 | DPO 后输出变长为什么 | `log π` 是 token logprob 之和（负值累加），长序列更负 → 学到"长=好" |
| 37 | likelihood displacement | DPO 只约束差值不约束绝对水平，chosen 的绝对概率也可能下降 |
| 38 | IPO/KTO/ORPO/SimPO 各改了什么 | 平方损失 / 二元标签 + 不对称损失 / SFT+odds ratio（无 ref）/ 长度归一化+margin（无 ref） |
| 39 | GRPO 怎么去掉 value model | 同题采一组，用组内均值当 baseline、标准差归一化 |
| 40 | GRPO 的优势公式 | `A_i = (r_i − mean)/std` |
| 41 | 组内奖励全同时会怎样 | std=0 → 优势全 0 → 该组白采，实践中要过滤 |
| 42 | GRPO 保留 PPO 的什么 | clip（限更新幅度）和 KL 约束（防跑飞） |
| 43 | RLVR 是什么 | 用可验证验证器（答案比对/单测/schema）当奖励，不用人训 RM |
| 44 | RLVR 三个优势 | 奖励可靠、可大规模自动化、信号方向明确 |
| 45 | 稀疏奖励四条对策 | 难度筛、课程学习、部分奖励、混合任务 |
| 46 | reward hacking 的典型表现 | 格式套利、答案枚举、长度套利、提前终止（Agent） |
| 47 | 训练崩的三个信号 | 平均奖励不升、策略熵断崖式下降、KL 暴涨 |
| 48 | 为什么 R1 不用 PRM 当主奖励 | 过程奖励容易被刷；结果奖励无法伪造 |
| 49 | LoRA 为什么 B 置零 | 保证训练开始 `ΔW=BA=0`（无损起步、稳定、可关闭） |
| 50 | LoRA 参数量怎么算 | `r(d+k)`；4096×4096、r=8 → 65.5K（0.39%） |

| 55 | PagedAttention 用 OS 的什么思想 | 虚拟内存分页：逻辑连续、物理离散、块表映射、按需分配、块共享 |
| 56 | 静态批处理的问题 | 要等最长序列结束，短序列 padding 空转 |
| 57 | chunked prefill 的取舍 | 用 TTFT 略增换 TPOT 平稳 |
| 58 | 投机解码为什么无损 | 接受规则 `min(1, p_t/p_d)` + 残差重采样，保证输出分布不变 |
| 59 | 加速比取决于什么 | 接受率 α、草稿长度 k、draft 成本；α≈0.7–0.8 时 1.5–2.5× |
| 60 | TTFT 和 TPOT 分别由什么决定 | TTFT=prefill+排队；TPOT=decode 每步 |
| 61 | 端到端延迟公式 | `TTFT + TPOT×(输出token数−1)` |
| 62 | 80G 卡跑 8B/8k 能多少并发 | 权重 16G + KV 1G/序列 → 约 60 路 |
| 63 | prefix cache 命中条件 | 从第一个 token 起完全一致；所以稳定内容必须放前面 |
| 64 | KV cache 与 prefix cache 的区别 | 前者单请求内复用历史 KV；后者跨请求复用相同前缀 |

| 67 | 为什么激活量化比权重难 | 激活动态变化且含极端异常值；权重静态可离线优化 |
| 68 | GPTQ / AWQ / SmoothQuant 的区别 | 二阶信息补偿误差 / 按通道缩放保护显著通道 / 等价变换把激活难度迁给权重 |
| 69 | 8B 塞进 24G 卡怎么算 | INT4 权重 4G + 8k KV 约 1G + 框架 1–2G ≈ 6–7G |
| 70 | 量化后必须回归测哪四类 | 主任务、长上下文、格式合规率、需要 logprob 的场景 |

## 附表一：20 个最容易说错的表述

| ❌ 错误说法 | ✅ 正确说法 |
|---|---|
| MQA 省算力 | MQA 省 **KV cache 显存** |
| Attention 复杂度 O(n²) | 时间 `O(n²d)`、空间 `O(n²)` |
| FlashAttention 是近似注意力 | 它是**精确**的，优化 IO |
| RMSNorm 效果更好 | 效果相当，**更快、参数更少** |
| DPO 不需要参考模型 | DPO **需要 reference**，不需要 reward model |
| DPO 是简化版 RLHF | DPO 是 RLHF 目标的**闭式解重参数化** |
| 参考模型用来做 KL 约束（我的方法里） | 我的**判别式改造**里它做**难度归一化** |
| GRPO 不需要 reward | GRPO 不需要 **critic**；reward 仍然需要 |
| 熵越低越好 | 熵断崖 = **熵塌缩**，探索消失 |
| MoE 省显存 | MoE **省算力不省显存** |
| BF16 比 FP16 精度高 | BF16 **动态范围大**，精度更低 |
| 量化只影响权重 | 权重/激活/**KV cache** 三类都能量化 |
| 向量检索全面优于 BM25 | 两者失效场景**互补** |
| RAG 效果差就换大模型 | 先查 **Recall@k** |
| chunk 越小越好 | 要权衡，推荐父子块 |
| 有上下文窗口就够了 | 窗口不是记忆（会满/会丢/不可查） |
| 多 Agent 一定更强 | 只在需要隔离/多视角/交叉验证时划算 |
| 模型会自己调用工具 | 模型只输出 tool_call，**执行在校验后的代码里** |
| MCP 是 function calling 升级版 | 两者**正交** |
| 我用过 LangChain 系列 | 我手写过等效编排，没用过框架 API |

| 9 | dropout 在推理时做什么 | 关闭（缩放已在训练时用 inverted dropout 处理） |
| 10 | 交叉熵与 KL 的关系 | 分类里 softmax+CE 等价于最小化与 one-hot 的 KL |
| 11 | 精度、召回、F1 的关系 | F1 是调和平均；类别不均衡时用 Macro/加权 |
| 12 | AUC 的意义 | 随机正样本排在负样本之上的概率；与阈值无关 |
| 13 | 为什么用 Macro-F1 | 每类等权，反映难类/小类表现 |
| 14 | 什么是数据泄漏 | 训练集含测试信息（如目标编码未在折内做） |
| 15 | 类别不均衡的处理 | 重采样、类权重、Focal Loss、阈值调优、分层评估 |
| 16 | 什么是 softmax 温度 | logits/T 控制分布锐度，T 大更平 |
| 17 | 残差连接为什么有用 | 提供恒等路径，梯度直通，缓解退化 |
| 18 | 初始化为什么重要 | 方差过大/过小导致激活爆炸/消失（Xavier/He 按 fan 缩放） |
| 19 | 梯度裁剪用在哪 | RNN/Transformer 训练稳定（按范数裁剪） |
| 20 | 为什么用 bf16 混合精度 | 省显存/带宽提速，主权重与优化器状态保留 fp32 保稳定 |
