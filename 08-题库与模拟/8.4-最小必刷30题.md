# 8.4 最小必刷 30 题（时间不够时的取舍清单）

> **这篇的来源**：借鉴英文题库里最实用的一个设计 —— `Kazukie0647/AI-Engineer-Interview-Questions` 的「**AI Engineer 75**」：与其刷 1000 题，不如给一份**按频率排序的最小必刷集**并配时间计划。
> **这篇给你的**：30 道题（按"**出现频率 × 你的短板**"排序），每题一句话答案 + 指向的详细章节。
> **用法**：时间不够就按 §4 的三档计划走；时间够就当作**考前最后一遍的总检**。

---

## 1. 怎么选出的这 30 题

:::card 三个筛选标准
1. **出现频率**：来自字节/百度/美团等面经里反复出现的问题（GRPO vs PPO、KV cache 计算、手写注意力等）
2. **你的短板权重**：你没有 RL 训练经验、没有 MCP/框架经验 → 这几块优先级上调
3. **区分度**：能拉开差距的（不是"什么是 RAG"这种谁都会的）

**排除掉**：纯记忆题（BERT 各版本区别）、偏岗位题（CV/多模态）、你能秒答的（LoRA 原理你已经很熟）
:::

## 2. 30 题清单（每题一句话答案 + 详解位置）

### A. 必答且必须满分（10 题）

| # | 问题 | 一句话答案 | 详解 |

| 2 | 9.0pp 怎么算的 | 四数据集 vs **各自最强基线**：+2.65/+14.85/+7.53/+11.13，算术平均 9.04 | 2.1 §7.1 |
| 3 | 这不就是 DPO 吗 | 三处不同：偏好对是**标签**不是回答、参考模型做**难度归一化**、多了两个表示层目标 | 2.1 §8 |
| 4 | 你个人做了什么 | 按"问题定义/方法设计/实现/实验/写作"五个动作各给一个具体决策 | 2.5 §11 |
| 5 | CausalPoison 的核心贡献 | 把攻击评估从 **outcome-level** 推进到 **relation-level**（`q → P* → y*`） | 2.2 §4 |
| 6 | 那怎么防 | 四层：来源可信/多源一致/指令数据分离+拒答/审计；且**最小权限最关键** | 5.6 §3 |
| 7 | 你的三个项目什么关系 | 判得准（模型侧）→ 查得到（系统侧）→ 扛得住（评估侧） | 2.4 §2.1 |

| 10 | 你项目的失败 case | RePref 6 难例救回 3 个 + "很果断地错"说明知识缺失；CausalPoison 检索深度加大后退化 | 2.1 §7.6 |

### B. 高频技术题（12 题）

| # | 问题 | 一句话答案 | 详解 |
|---|---|---|---|
| 11 | KV cache 怎么算 | `2×layers×n_kv×d_head×seq×batch×bytes`；8B/GQA-8头/8k ≈ **1GB** | 4.4 §3 |
| 12 | vLLM 为什么快 | PagedAttention（省显存）+ 连续批处理（提利用率），两者**配套** | 4.4 §4–5 |
| 13 | 为什么 decode 是 memory-bound | 每步算 1 token 却读全部权重+KV，算术强度 ≈1 FLOP/byte（GPU ≈150） | 4.4 §2 |
| 14 | Attention 为什么除以 √d | 点积方差 = `d_k` → softmax 饱和 → 梯度消失 | 4.1 §2.3 |
| 15 | MQA/GQA 省什么 | **省 KV cache 显存**（不是算力）；Llama-3 是 32 Q 头 / 8 KV 头 | 4.1 §9 |
| 16 | FlashAttention 是近似吗 | 不是，是**精确**的；快在减少 HBM 读写 | 4.1 §10 |
| 17 | DPO 为什么不需要 RM | RLHF 目标闭式解 → 反解隐式奖励 → `Z(x)` 相减时抵消 | 3.2 §2 |
| 18 | DPO 还需要 reference 吗 | **需要**（算 log-ratio）；不需要的是 reward model | 3.2 §5 |
| 19 | GRPO 和 PPO 的区别 | GRPO 用**组内均值/标准差**替代 critic 的 `V(s)` | 3.3 §3 |
| 20 | 组内奖励全相同会怎样 | `std=0` → 优势全 0 → 该组白采，要过滤 | 3.3 §3.1 |
| 21 | RAG 效果不好先查哪 | **Recall@k** —— 多数失败在检索不在生成 | 5.1 §8 |
| 22 | Contriever 和 ANCE 区别 | 无监督+batch 内负例 vs 有监督+**全库 ANN 难负例** | 5.2 §4 |

## 4. 三档时间计划

:::card ① 只有 2 小时（面试在明天）
- **40 min**：30 题的一句话答案过一遍（§2）
- **30 min**：手撕 3 题各默写一遍（§3）
- **20 min**：数字口径表（2.4 §6）只看加粗的
- **30 min**：60 秒串讲 + 3 个反问，出声练两遍

**目标**：不在任何一个回答上卡死，数字不说错。
:::

:::card ② 只有 1 天
- **上午**：A 组 10 题（项目题）全部练到能不看稿说
- **下午**：B 组 12 题 + C 组 8 题，每题先自己说 20 秒再看答案
- **晚上**：手撕 3 题 + 8.2 的轮次 A 完整走一遍（录音回听）

**目标**：项目题零瑕疵，技术题不冷场。
:::

:::card ③ 有 3 天
- **Day 1**：2.1/2.2 通读 + 数字口径背准（这是投入产出比最高的）
- **Day 2**：B 组 12 题溯源到 4.1/4.4/3.2/3.3/5.1/5.2 读正文 + 手撕 8 题各写一遍
- **Day 3**：C 组 8 题 + 8.2 三轮模拟（至少走 A、B 两轮）+ 8.3 得分项清单复习

**目标**：能扛两层追问，被质疑时不慌。
:::

## 5. 考前 10 分钟（进面试前的最后一遍）

:::card 只做这三件事
1. **默念 60 秒串讲**（判得准 → 查得到 → 扛得住）
2. **复核四个数字**：95.04/85.81/86.56/93.96 → 平均 **9.0pp**；HoVer 20% 数据 **+8.86pp**；ASR **96.5%**；Complete Success **88.25% vs 57.75%**
3. **提醒两条纪律**：先给结论再展开；不知道就说不知道

**不要**：翻新内容（只会增加焦虑）、背新题（记不牢还会挤掉已有的）
:::

## 6. 自测（检验"最小集"是否真的掌握）

:::qa 如果只能记住一个数字，记哪个
8B/GQA-8头/8k 的 KV cache ≈ 1 GB —— 因为它能被追问三层（公式/估算/并发上限）。
:::

:::qa 哪三题的答案最容易被自己说错
① MQA 省的是 KV cache 不是算力 ② DPO 需要 reference 不需要 RM ③ MoE 省算力不省显存。
:::

:::qa 为什么"项目题"排在前 10
因为面试 40–60% 时间在项目上，且只有这部分别人抄不走；技术题可以靠通用知识，项目题只能靠你。
:::

:::qa 2 小时计划里最该省掉的是什么
通读新内容。只做三件事：一句话答案、手撕 3 题、数字口径。
:::
