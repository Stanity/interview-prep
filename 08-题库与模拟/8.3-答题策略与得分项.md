# 8.3 答题策略：考察点与得分项（借鉴外部题库的框架）

> **这篇的来源**：我对照了 GitHub 上的主流题库（`wdndev/llm_interview_note` 15k⭐、`km1994/AIGC-Interview-Book` 800+ 考点），发现它们题目组织上有一个我们缺的中间层 —— 把「**考察点**（他在考什么）」和「**得分项**（说到什么才加分）」与「答案」分开。
> **本文把这层框架补给你**：不是改现有 672 张卡（成本过高），而是给一个**统一的答题结构 + 六类问题的得分项清单**。面试时套它，比背答案更稳。

---

## 1. 通用答题框架（四段，任何技术题都适用）

:::card 结论 → 机制 → 权衡 → 边界
| 段 | 说什么 | 时长 | 为什么必须 |
|---|---|---|---|
| **① 结论** | 一句话给出判断（"是/不是/取决于"） | 5–10 秒 | 面试官先要判断你有没有概念 |
| **② 机制** | 为什么成立（关键机制/公式） | 20–40 秒 | 区分"背过"和"懂" |
| **③ 权衡** | 代价是什么、什么场景不适用 | 15–30 秒 | **这是最容易加分的一段**，多数人只说优点 |
| **④ 边界** | 我知道到哪、不知道什么 | 5–10 秒 | 建立可信度，防止被挖穿 |

**关键**：第 ③ 段（权衡）是分水岭。比如讲 MoE，只说"省算力"是及格；补上"**但不省显存，带宽压力反而更大**"才是好答案。
:::

---

## 2. 「考察点 vs 表面问题」对照表（**最实用的一页**）

面试官的问题往往只是入口，真正在考的是另一件事：

| 他问的（表面） | 他其实在考（考察点） |
|---|---|
| "Attention 为什么除以 √d" | 你是否理解 softmax 饱和与梯度消失，而不只是记住公式 |
| "KV cache 怎么算" | 你是否真的估过显存、知道成本在哪 |
| "vLLM 为什么快" | 你懂不懂 **decode 是 memory-bound** |
| "DPO 和 PPO 区别" | 你是否知道 DPO 省掉了什么（RM + 在线采样） |
| "GRPO 是什么" | 你是否理解 value model 的作用（降方差） |
| "RAG 怎么优化" | 你是否**分层诊断**（检索 vs 生成）而不是罗列技巧 |
| "怎么评测 Agent" | 你是否知道**结果级不足以说明问题** |
| "为什么不用一个 Agent" | 你是否理解**上下文隔离与目标冲突** |
| "你用过多 Agent 框架吗" | 你**做过系统**还是只会调包 |
| "你的方法有什么不足" | 你是否**真的想过**，还是只在背优势 |

**用法**：听到问题时先在心里过一遍"他到底在考什么"，再决定答案往哪个方向强化。
:::

## 3. 六类问题的得分项清单（说到这些才加分）

:::card ① Transformer / 注意力类
**必说（及格线）**：Q/K/V 的作用、`softmax(QKᵀ/√d)V`、复杂度 `O(n²d)`。
**得分项（拉开差距）**：
1. **为什么除 √d** 用**方差**解释（`q·k` 方差 = `d_k` → 饱和 → 梯度消失）
2. 说清 attention 与 FFN 的复杂度对比（`O(n²d)` vs `O(nd²)`），并指出 **`n > d` 时注意力主导**
3. 面试官问"MQA/GQA 省什么"时，明确说**省 KV cache 显存，不是算力**
4. 主动提 **FlashAttention 是精确算法**（不改数学结果）
5. 被问长上下文时，指出瓶颈**不只是位置编码**（还有注意力稀释、lost in the middle、attention sink）
:::

:::card ② 推理 / KV cache 类
**必说**：KV cache 公式 `2×layers×n_kv×d_head×seq×batch×bytes`。
**得分项**：
1. **能现场算**（8B/GQA-8头/8k ≈ 1GB；80G 卡约 60 路并发）
2. 说清 **decode 是 memory-bound**，并给出算术强度 ≈1 FLOP/byte 的估算
3. 由此推出三条优化路线：**少读（量化/GQA）、一次搬完多用几次（大 batch）、一次验证多个 token（投机解码）**
4. PagedAttention 与连续批处理**是配套的**（分页让 KV 能零散申请，连续批处理才能随时插新序列）
5. 投机解码**无损**（接受规则 + 残差重采样）
:::

:::card ③ 后训练 / RL 类
**必说**：PT → SFT → 偏好对齐 → RL 的动机链条；DPO loss 形式。
**得分项**：
1. **DPO 为什么不需要 RM**（闭式解 + `Z(x)` 相消），以及**为什么仍需要 reference**
2. **DPO 的梯度说明自带难例挖掘**（权重 `σ(r̂_l − r̂_w)`）
3. GRPO 用**组内归一化替代 critic**，以及**组内奖励全同时优势为 0**
4. 主动提四个局限：长度偏置、likelihood displacement、off-policy、不能探索
5. 能说出**训练崩的三个信号**（奖励不升、熵塌缩、KL 暴涨）
6. 诚实边界：**没跑过 RL 训练**就说没跑过，但能讲清"第一步该做什么"（确认 pass@k ≠ 0）
:::

:::card ④ RAG 类
**必说**：五段链路（索引/检索/重排/生成/引用）。
**得分项**：
1. **先分层诊断**：Recall@k → 正确 chunk 在不在 top-3 → 塞进 context 后还在不在 → 答案对不对
2. 明确说 **"绝大多数 RAG 失败在检索，不在生成"**
3. chunking 给**父子块**（小块检索精度 + 父块上下文）
4. 混合检索的理由是**失效场景互补**（BM25 精确匹配 vs 稠密语义），融合用 **RRF（只用排名免调参）**
5. 双塔 vs cross-encoder 的分工（**能预计算 vs 必须在线**）
6. 评测讲 **faithfulness**（拆原子陈述逐条核验）+ 提醒 **context 错时"忠实但事实错"**
:::

:::card ⑤ Agent 类
**必说**：ReAct 循环、工具调用链路、四类终止。
**得分项**：
1. 讲范式时按**"每个修了上一个什么问题"**讲（CoT→ReAct→Plan→Reflexion→ToT），不是罗列
2. **四类终止**，并强调"**别只靠模型自评**"
3. 工具描述是"**最被低估的 prompt**"（写清何时用/何时不用）
4. 错误必须**归一化回传**（模型才有机会自愈）
5. **共享黑板要共享状态而不是上下文**（否则退化成单 Agent）
6. 评测讲三层 + **pass^k**（p=0.7 时 pass@3≈97% vs pass^3≈34%）
7. 没用过框架就说没用过，接"**我手写过等效编排**"
:::

:::card ⑥ 项目类（你自己）
**必说**：一句话定位 + 方法三件套 + 主结果。
**得分项**：
1. **数字口径说清**（"+9.0 是四数据集 vs 各自最强基线的平均"）
2. 主动给**提升分布**（+2.65/+14.85/+7.53/+11.13），说明方法的适用边界
3. **消融能讲"为什么掉了"**（对应哪种失败模式），不只是报数字
4. **失败 case 诚实**（6 个难例救回 3 个；"很果断地错"说明知识缺失）
5. 说清**你个人做了什么**（按定义/设计/实现/实验/写作五个动作）
6. 三条局限 + 一条最想改的方向
:::

## 4. 难度星级与时间分配（借鉴题库的优先级标注）

:::card 如果只有一天，按这个分配
| 星级 | 内容 | 要求 |
|---|---|---|
| **⭐⭐⭐** | 项目三篇（2.1/2.2/2.3）+ 2.4 交叉追问 + 数字口径表 | **必须背到零瑕疵**（占面试 40–60%） |
| **⭐⭐⭐** | KV cache 手算、DPO 推导、GRPO vs PPO、RAG 分层诊断、Agent 评测三层 | 必须能白板/口述 |
| **⭐⭐** | 注意力变体、MoE、量化方法、MCP 三原语、Memory 四类、多 Agent 拓扑 | 能讲清机制 + 一个权衡 |
| **⭐** | 分布式训练、推理框架横向、Tokenizer 细节、BERT/ChatGLM | 知道是什么、能接话 |
:::

**一句话**：「**⭐⭐⭐ 答不满分是灾难，⭐ 答不上来只是瑕疵** —— 时间要按这个优先级分配，而不是平均用力。」
:::

## 5. 三个"扣分陷阱"（比得分更值得记）

:::card 会被直接扣分的表达
1. **只讲优点不讲代价** → 立刻被追问"那它的缺点呢"，然后答不上
2. **数字含糊** → "提升了十几个点" → 追一句就露馅
3. **绝对化表达** → "MoE 一定比稠密好"、"提示注入可以防住" → 被反例打脸

**替换原则**：**任何结论都给一个适用条件**（"在什么场景下"、"代价是"）。
:::

:::card 一个高性价比的小技巧
**主动暴露一个边界**，能显著提升可信度：
> 「这块我只到原理层面，没做过调参。」/「这个数字我记得是 X，不排除有偏差。」

因为它传递的信号是"**这个人不会编**" —— 后面你说的所有话可信度都会上升。
:::

## 6. 自测（6 题）

:::qa 通用答题框架的四段，哪一段最容易加分
结论 → 机制 → **权衡** → 边界。「权衡」最容易加分，因为多数人只讲优点。
:::

:::qa 「Attention 为什么除以 √d」这题，面试官真正在考什么
考你是否理解 **softmax 饱和导致梯度消失**，而不只是记住公式。
:::

:::qa 「vLLM 为什么快」的满分答法关键点
不只说 PagedAttention，而要说出**decode 是 memory-bound**（算术强度≈1）、分页与连续批处理**配套**。
:::

:::qa 项目类问题的六个得分项里，最容易漏的是哪个
**提升分布**（不只报平均值）和**失败 case**（诚实说 3/6 救回）。
:::

:::qa 三个扣分陷阱
只讲优点不讲代价、数字含糊、绝对化表达。
:::

:::qa 主动暴露边界的价值
传递"不会编"的信号 → 后续所有话的可信度上升。
:::
