## 1. 30 秒口述版（背下来）

:::card 30 秒版
「这是我第二个工作，方向是 **RAG 系统的知识投毒**。

现有投毒研究都在优化一个指标：**ASR**——目标答案有没有被生成出来。但我发现一个问题：**答案命中并不等于攻击者控制了支撑这个答案的知识关系**。模型可能是因为答案泄漏、无关文本线索、或者自身的先验偏好而说出目标答案。

所以我把攻击能力从 **outcome-level control（结果级控制）** 提升到 **relation-level control（关系级控制）**：不仅要求 `q → y*`，还要求 `q → P* → y*`，也就是**攻击者指定的那条知识路径 P\* 必须是原因**。

方法上我叫 CausalPoison：先构造攻击者指定的恶意知识路径，用它约束候选文档生成；然后对每个候选构造**配套的 relation break 和 relation repair 变体**，观察目标答案是否按 **1 → 0 → 1**（原状态命中、破坏后消失、修复后恢复）的可逆行为变化；用这个行为一致性给候选打分排序，选出关系依赖最强的文档注入语料。

在 NQ、HotpotQA、MS MARCO、MuSiQue 四类 QA 上，ASR 平均 **96.5%**，比 PoisonedRAG 平均高 **8.5 个点**；更重要的是**关系级**指标：完整可逆成功（complete success）平均 **88.25%**，而 PoisonedRAG 只有 **57.75%**。」
:::

## 2. 3 分钟版（项目轮主线）

1. **背景**（20s）：RAG 靠外部知识提升事实性，但也因此暴露在语料投毒下。
2. **现有工作的共同目标**（25s）：都在做 **outcome level attack control** —— 让恶意文档被检索到 + 让 victim 生成目标答案。基线包括 Naive、Disinformation、Prompt Injection、HijackRAG、PoisonedRAG。
3. **核心 gap**（30s）：**产生目标答案 ≠ 控制了支撑它的关系/证据路径**。可能是 answer leakage、无关文本线索、模型先验偏好导致的"假成功"。
4. **我的重构**（30s）：提出 **relation controllable knowledge poisoning** 这个更强的攻击能力，目标从 `q → y*` 变成 `q → P* → y*`。
5. **方法四阶段**（45s）：构造恶意知识路径 → 路径约束的候选生成 → break/repair 干预与三状态评估 `1→0→1` → 按 `S_state` 排序选 top-m。
6. **实验**（30s）：4 数据集 × 100 query（共 400）、6 个 victim generator、5 个基线、4 个检索器；ASR 96.5%（+8.5pp）、complete success 88.25% vs 57.75%、relation preserving control failure 5.5% vs 13.0%。

## 4. 核心概念：outcome-level vs relation-level（全文灵魂，必须讲透）

:::card 两种攻击能力的区别
**Outcome-level attack control（现有工作的目标）**
只要 victim 生成了攻击者指定的答案 `y*`，就算成功。指标是 ASR。
**问题**：模型可能因为别的原因说出 `y*` —— 答案泄漏、无关的文本线索、模型自身的先验偏好。**这时投毒"成功"了，但你并没有控制支撑它的知识。**

**Relation-level attack control（本文提出）**
要求答案**依赖于攻击者指定的知识路径** `P*`：
```
q → P* → y*        (公式 1)
```
poisoned evidence 必须在三种状态下表现出可逆行为：
- 指定关系**存在**时 → 诱导出目标答案（`Y⁺ = 1`）
- 关系被**破坏**时 → 目标答案消失（`Y⁻ = 0`）
- 同一关系被**恢复**时 → 目标答案回来（`Y^rep = 1`）

即 **`1 → 0 → 1`**（公式 6）。这种**可逆的行为响应**，就是"关系依赖"的可观测证据。
:::

:::card 为什么"可逆"比"消融"更有说服力（必答追问）
如果只做"删掉某段文档再看答案有没有消失"（一次性消融），无法区分：
- 答案消失是因为**关系**没了，还是因为**文档整体被改了**（长度、风格、相关性都变了）？

CausalPoison 的做法是构造**配套的 break 和 repair 变体**：
- break 只让**指定关系失效**（改目标实体 / 反转关系方向 / 换成不兼容的替代关系），**其余实体、无关信息、文档长度、写作风格尽量保持不变**
- repair 从**被破坏的文档**重建，只恢复同一条关系，其余内容尽量保留

于是"破坏后消失、修复后回来"就构成了一个**可逆的反事实测试**：只有真正依赖这条关系的文档，才会按 `1→0→1` 走。论文还额外报告了**语义相似度**（Table 5，三组平均 88~91%），证明变体在文档级语义上高度接近，改动是"局部的"。
:::

:::card 一个必须说清的边界（防止被"你这算真因果吗"一击致命）
论文自己明确写了：这里的"因果"是**操作性定义（operational）**。

> CausalPoison 衡量的是"**攻击行为如何随指定关系的移除与恢复而变化**"，是在**输入-输出层面**度量可逆的关系依赖，**并不试图恢复 victim 模型内部的因果结构或潜在推理过程**。

**面试话术**：「我用的是干预主义的因果概念——**能被我干预、并且表现为可逆响应**，就算依赖。这不是在做模型内部机制的可解释性，是在做**行为层面的因果检验**。这个边界论文里写得很清楚。」
:::

## 5. 方法：四阶段 + 九个公式

### 5.1 总流程（公式 2）

```
q, y*  →  P*  →  {d₁⁺, …, dₙ⁺}  →  {dᵢ⁺, dᵢ⁻, dᵢ^rep}  →  S_state^i  →  A        (公式 2)
```

**四阶段**：① 构造恶意知识路径 `P*` → ② 路径约束的候选生成 → ③ 构造 break/repair 变体并评估三状态 → ④ 按 `S_state` 排序选 top-m 注入语料。

### 5.2 恶意知识路径构造（公式 3）

:::card 路径是什么
每条恶意关系是一个三元组：源实体 `s_j`、语义关系 `ρ_j`、目标实体 `o_j`
```
r_j* = ⟨s_j, ρ_j, o_j⟩
P*   = {r_1*, r_2*, …, r_h*}              (公式 3)
约束：o_j = s_{j+1}                        （相邻关系必须共享中间实体）
```
- **单跳 / 直接事实查询**：`P*` 只有一条主关系（查询实体 → 目标答案）
- **多跳查询**：`P*` 由多条**连通**关系组成，规定中间实体如何一步步通向目标答案

**为什么这一步是"先验约束"而不是"事后解释"**：路径在**生成投毒文档之前**就固定了，因此它不是观察 victim 输出后编出来的解释，而是**生成时的语义约束**。
:::

### 5.3 路径约束的候选生成（公式 4）

```
d_i⁺ ~ f_s[q, y*, P*]                       (公式 4)
```

每个候选必须表达 `P*` 里的**实体、关系方向、关系连接**。对多跳查询，候选要**显式连接中间实体**，而不是罗列几条无关的恶意陈述。

> **关键点**：只给 `y*` 是不够的（那会退化成 PoisonedRAG）；给 `P*` 才能让候选"长"出指定结构。

### 5.4 关系破坏与修复（公式 5、6）

```
Y_i^z = 1{ ŷ_i^z ≃ y* },   z ∈ {+, −, rep}          (公式 5)
期望行为：Y_i⁺ = 1,  Y_i⁻ = 0,  Y_i^rep = 1           (公式 6)
```

:::card break 和 repair 具体怎么改（面试官会追问细节）
**Break（破坏指定关系，其余尽量不动）**，按关系类型三选一：
1. **修改目标实体**（换个 object）
2. **反转关系方向**（把 A→B 改成 B→A）
3. **替换为不兼容的替代关系**

约束：**保留其余实体、无关信息、文档长度、写作风格**，目标是"让指定语义依赖失效，但文档看起来没坏、也没跑题"。

**Repair（从被破坏的文档重建）**：**只**恢复同一条指定关系，其余内容尽量沿用被破坏的版本。

> 注意：**repair 是从 break 后的文本重建的，不是从原文复制**。这是"可逆性"论证的关键——否则就退化成"把原文放回去当然能恢复"。
:::

### 5.5 状态匹配打分与选择（公式 7、8）

:::card 打分公式
```
S_state^i = ( Y_i⁺ + (1 − Y_i⁻) + Y_i^rep ) / 3        (公式 7)
```
三项**等权**：
- 第 1 项 `Y_i⁺`：**原始状态下的攻击有效性**（能不能诱导出目标答案）
- 第 2 项 `1 − Y_i⁻`：**破坏后必须被抑制**
- 第 3 项 `Y_i^rep`：**修复后必须恢复**

`S_state = 1` 表示完全符合期望的可逆行为；分数越低说明某一状态没按预期走。

**选择**（公式 8）：
```
A = TopM( {d_i⁺}, S_state^i ),  |A| ≤ m
```
先做**有效性过滤**（`Y_i⁺ = 1` 才进入排序），再按 `S_state` 取 top-m。
:::

### 5.6 注入语料（公式 9）

```
D' = D₀ ∪ A                                 (公式 9)
```

:::card 一个容易漏掉的工程点
**只有原始版本被注入**，break 和 repair 变体**只用于候选评估，不进知识库**。

另外：关系级控制**不能免除检索要求** —— 恶意文档不被检索到就没用。所以沿用 PoisonedRAG 的 **retrieval enhancement**：**把 target query 前置到每个投毒文档**。这个操作只提升检索命中率，**不参与** `S_state` 打分。
:::

### 7.6 Relation Preserving Control（Table 6）——**最能证明"特异性"的实验**

| Dataset | PoisonedRAG | CausalPoison |
|---|---|---|
| NQ | 16.0% | **4.0%** |
| HotpotQA | 15.0% | **8.0%** |
| MS MARCO | 19.0% | **9.0%** |
| MuSiQue | 2.0% | **1.0%** |
| **平均** | **13.0%** | **5.5%** |

:::card 这个实验的精妙之处（讲出来很加分）
**做法**：构造一个"relation **preserving** control" —— 修改**与指定关系无关**的内容，但**保留**那条关系本身。

**逻辑**：如果攻击被抑制是因为"文档被改了"（而非关系被破坏），那么这个 control 也应该导致攻击失败 → **control failure rate 高**。

**结果**：CausalPoison 只有 **5.5%**，PoisonedRAG 是 **13.0%**。

**结论**：攻击效果**对"指定关系的变化"敏感**（break 后失败率高），而**对"无关内容的变化"不敏感**（preserving control 失败率低）。这个"敏感/不敏感"的对比，才是"关系依赖"最干净的证据。
:::

### 7.7 消融（Table 7）

- **去掉 intervention guided selection**：HotpotQA、MS MARCO、MuSiQue 的 ASR 下降，**NQ 不变**（NQ 是单跳，关系结构简单，干预筛选的边际收益小）
- **去掉 malicious knowledge path**：**四个数据集全部下降**，其中 **NQ 和 MS MARCO 下降最大**

**话术**：「路径构造比干预筛选更关键 —— 因为路径决定了候选的**语义结构**，而筛选只是从已有候选里挑更好的。NQ 上筛选无收益也说明：单跳场景的候选本来就容易满足关系约束。」

### 7.8 检索鲁棒性（Table 9）与检索深度（Figure 3）

- **4 个检索器**下平均 **ASR 保持 0.97**，平均 Retrieval F1 为 **0.97~0.99**，数据集级别**跨检索器波动不超过 2 个百分点**

- 解释：恶意证据占检索上下文比例下降 → 干净证据竞争加剧

> **面试价值**：这组数据让你能回答"你的攻击在实际系统里还成立吗"——**成立，但依赖攻击预算与检索深度的比例**。

### 7.9 防御（Defenses）

论文单独有一节 Defenses，并做了 **query paraphrasing** 防御实验（Table 10：无防御 vs query paraphrasing 防御下的攻击效果）。**这一节你要自己过一遍原文**（我没在本次提取中逐段核对），面试时只说你有把握的部分。

**防御侧你能讲的三条**（面试官一定会问"那怎么防"）：
1. **来源可信度与签名**：语料入库要可溯源
2. **多源一致性**：同一事实要求多个独立来源支持，单文档不能决定答案
3. **检索多样性 + 答案级核验**：不要让单一文档垄断上下文；对答案做引用核验

## 8. 十二个追问预答

:::qa 你这算"真因果"吗？还是一次普通消融实验
关键区别在于**可逆性 + 配套变体 + 特异性对照**三层：
1. **可逆**：不只是"删了会怎样"，而是要求 `1 → 0 → 1` 的完整往返；
2. **配套变体**：break 只动指定关系（实体/方向/替代关系），repair 从**被破坏文本重建**（不是复制原文）；
3. **特异性对照**：relation **preserving** control 证明攻击对"无关内容变化"不敏感（失败率 5.5% vs 13.0%）。
另外论文明确说了这是**操作性（operational）**因果：度量"行为如何随关系干预而变化"，不声称恢复模型内部因果结构。
:::

:::qa 为什么必须"预先指定"支撑关系？事后分析不行吗
事后分析的问题是可以**编故事**：看到模型输出了目标答案，再反向构造一条"解释"很容易，但这不能证明攻击**依赖**它。
预先指定 `P*` 的作用是：**先立一个可被推翻的假设**，然后用 break/repair 去检验。这更接近预注册（pre-registration）的思路。
:::

:::qa break 的时候怎么保证"只改了关系，没改别的"
三条约束 + 一个证据：
- break 只做三种操作之一（改目标实体 / 反转方向 / 换不兼容关系），**保留其余实体、无关信息、文档长度、写作风格**
- repair 是从 break 后的文本重建的，**不是把原文放回来**
- **Table 5 的语义相似度**：三组变体平均 88~91%，original 与 repaired 相似度最高（91.03%）→ 改动是局部的
:::

:::qa 为什么 repair 要从被破坏的文本重建，而不是直接用原文
如果用原文，"修复后恢复"就变成"把原文放回去当然有效"，**证明不了任何东西**。
只有从**被破坏的文本**重建、只恢复那一条关系，才能说明"是这条关系的恢复导致答案回来"，而不是"原文整体回来了"。
:::

:::qa S_state 三项等权合理吗？为什么不加权
论文用等权（`/3`）有三个理由：
1. **可解释**：三项分别对应"有效 / 被抑制 / 恢复"，语义对称；
2. **避免调参**：加权会引入新超参，而攻击场景下没有验证集可调；
3. **配合硬约束**：`Y⁺ = 1` 已经作为**过滤条件**先筛掉了不有效的候选，剩下两项是主要的区分项。
:::

:::qa 你的 ASR 只比 PoisonedRAG 高 8.5 个点，是不是提升很小
这是**最有价值的一个追问**，标准答案是"看哪个指标"：
- **ASR**：+8.5pp（96.5% vs 88.0% 左右）——提升确实有限，因为 outcome 级控制**已经被前作做到了接近饱和**（PoisonedRAG 在 HotpotQA 上已经 0.94）。
- **关系级**：Complete Success **88.25% vs 57.75%**（+30.5pp）；Break Failure **6/4/2/10% vs 34/40/25/43%**。
**结论句**：「在 ASR 接近饱和的情况下，我把评估维度换了——从"有没有说出答案"到"是不是靠我指定的关系说出来的"，这才是本文的贡献。」
:::

:::qa Break Failure 那一列最能说明什么
它衡量"**关系被删掉后，目标答案还在**"的比例。PoisonedRAG 高达 **34/40/25/43%**，说明它相当一部分"成功"其实是**不依赖指定关系的假成功**（靠答案泄漏、表层线索或模型先验）；CausalPoison 只有 **6/4/2/10%**。
:::

:::qa 为什么 HotpotQA 上 ASR 能到 1.00
HotpotQA 是多跳（2-hop 为主），恶意文档需要连接两个实体 —— 这恰恰是**路径约束**最擅长的场景：`P*` 显式规定了中间实体，所以候选文档天然携带"两个 hop 的连接"，检索到一篇就够支撑推理，不需要模型自己去连。
同时这也解释了 **MuSiQue（2–4 hop）只有 0.96**：hop 越多，单文档覆盖整条路径越难。
:::

:::qa 检索深度一加大攻击就掉，这说明什么
说明攻击**依赖恶意证据在上下文中的占比**。k 从 5 到 20 时：
- NQ 0.98 → 0.88、MuSiQue 0.96 → 0.91（相对稳）
- **HotpotQA 1.00 → 0.62、MS MARCO 0.92 → 0.34**（掉很多）
原因是干净证据稀释了恶意证据。工程含义：**防御方增加检索宽度/多样性，是有效的缓解手段**（虽然不能根治）。
:::

:::qa 换检索器还成立吗
成立。四个检索器上**平均 ASR 保持 0.97**，平均 Retrieval F1 0.97~0.99，数据集级别波动 ≤2pp。说明方法不绑死在某个检索器上。
:::

:::qa 消融里为什么 NQ 去掉 selection 不下降
因为 NQ 是**单跳**：候选只需要"一条主关系"，20 个候选中满足 `1→0→1` 的比例本来就高，**筛选的边际收益接近 0**。
而多跳数据（HotpotQA/MS MARCO/MuSiQue）候选质量参差，筛选才关键。这也侧面说明**路径构造**（去掉它四个数据集全掉）是更基础的一环。
:::

:::qa 这是攻击研究，伦理上怎么说
三条：
1. **贡献是评估方法**：提出了一个**更强的评估维度**（relation-level），让防御研究有更严格的靶子 —— 原来的 ASR 会**高估**攻击成功率（因为含大量假成功）；
2. **没有释放攻击工具**：方法依赖 GPT-4.1 做 surrogate，成本高、难以规模化滥用；
3. **直接指向防御**：break failure / preserving control 这些指标本身就是**给防御方用的诊断工具**（能定位"你的系统是真的抗投毒，还是只是答案没被钓出来"）。
:::

| ❌ 别这么说 | ✅ 换成这么说 |

## 11. 自测（合上文档，60 秒答完每题）

:::qa 一句话说清 outcome-level 和 relation-level 的区别
Outcome-level 只要求 victim 说出目标答案；relation-level 还要求这个答案**依赖攻击者指定的知识路径**，并用 `1→0→1` 的可逆行为来验证。
:::

:::qa 什么是"假成功"？谁的数字最能体现它
假成功 = 生成了目标答案，但**不依赖指定关系**（靠答案泄漏、表层线索、模型先验）。
最能体现的是 **Break Failure**：PoisonedRAG 34/40/25/43%，CausalPoison 6/4/2/10%。
:::

:::qa S_state 的公式和三项含义
`S_state = (Y⁺ + (1 − Y⁻) + Y^rep) / 3`：原始状态有效、破坏后被抑制、修复后恢复，三项等权。
:::

:::qa 为什么 repair 必须从被破坏文本重建
否则等于"把原文放回去"，无法证明"是这条关系的恢复导致答案回来"。从破坏文本重建、只恢复指定关系，才是真正的可逆性检验。
:::

:::qa relation preserving control 这个实验想证明什么？结果是多少
证明攻击失败**不是因为文档被改了**，而是因为**关系被破坏**：改无关内容但保留关系时，CausalPoison 的 control failure 只有 **5.5%**，PoisonedRAG 是 **13.0%**。
:::

:::qa 面试官说"ASR 只高 8.5 个点，贡献有限"，你怎么答
承认 ASR 接近饱和（PoisonedRAG 在 HotpotQA 已 0.94），然后把话题带到关系级：Complete Success 88.25% vs 57.75%（+30.5pp），Break Failure 从 30+ 降到个位数 —— **贡献在于换了评估维度，不是把 ASR 再抬高一点**。
:::

:::qa 检索深度加大后攻击会怎样？为什么
会掉：k 从 5→20，HotpotQA 1.00→0.62、MS MARCO 0.92→0.34（NQ/MuSiQue 较稳）。原因是干净证据稀释了恶意证据占比 —— 这解释了为什么"增加检索宽度/多样性"是有效缓解手段。
:::
