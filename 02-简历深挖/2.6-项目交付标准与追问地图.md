# 2.6 项目交付标准与追问地图（做到什么程度才敢写简历）

> **这篇的来源**：借鉴 `youngyangyang04/llm-master` 的一个很好设计 —— 它给每个项目配了**"最低交付标准"**（比如 AI 助手要带异常处理、Token 统计、自动化测试；生产服务要有 **P99 / TTFT / TPOT / Goodput / 容量报告**）。
> **这篇给你两样东西**：① 三个项目的**交付标准对照**（你现在达到哪一档）② 每一档对应的**追问地图**（他会问什么、你该怎么答）。
> **标注**：`★★★` 面向"我到底该怎么说我的项目"

---

## 1. 为什么需要"交付标准"

:::card 一个残酷的事实
面试官判断"你的项目值多少分"，看的不是**你做了多少**，而是**它能承受多深的追问**。

同一句话"我做了个多智能体检索系统"：
- **原型级**说法 → 只能答一层，第二层就"这个没细看"
- **研究级**说法 → 能答三层（为什么这样设计、掉了什么、失败在哪），并且**主动划出边界**
- **生产级**说法 → 还能答部署细节（QPS、P99、成本、灰度、回滚）

**你现在的位置是"研究级"**（有两篇论文支撑），所以策略是：**把研究级讲满，明确承认生产级没做**，而不是假装生产级。
:::

## 3. 追问地图（每个项目会被挖到哪里）

:::card RePref-Fact 的四层追问
```
L1 是什么：你的方法一句话？
L2 为什么：为什么要减参考模型？为什么加表示层两项？
L3 数字/细节：α、γ 多少？消融掉多少？最强基线多少分？基线是怎么跑的？
L4 反事实：如果去掉偏好 loss 只留对比会怎样？换成 32B 还成立吗？这算原创吗？
```
**L3 是分水岭**：能答 L3 才算真做过。你的 L3 缺口是 **α、γ**（论文未披露，已给话术）。
:::

:::card CausalPoison 的四层追问
```
L1 是什么：核心贡献？
L2 为什么：为什么 repair 要从破坏文本重建？为什么 S_state 三项等权？
L3 数字：ASR 多少？Complete Success 多少？Break Failure 多少？24 个配置里那 3 个是什么？
L4 反事实：这算真因果吗？换个 victim 还成立吗？怎么防？
```
**L4 的"那怎么防"必须张口就来**（5.6 已备）。
:::

:::card 多智能体检索的四层追问
```
L1 是什么：为什么是多轮多 Agent？
L2 为什么：为什么不用一个 Agent？循环怎么停？
L3 数字：+3.7pp 对比的是谁？成本多少？消融做了哪些？
L4 反事实：和 Adaptive-RAG 什么区别？能上生产吗？长程任务行不行？
```
**L3 的"成本多少"是你最可能卡的地方** —— 见 §4 的诚实答法。
:::

## 4. 三个"缺口"的诚实答法（背下来）

:::card ① 成本没统计（多智能体项目）
> 「我没有系统统计过多轮检索的成本 —— 这是我认为投稿前必须补的一项。因为多轮方法的收益必须和**检索次数、token 消耗**放在一起看才有意义。我知道该怎么算：固定一批 query，对比单轮/固定多轮/我的方法的平均检索次数与 token，再除以准确率提升。」

**为什么这样答好**：承认缺口 + 说明你知道该怎么补 = 成熟。
:::

:::card ② 没有生产环境经验
> 「我没有生产环境经验：没有 serving、没有线上监控、没有高并发。但我做过的工程强度不小 —— 四检索器 × 多生成模型的全语料评测、400 个 query 的三状态干预评估、完整的消融矩阵。这些都需要可复现脚本、统一配置、失败重试与结果聚合。**缺的是生产环境的打磨，不是工程习惯。**」
:::

:::card ③ 没有开源
> 「目前没有开源。CausalPoison 属于攻击方法，我不想直接释放可复现的攻击工具；RePref-Fact 的训练代码我打算在论文正式发表后整理开源。」
:::

## 5. 简历上必须先修的三处（**面试前务必处理**）

:::card 三处数字/口径问题
| # | 问题 | 建议 |
|---|---|---|
| 1 | 简历写「替换支撑关系后答案率 **95.0% → 23.0%**」 | 论文终版**无此数字**（Table 4 的 Break Failure 是 6/4/2/10%）→ 删掉或改成 Table 4 的口径 |
| 2 | 简历写「关系级可逆性 **68.2%**」 | 论文无此数 → **建议换成 Complete Success 88.25%（PoisonedRAG 57.75%）** |
| 3 | CausalPoison 投稿会议 | PDF 版权页是 USENIX，简历写 WWW 2027 → **核对后统一** |

**为什么必须修**：面试官顺着这三个数字任一追问"分子分母是什么"，答不上来会让**前面所有真实数据都变得可疑**。宁可少一个数字，不要多一个说不清的。
:::

## 6. 如果要把项目"升级到生产级"，该补什么（面试被问"你会怎么继续"时用）

:::card 三个项目各自的升级路径
| 项目 | 从研究级 → 生产级要补什么 |
|---|---|
| **RePref-Fact** | ① 多 seed 与置信区间 ② 推理服务的 P99/TTFT ③ 数据漂移监控（新数据的标签分布变化） ④ 与业务指标的关联（不是只看 Macro-F1） |
| **CausalPoison** | ① 做成**回归测试工具**（每加一层防御跑一次可逆性） ② 成本可控的 surrogate ③ 与线上语料审计打通 |
| **多智能体检索** | ① **trace 与回放** ② 成本统计与预算控制 ③ checkpoint 断点恢复 ④ 评测集与回归门禁 |

**面试话术**：「如果继续做，我会先补**成本统计**和**trace** —— 因为这两个不解决，其他的优化都无法判断是否真的有用。」
:::
