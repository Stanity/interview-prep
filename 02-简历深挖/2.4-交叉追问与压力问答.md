## 1. 三套串讲版本（按时间长短准备）

:::card 60 秒版（自我介绍 / 面试开场）
「我是孙锦洋，中科院信工所网络空间安全专业硕士，2027 届，研究方向是大模型的可信推理与安全。

我的工作围绕一个问题：**大模型在事实层面到底可不可信**。我从三个侧面做：**判得准**——用标签空间相对偏好学习把事实核查的判别边界做稳，这篇被 SMC 2026 录用；**查得到**——用证据状态驱动的多智能体动态检索解决复杂声明的证据分散问题；**扛得住**——把 RAG 知识投毒的评估从"答案有没有命中"推进到"答案是不是依赖我指定的知识关系"，投毒检测的 ASR 96.5%、关系级可逆成功 88.25%。

工程上我是 Python / PyTorch 为主，做过 LoRA 微调、四种检索器的全语料评测、多智能体编排的手写实现。算法方面有 ICPC 亚洲区银牌。」
:::

:::card 3 分钟版（项目轮开场，面试官说"讲讲你的项目"）
**主线一句**：「我做的事情可以概括成一句话：**让大模型在事实层面可信 —— 先判得准，再查得到，最后测得出它有多容易被骗。**」

**第一段：判得准（RePref-Fact）**
「事实核查的难点是支持和反驳的样本语义高度相似，差别常常只在数字、实体、时间或一个否定词上。现有方法都在做 point-wise 分类，独立优化正确标签，没有显式建模它相对竞争标签的优势。我把它重构成**标签空间上的相对偏好学习**：用冻结参考模型给出标签间优势作基线，构造偏好 gap 让模型去扩这个间隔；同时在表示层加了两个互补目标——标签 embedding 原型的互信息对齐保住标签信息，监督对比学习保证类内紧凑、类间可分。四个数据集上对比各自最强基线，Macro-F1 平均提升 9.0 个点。这篇被 SMC 2026 录用。」

**第二段：查得到（多智能体动态检索）**
「到了复杂声明，单轮静态检索不够——证据分散在多个源、可能相互冲突、还要多跳定位。我设计了**证据状态驱动**的多智能体框架：把声明拆成可验证子目标，三类子 Agent（补全 / 反驳 / 冲突消解）共享一份证据状态，用事实依赖图决定检索顺序，再按证据覆盖情况动态选检索策略。核心是把一次性检索变成**由状态反馈驱动的多轮决策**。」

**第三段：扛得住（CausalPoison）**
「最后一层是安全。现有 RAG 投毒研究都在优化 ASR，但**答案命中不等于控制了支撑答案的知识关系**——模型可能因为答案泄漏、无关线索或先验偏好说出目标答案。我把攻击能力从 outcome-level 提升到 relation-level：要求 `q → P* → y*`，方法是先构造恶意知识路径，再对每个候选做**关系破坏与修复的可逆干预**，看目标答案是否按 `1→0→1` 变化，按这个行为一致性给候选打分。四类 QA 上 ASR 96.5%，但真正的贡献在关系级：complete intervention success 88.25%，而 PoisonedRAG 只有 57.75%，它的 break failure 高达 34~43%。」

**收尾一句**：「这三块合起来，就是我认为 Agent 落地必须回答的三个问题：**判得准、查得到、靠得住**。所以我投 Agent 岗不是转方向，而是把中间"证据获取"这一段从单轮检索升级成状态驱动的多轮决策 —— 这正是 Agent Loop 要解决的问题。」
:::

## 2. 三个项目之间的关系（12 种交叉追问）

面试官经常从 A 跳到 B，考的是"你到底有没有体系"。下面 12 组是覆盖概率最高的。

### 2.1 主线叙事类

:::qa 这三个项目是不是同一件事换个说法
不是，它们是同一个问题的**三个不同层次**：
- **判得准（RePref-Fact）**：给定证据后，判断这一层怎么做得稳 → 模型侧
- **查得到（多智能体检索）**：证据还没到手时，怎么把它找全找对 → 系统侧
- **测得出被攻击的程度（CausalPoison）**：证据被污染时，系统会怎样、依赖了哪条知识 → 评估侧

**一句话**：「前两个是能力建设，第三个是**度量**——你得能说清系统在什么条件下会失效，才能谈落地。」
:::

:::qa 为什么先做判别、再做检索、最后做安全？顺序有讲究吗
是我研究推进的自然结果，但回头看有内在逻辑：
1. 先做**判别**，因为这是事实核查的核心任务，也最容易量化；
2. 做判别时发现**证据质量**是瓶颈（尤其是多跳），于是转向**检索**；
3. 做完检索意识到"检索到的东西本身可能是**被投毒的**"，于是转向**安全与评估**。

**加分句**：「所以我的研究线是**被问题推着走的**，不是先定三个方向再各做一个。」
:::

:::qa 三个项目的共同方法论是什么
三个项目都用了同一个思路：**构造对照组，用"差异"而不是"绝对表现"来下结论**。
- RePref-Fact：正确标签 vs 竞争标签（再减去参考模型的基线）
- 多智能体：有冲突消解 vs 没有（消融）
- CausalPoison：原状态 vs 破坏 vs 修复（`1→0→1`）

**一句话**：「我不太相信"我的方法分数高"这种结论，我更相信"**干预之后变化的方向对不对**」。
:::

### 2.2 技术互串类（最容易翻车，务必准备）

:::qa 你的偏好学习方法能用到投毒检测上吗
能，而且是个好问题。思路是：
- 投毒检测本质是判断"这段证据与模型已知知识是否**一致**"
- 可以把"一致 / 不一致"当成两个**标签假设**，用我的相对偏好框架来判断
- 冻结参考模型在这里的角色是"**未被污染的基线**"——正好对应投毒场景里"干净模型"的假设

**诚实边界**：「这是我在**想**的方向，没有实验。而且有个明显风险：如果投毒比例很高，参考模型也可能被污染。」
:::

:::qa CausalPoison 的"破坏-修复"能不能用在你的事实核查上
本质上它就是一种**数据增强/鲁棒性检验**：
- 对事实核查样本，我可以把"决定性线索"破坏再修复（比如把数字 12% 改成 21% 再改回来）
- 检验模型是否**真的依赖那条线索**，而不是靠表层模式
- 这正好对 RePref-Fact 要解决的 "label boundary ambiguity" —— **它能给出一个更细粒度的诊断指标**，而不只是 Macro-F1

**加分句**：「Macro-F1 只能告诉我"判对了多少"，可逆干预能告诉我"**判对的那些里有多少是真的看对了地方**」。这是我下一步想做的。
:::

:::qa 多智能体的证据状态和 RePref-Fact 的表示学习有关系吗
两者处在不同层，但可以接起来：
- **证据状态**是**符号层**的结构化工作记忆（哪些子目标覆盖了、证据置信度、冲突标记）
- **RePref-Fact 的表示**是**向量层**的判别表征

可以接的地方：把证据状态作为**额外条件**注入表示（类似 RAG 的 conditioning），或者用证据覆盖率作为**样本难度权重**去调整偏好 loss 的权重（难样本、证据不全的样本加大权重）。

**诚实**：「这是思路，没做实验。」
:::

:::qa RAGtruth 在 RePref-Fact 里是数据集，在 CausalPoison 里是主题，两者什么关系
这是个巧合但很自然的连接：
- **RePref-Fact 用 RAGtruth 做"RAG 输出幻觉检测"**，本质是判断"生成的内容有没有证据支撑" → 这是**判别**问题
- **CausalPoison 研究"注入的知识能不能操纵生成"** → 这是**攻击**问题

两者是同一枚硬币的两面：**幻觉检测是"内容与证据不一致"，投毒是"证据被蓄意伪造"**。所以我在 RePref-Fact 里练的"证据-结论一致性判别"，正好是 CausalPoison 里"关系依赖度量"的基础。

**一句话**：「一个是防守（识别不支撑），一个是进攻（制造假支撑），用的是同一套'证据是否真的支撑结论'的判断。」
:::

## 3. 15 个攻击性提问（压力面预演）

:::qa 【攻击】9.0 个点是不是因为 baseline 太弱
**先承认口径，再给数据**：
- 我的 baseline 是**同期方法在同设置下的复现**，不是照抄论文数字，而且包括 prompt 式和 SFT 式两类
- 最强基线在 FEVEROUS 上是 BiDeV **92.39**（很强），我们的提升只有 **+2.65**
- 提升主要来自 HoVer（+14.85）和 SciFact（+11.13）—— 这两个的共同点是**需要细粒度证据聚合**

**收尾**：「所以不是"平均提升大所以方法好"，而是**提升的分布告诉我们方法在什么场景有效**：边界敏感和多跳聚合的场景收益大，已经很强的单跳场景收益小。」
:::

:::qa 【攻击】你的平均 9.0 是不是挑了数据集
不是，四个都提升了。而且我把"提升分布"主动说出来比藏起来更有说服力：
FEVEROUS +2.65 / HoVer +14.85 / RAGtruth +7.53 / SciFact +11.13，平均 9.04。
**如果我要挑，就不会把 +2.65 那个放在主表里。**
:::

:::qa 【攻击】你这个方法的 novelty 在哪？不就是 DPO + 对比学习 + 互信息拼起来
**承认结构来源，强调问题重构**：
1. 公式 (2) 的 log-sigmoid 确实借了 DPO 形式，但**偏好对是标签而不是回答**、**参考模型用来做难度归一化而不是 KL 约束**
2. `L_MI` 和 `L_SCL` 都是标准组件，但**它们和 `L_pref` 的关系是我设计的**：一个管输出层间隔，两个管表示层的信息与几何，消融证明三者各自对应一种失败模式（−2.51 / −1.78 / −1.66）
3. **novelty 不在组件，在问题重构成"标签空间偏好"** —— 把判别任务从"分类"变成"比较"

**收尾**：「如果说这是工程组合，那它至少是**有消融支撑的组合**：我知道每个组件去掉会掉在哪。」
:::

:::qa 【攻击】你的攻击 ASR 只比 PoisonedRAG 高 8.5 个点，贡献是不是很小
这是**最好的一个追问**，答案要主动重构评价维度：
- **ASR 已经接近饱和**：PoisonedRAG 在 HotpotQA 上已经 0.94，天花板就在那
- **真正的贡献是换评估维度**：Complete Success **88.25% vs 57.75%**（+30.5pp）；Break Failure **6/4/2/10% vs 34/40/25/43%**
- 换句话说：**前作的"成功"里有 30~40% 是假成功**（不依赖指定关系）

**一句话**：「ASR 上我只是把天花板推了一点，但我证明了**原来的天花板有很多是虚的**。」
:::

:::qa 【攻击】你的实验用 GPT-4.1 做 surrogate，模型一升级方法就废了
- **不是依赖模型能力，是依赖"能构造路径 + 能评估三状态"**，任何同等能力的模型都可以替换（论文里跨模型验证用了 Gemini 2.5 Pro，complete success 89/88/85/78%，说明行为可迁移）
- 而且**攻击成本上升本身是好事**（对社会而言），说明这个方法不适合大规模滥用
:::

:::qa 【攻击】你做攻击研究，伦理上有问题吗
三条：
1. **贡献是评估方法**：原有 ASR 会**高估**攻击成功率（含大量假成功），我给出了更严格的度量，对防御研究更有价值
2. **不释放工具**：依赖 GPT-4.1 surrogate、成本高，不易规模化
3. **指标可直接用于防御**：break failure / preserving control 是**诊断工具**（能定位"系统是真抗投毒，还是只是答案没被钓出来"）
:::

:::qa 【攻击】你个人到底做了什么？还是导师做的
**必须具体到动作**（这是最容易翻车的一题）：
> 「两篇我都是第一作者。具体到动作：
> - **RePref-Fact**：问题重构（把分类改成标签空间偏好）、设计偏好 gap 与三项联合目标、实现 PyTorch 训练与评测流水线、跑完消融/骨干对比/超参/低资源/噪声/案例/t-SNE 全套实验、写论文。
> - **CausalPoison**：提出 relation-level 这个评估维度、设计 break/repair 干预协议与 `S_state` 打分、实现路径构造的代码级校验（中间实体与关系不满足约束就重生成）、搭建 4 检索器 × 6 victim 的全语料评测、做 relation preserving control 这个特异性对照。
> - **多智能体检索**：证据状态字段设计、三类子 Agent 的职责划分、事实依赖图调度、策略层分发、终止条件。」

**注意**：把"我"和"我们"分清楚。凡是说"我们"的地方，面试官都会追问"你做了什么"。
:::

:::qa 【攻击】你有没有实习经历
诚实 + 把话题拉回能力：
「没有大厂实习。我的时间主要花在论文上（两篇第一作者）。🟡 如果有短期合作/项目经历，就补一句；没有就说：**我缺的是工业环境下的协作与交付节奏，这块我打算用入职后的前三个月补。**」
:::

:::qa 【攻击】你的三个项目哪个最难？为什么
选 **RePref-Fact**，理由要技术性：
- 它的难点不是工程，而是**问题定义**：怎么让"相对优势"这个概念能落到可优化的目标上，还要能证明它等价于"扩大间隔"
- 第二个难点是**三项 loss 的配平** —— 量级不同，需要分别确认单项量级再联合搜
- 第三个是**消融设计**：必须让每个组件对应一种**可解释的失败模式**，而不是"去掉就掉点"

**对比说明**（显成熟）：「CausalPoison 难在设计和对照（怎么证明可逆性是真的），但它的技术栈是熟路；多智能体最难的是**工程复杂度**，而不是理论。」
:::

## 7. 答砸了怎么救场（三句话模板）

:::card 三种"翻车现场"的补救
**场景 A：数字说错了，被指出**
> 「抱歉，我把两个数记混了——准确值应该是 **X**，我刚才说的是 Y 那个骨干下的数。谢谢您纠正。」
**要点**：立刻承认 + 给出正确值 + 说明为什么会混（显得你真的有这两组数）

**场景 B：完全不会答某个概念**
> 「这个概念我没有系统学过，我的理解是 **A**，不确定对不对；如果是 B 的话，那我刚才说的那部分就要重新想。您能说一下正确的方向吗？」
**要点**：给一个可被纠正的猜测 + 明说不确定 + 请教（比沉默和硬编都强）

**场景 C：被质疑方法没价值**
> 「您这个质疑我接受，我补充一个我自己也想过的点：**它真正的局限是 X**。我现在的证据只能支持到 Y，再往上我就没有实验了。」
**要点**：接受 + 主动指出更深的局限 + 划清证据边界（**这比硬撑更加分**）
:::
