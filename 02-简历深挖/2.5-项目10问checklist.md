# 2.5 项目 10 问 checklist（三个项目通用答题模板）

> **这篇解决什么**：面试官问项目的套路其实高度固定 —— **就这 10 个问题**。这篇把它们拆成可执行的答题结构，并对你的三个项目分别给出要点。
> **用法**：面试前一天，对每个项目把 10 问各说一遍（出声，不看稿）。卡住的地方回去看 2.1 / 2.2 / 2.3。
> **配一张速查表**：见 §12，可以单独打印/截图。

---

## 0. 为什么是这 10 问

:::card 面试官问项目的真实意图（知道这个才知道怎么答）
| 他其实想确认 | 对应问题 |
|---|---|
| 你是不是真的理解问题（而不是照着做） | Q1 为什么做、Q2 现有方法的问题 |
| 你是不是主导者 | Q3 你的方法、Q4 为什么这么设计 |
| 你有没有工程判断力 | Q5 有没有更简单的方法、Q6 baseline |
| 你的实验是否可信 | Q7 指标、Q8 提升来源 |
| 你诚不诚实 | Q9 失败 case、Q10 重做怎么改 |

**一句话**：「这 10 问不是知识题，是**可信度审查**。答得好不好，取决于你有没有真的想过。」
:::

## Q1 为什么做这个问题

:::card 答题结构（三步）
1. **场景**：这个任务在真实世界里解决什么（一句话）
2. **痛点**：现有做法在什么地方不够用（**要具体到现象，不是"效果不好"**）
3. **你的切入点**：你打算从哪个角度动它
:::

:::card 三个项目的答案要点
**RePref-Fact**
- 场景：给定证据判断声明是支持还是反驳
- 痛点：支持和反驳的样本**语义高度相似**，差别常只在数字/实体/时间/否定词 —— 现有方法做 point-wise 分类，不建模"正确标签相对竞争标签的优势"，边界附近的样本不稳
- 切入点：把分类改成**标签空间上的比较**

**CausalPoison**
- 场景：RAG 依赖外部知识，也因此暴露在知识投毒下
- 痛点：现有研究都在优化 ASR，但**答案命中 ≠ 控制了支撑答案的知识关系**（可能是答案泄漏、无关线索、模型先验）
- 切入点：把评估从 **outcome-level** 推进到 **relation-level**

**多智能体检索**
- 场景：复杂声明的核查需要跨多个证据源
- 痛点：单轮静态检索有四种失效（覆盖不全 / 证据冲突 / 需多跳 / query-证据错配）
- 切入点：把一次性检索变成**证据状态驱动的多轮决策**
:::

## Q2 现有方法有什么问题

:::card 答题结构
**必须具体到"哪一类方法 + 它的哪个假设不成立"**，不要说"效果不好"。

回答公式：`「X 类方法假设了 A，但在我们的场景里 A 不成立，所以会出现 B 现象。」`
:::

:::card 三个项目的答案要点
**RePref-Fact**（论文里的两个 source，直接用）
1. **目标层面**：point-wise 分类独立优化 gold label，不显式建模相对优势 → 边界附近不稳
2. **表示层面**：标准预测目标产出的表示既不保留足够的 label-relevant 事实信息，也无清晰类间分离

**CausalPoison**
- 现有工作（含 PoisonedRAG、HijackRAG 等）共同目标是 **outcome-level control**：只验证"目标答案有没有被生成"
- **这个验证方式本身有缺陷**：无法区分"依赖指定关系"和"碰巧说出答案"
- 证据：在我们的 post-hoc 关系干预下，PoisonedRAG 的 **Break Failure 高达 34/40/25/43%**

**多智能体检索**
- 单轮检索方法假设了"一次 query 能召回足够证据"，这在四类场景下不成立（覆盖不全/冲突/多跳/错配）
- 多轮固定次数方法假设了"轮数是事先可知的"，但实际上**要查几轮取决于证据覆盖情况**
:::

## Q3 你的方法是什么

:::card 答题结构（三段式）
1. **一句话总述**（它是什么）
2. **2–3 个组件**（每个一句话）
3. **数据流**（从输入到输出怎么走）

**纪律**：先给一句话，再看反应展开 —— 不要一上来讲 5 分钟细节。
:::

:::card 三个项目的一句话 + 组件
**RePref-Fact**
> 「在标签空间上做相对偏好学习，再用两个表示层目标补信息与几何。」
- 组件：`L_pref`（输出层扩间隔）+ `L_MI`（标签原型对齐保信息）+ `L_SCL`（监督对比保几何）
- 数据流：`(claim, evidence)` → 标签打分 `sθ(x,y)` → 偏好 gap（减参考基线）→ 偏好 loss；同时取隐表示做两项表示约束

**CausalPoison**
> 「先构造恶意知识路径，用关系破坏—修复的可逆干预筛出真正依赖该关系的投毒证据。」
- 组件：路径构造 → 路径约束生成候选 → 三状态评估（`1→0→1`）→ 按 `S_state` 选 top-m
- 数据流：`q, y* → P* → 候选 → {d⁺, d⁻, d^rep} → S_state → 注入语料`

**多智能体检索**
> 「证据状态驱动的多智能体动态检索：状态决定什么时候继续、下一步谁执行。」
- 组件：子目标拆解 + 证据状态（覆盖率/冲突/边际收益）+ 三类子 Agent + 事实依赖图 + 策略分发
- 数据流：`claim → 子目标 → 状态初始化 → (选角色 → 选策略 → 检索 → 更新状态) 循环 → 聚合输出`
:::

## Q4 为什么这样设计

:::card 答题结构（这是最能体现"你想过"的一问）
对每个关键设计，说清 **"如果不这样做会怎样"**（反事实）。

回答公式：`「我选 A 而不是 B，是因为如果 B 的话会出现 C。」`
:::

:::card 三个项目的关键设计 + 反事实
**RePref-Fact**
- 参考模型**冻结** → 不冻结则基线漂移，模型可靠压低参考模型的分数"制造优势"→ 目标漂移
- 用 **gap 相减**而不是绝对分数 → 相当于对实例难度做归一化，让难样本获得更多梯度
- 加**表示层**两项而不只改目标 → 只改目标时表示可能靠表层捷径（分数上去了但学错东西）

**CausalPoison**
- **预先**指定路径 → 事后分析可以"编故事"，无法证明依赖
- break **尽量保持其余内容不变** → 否则无法区分"答案消失是因为关系没了"还是"文档整体变了"
- repair **从被破坏文本重建**（不是复制原文）→ 否则"把原文放回去当然有效"，证明不了任何东西
- 加 **relation preserving control** → 证明攻击对"关系变化"敏感、对"无关内容变化"不敏感

**多智能体检索**
- 用**显式状态**而不是靠 prompt 记忆 → 上下文会爆且读不出"覆盖率"这种量
- **三类角色**而不是一个 → 目标函数冲突（找支撑 vs 找反证），混在一起会意图漂移
- **依赖图**而不是固定顺序 → 否则会反复查同一事实的不同说法
:::

## Q5 有没有更简单的方法

:::card 这是**陷阱题**：面试官想看你会不会"过度设计"
**标准答法结构**：
1. **承认存在更简单的方法**（给一个具体的）
2. **说明它在哪不够**（用数据或机制）
3. **说清代价**（复杂方案的代价你也认）

**千万不要**说"没有更简单的方法"。
:::

:::card 三个项目的答案
**RePref-Fact**
- 更简单的：单纯 SFT（交叉熵微调）
- 为什么不够：论文 Table III 里 SFT 在 HoVer 上 80.74 / 81.22，我们 85.59 / 85.81 —— **+4.6~5.1**
- 代价：多两个损失项 + 需要调权重（α、γ），训练成本略高

**CausalPoison**
- 更简单的：只做一次性消融（删掉文档看答案有没有消失）
- 为什么不够：无法区分"关系失效"和"文档整体变化"；而且没有 `1→0→1` 的往返证据
- 代价：每个候选要评估 3 次状态（成本 ×3），且需要 surrogate model 反复调用

**多智能体检索**
- 更简单的：单 Agent + 固定轮数多轮检索
- 为什么不够：轮数不可预知（取决于覆盖情况），且没有冲突消解机制
- 代价：token 成本、协调开销、可能"两个 Agent 打架"
:::

## Q6 baseline 是什么

:::card 答题结构
**分层说**：传统方法 / LLM 方法 / 同类最强。**并且必须说清"是不是同设置复现"**（这是可信度的关键）。
:::

:::card 三个项目的 baseline
**RePref-Fact**（10 个基线，5 传统 + 5 LLM）
- 传统：BERT-FC、LisT5、RoBERTa-NLI、MultiVerS、KGAT
- LLM：ProgramFC、GraphCheck、CORRECT、LettuceDetect、BiDeV
- **最强基线**：FEVEROUS 是 BiDeV 92.39；HoVer 是 BiDeV 70.96；RAGtruth 是 LettuceDetect 79.03；SciFact 是 CORRECT 82.83
- 关键话术：**同期方法是在相同设置下复现的，不是照抄论文数字**

**CausalPoison**（5 个）
- Naive Attack、Disinformation Attack、Prompt Injection Attack、HijackRAG、**PoisonedRAG**
- 最强的是 **PoisonedRAG**（ASR 0.87/0.94/0.82/0.89）
- 关键话术：**所有方法用同一批 target query、同一 answer、同一 retriever、同一 retrieval depth、同一 victim、同一 budget、同一 ASR 判据**

**多智能体检索**
- 🟡 必须是：单轮检索 + LLM 判断、多轮固定次数检索、（如复现过）同期方法
- 关键话术：说不清具体方法名时，说"我主要对比单轮和固定多轮两类"，别硬编 SOTA 名字
:::

## Q7 指标为什么这么选

:::card 答题结构
**指标选择 = 你对"什么算成功"的定义**。要说清：主指标 + 为什么不用另一个 + 辅助指标。
:::

:::card 三个项目
**RePref-Fact**
- 主指标 **Macro-F1**：四个数据集类别不均衡，Accuracy 会被多数类主导；Macro 对每类等权，能反映**难类**表现
- 辅助：HoVer 拆成 2-hop / 3-hop / 4-hop 分别报 —— 越难的 hop 越能看出差距

**CausalPoison**
- 主指标 **ASR**：沿用前作，便于横向对比
- **但 ASR 不够** → 所以自己加了三个：**Complete Intervention Success**（`1→0→1` 全走完）、**Break Failure**（破坏后答案还在的比例）、**Repair Failure**
- 再加 **Retrieval F1**（证明不是靠"多塞文档"取胜）和 **语义相似度**（证明变体改动是局部的）
- 一句话：「ASR 只能说明"说出答案了"，我需要能说明"**为什么**说出答案"的指标。」

**多智能体检索**
- 主指标 Macro-F1（与数据类别不均衡一致）
- 辅助：**检索次数 / token 成本**（多轮方法的收益必须和代价一起看）🟡 按你的实际说
:::

## Q8 最大提升来自哪里

:::card 答题结构
**不要说"整体都提升了"** —— 要说清**提升的分布**，因为分布才说明方法的适用边界。
:::

:::card 三个项目
**RePref-Fact**
- 分布：FEVEROUS **+2.65** / HoVer **+14.85** / RAGtruth **+7.53** / SciFact **+11.13**，平均 **+9.04**
- 最大来自 **HoVer（多跳）**：跨句线索更容易被表层模式带偏，显式建模间隔收益最大
- 最小是 **FEVEROUS**：BiDeV 已经 92.39，天花板高
- **消融里最大贡献是 `L_pref`（平均 −2.51）**，说明"扩间隔"是主要收益来源，表示层两项是补强

**CausalPoison**
- **ASR 提升有限（+8.5pp）**，因为 outcome 级已接近饱和
- **真正的提升在关系级**：Complete Success **88.25% vs 57.75%**（+30.5pp）
- 机制上最大贡献是**路径构造**（去掉它四个数据集全掉），而不是干预筛选（去掉它 NQ 不变）

**多智能体检索**
- 平均 +3.7pp，**提升主要来自多跳那类**（单轮检索缺口最大）
- 🟡 消融：按你实际做过的说（去掉冲突消解 / 去掉依赖图 各掉多少）
:::

## Q9 失败 case 是什么

:::card 这是**最能区分"真做过"与"读过"的一问**
要求：说**类别 + 机制**，不一定要具体例子；但如果你能说一个具体现象，效果翻倍。

**纪律**：不要说"没有明显失败 case"。
:::

:::card 三个项目的失败模式
**RePref-Fact**
1. **需要外部知识才能连起来的案例**：Table V 里我们仍有 3/6 判错，其中 2 个是"很果断地错"（margin 大但方向错）—— 说明**扩大间隔解决不了知识缺失**
2. 依赖标签空间已知：开放式核查时偏好对构造要重设计
3. 竞争标签是均匀处理的，没按难度加权

**CausalPoison**
1. **检索深度加大时攻击退化**：k 从 5→20，HotpotQA 1.00→0.62、MS MARCO 0.92→0.34 —— 干净证据稀释
2. **跨 hop 更多时失效**：MuSiQue（2–4 hop）ASR 0.96 低于 HotpotQA（2-hop）的 1.00
3. 依赖 surrogate 模型质量

**多智能体检索**
1. **拆解错了**（子目标粒度不合理）→ 后面全歪
2. **检索饱和但覆盖不够**（信息根本不在语料里）→ 应早点判"不可验证"
3. **冲突不可消解**（两个权威源直接矛盾）→ 应输出"存在冲突"而不是硬选
:::

## Q10 如果重新做一次，你会怎么改

:::card 答题结构
给**有优先级的 3 条**，第 1 条要是"技术上最有价值"而不是"工程上最省事"。

**加分点**：把三条和你**下一步研究计划**接上 —— 面试官会认为你是真的想做，不是为了毕业凑数。
:::

:::card 三个项目的答案
**RePref-Fact**
1. **按难度给竞争标签加权**：现在把 `Y\{y⁺}` 当均匀的竞争标签，如果按难度加权，难例的间隔会拉得更开（这是我最想改的）
2. 把 CausalPoison 的**可逆干预**搬过来做诊断指标：回答"判对的那些里有多少是真的看对了地方"
3. 补全参微调的对照，验证结论是否依赖 LoRA

**CausalPoison**
1. **把 relation-level 这套评估做成通用基准**（不只用于投毒，也可用于 RAG 系统的知识依赖诊断）
2. 降低对 surrogate 的依赖（用更便宜的模型做路径构造与三状态评估）
3. 补防御侧的联合实验（在更强的防御下测可逆性还剩多少）

**多智能体检索**
1. **补成本与收益的完整对照**（多轮多花多少、换回多少）—— 这是我认为投稿前必须补的
2. 加**不可验证判定**：覆盖率长期上不去时主动输出"证据不足"，而不是硬答
3. 把状态层做成可复用组件（脱离这个项目也能用）
:::

## 11. "你个人具体做了什么"（**独立的必答题**）

:::card 为什么这题最危险
面试官听你说完 10 问，心里还有一个问题：**这些是你的功劳还是团队的？** 尤其是论文有导师、有合作者。
:::

:::card 答题模板：按五个动作分别说，每个动作给一个具体决策
| 动作 | RePref-Fact | CausalPoison | 多智能体 |
|---|---|---|---|
| **问题定义** | 把分类重构成标签空间偏好 | 提出 relation-level 这个评估维度 | 提出状态驱动的多轮决策 |
| **方法设计** | 偏好 gap 减参考基线、三项联合目标 | break 的三种操作、`S_state` 三项等权打分 | 证据状态字段、三类角色划分 |
| **实现** | PyTorch 训练与评测流水线 | 路径构造的代码级校验、4 检索器 × 6 victim 评测框架 | 编排层手写实现 |
| **实验** | 消融/骨干/超参/低资源/噪声/案例/t-SNE 全套 | 主实验 + 干预分布 + preserving control + 语义相似度 + 消融 | 三类数据评测、消融 |
| **写作** | 一作 | 一作 | — （在研） |
:::

:::card 三条表达纪律
1. **把"我们"换成"我"**：凡是说"我们做了 X"，面试官都会追问"你做了什么"。**主动说清自己的部分**，反而显得坦荡
2. **说具体动作，不说角色**：❌「我负责方法设计」→ ✅「偏好 gap 里减参考模型这一项是我定的，因为它做难度归一化」
3. **合作的部分要说明**：「baseline 复现是我和同组另一位同学分工做的，我负责其中 4 个」—— **主动划清，比含混更可信**
:::

## 13. 自测（三个项目各 3 题，共 9 题）

:::qa RePref-Fact：Q4「为什么参考模型要冻结」
不冻结则基线漂移，模型可以靠压低参考模型的 gold 分数来"制造相对优势"，而不是真的提升自己 → 目标漂移。
:::

:::qa RePref-Fact：Q5「有没有更简单的方法」，怎么答才不失分

:::qa 多智能体：Q1「为什么做」，怎么避免和另外两个项目重复
聚焦在**证据获取**这个环节：单轮静态检索的四种失效（覆盖不全/冲突/多跳/错配），都不是"模型不够强"能解决的，而是检索需要反馈控制。

:::qa 多智能体：Q5「有没有更简单的方法」
单 Agent + 固定轮数多轮检索更简单，但轮数不可预知（取决于覆盖情况），且没有冲突消解角色；代价是 token 成本与协调开销。
:::
