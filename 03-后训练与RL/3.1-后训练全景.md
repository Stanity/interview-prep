# 3.1 后训练全景（Pretrain → SFT → 偏好对齐 → RL）

> **这篇的作用**：给你一张"后训练地图"。面试官问任何后训练问题，你都能先定位"它在哪个阶段、修什么问题"，再展开细节。
> **本文的定位**：`★★★` 必背骨架 ｜ 详细推导见 `3.2-DPO家族推导` ｜ Agent 侧见 `3.4-AgenticRL`
> **你的位置**：你做过 **LoRA + 偏好优化（RePref-Fact）**，**没跑过 PPO/GRPO 训练** —— 这个边界要清楚（§8）。

## 1. 30 秒口述版

:::card 30 秒版（被问"讲讲大模型后训练"时用）
「后训练可以按"**每步修上一个阶段的什么问题**"来记：

**预训练**解决"会不会说话、知不知道世界知识"，但它**不听指令** —— 你问它问题它可能继续补全。
**SFT** 用指令-回答数据教会它"按格式回答"，但只教了"能答"，没教"答得好"。
**偏好对齐**解决"哪个回答更好"：RLHF 用奖励模型 + PPO，DPO 直接用偏好对跳过显式奖励模型，RLVR/GRPO 用**可自动判定的奖励**（数学答案、代码单测）替代人训的奖励模型。

一句话概括整条链：**PT 给知识和语言能力，SFT 给指令跟随和格式，偏好对齐给"选择倾向"，RLVR 把能力推向可验证的正确性。**」
:::

## 2. 五阶段动机链条（这张表是全文骨架）

| 阶段 | 做什么 | 数据形态 | 修上一个阶段的什么问题 | 失败表现 |
|---|---|---|---|---|
| **① 预训练 PT** | next-token prediction | 海量无标注文本 | — | 会补全但**不听指令** |
| **② SFT** | 指令-回答的监督微调 | `(instruction, response)` | 不会按指令格式回答 | 能答但**质量不稳**（冗长/回避/不安全） |
| **③ 偏好对齐（RLHF-PPO）** | 训 RM + RL 优化 | 偏好对 → RM → 在线采样 | 没有"哪个更好"的倾向 | 训不稳、四模型显存大、RM 易被刷 |
| **④ 离线偏好优化（DPO）** | 直接用偏好对优化 | `(prompt, chosen, rejected)` | 省掉 RM 与在线采样 | off-policy、长度偏置 |
| **⑤ 可验证奖励 RL（RLVR/GRPO）** | 用规则/测试判定奖励 | prompt + 可判定奖励 | 人训 RM 不可靠、无法覆盖推理正确性 | 奖励被刷（reward hacking）、稀疏奖励 |

:::card 一句话记住每一步的"为什么"
- **为什么 PT 之后要 SFT**：PT 的目标是"预测下一个词"，不是"回答问题"。模型可能把你的提问当成文章开头继续写。
- **为什么 SFT 之后要偏好对齐**：SFT 只告诉模型"什么是合理回答"，没告诉它"**两个都合理时哪个更好**"。
- **为什么 PPO 之后要 DPO**：PPO 要 4 个模型（actor / critic / reward / reference）+ 在线采样，训练不稳、成本高。DPO 证明**可以把 RM 消掉**。
- **为什么 DPO 之后还要 RLVR/GRPO**：DPO 是**离线**的，只能用已有偏好对；而数学/代码这类任务有**自动判对错**的机制，可以**在线探索**，且奖励比人训 RM 更可靠。
:::

## 3. SFT 详解（看起来最简单，坑最多）

### 3.1 数据：质量 > 数量

:::card SFT 数据的四条实践原则
1. **质量优先**：几千条高质量 > 几十万条低质量。低质数据教的是"坏习惯"（冗长、套话、格式乱）
2. **多样性**：任务类型、长度分布、难度梯度都要覆盖，否则模型只会在窄分布上好
3. **格式一致**：同一个任务用同一套模板（chat template），否则模型学到的是格式噪声
4. **去重与防污染**：训练集和评测集去重（这是最容易被面试官抓的实验严谨性问题）
:::

### 3.2 loss mask：只对回答算 loss

:::card 这是 SFT 实现里最重要的一个细节
一条样本通常是拼接的：
```
<|user|> 请解释 KV cache <|end|><|assistant|> KV cache 是…… <|end|>
```
**如果整条都算 loss**，模型会被训练去"预测用户的提问"——这既浪费容量，又会削弱指令跟随。

**标准做法**：
- 只对 **assistant 回复部分**（含终止符）算交叉熵
- prompt 部分置 `label = -100`（PyTorch `CrossEntropyLoss` 的 `ignore_index`）

对应的工程细节：
- **packing**（把多条样本拼到一个序列里提高利用率）时，要保证 **attention 不跨样本**（用 attention mask 或 varlen kernel），否则会串味
- 序列截断要保证**不截掉回答**（宁可截 prompt 尾部）
:::

### 3.3 灾难性遗忘：为什么 SFT 会让模型变傻

:::card 现象与对策
**现象**：SFT 之后通用能力（多语言、长文、某些推理）下降 —— 因为在窄分布上过度拟合了。

**五个对策**（按性价比排）：
1. **只训 LoRA**（改的参数少，天然忘得少）
2. **低学习率 + 少 epoch**（通常 1–3 epoch，多了就是过拟合）
3. **混入少量通用/预训练数据**（如 5%–10%）做"回放"
4. **早停**：盯验证集（既看目标任务，也看一个通用任务）
5. **多阶段**：通用 SFT → 领域 SFT → 任务 SFT，每阶段量递减
:::

### 3.4 多阶段 SFT 的价值

:::card 为什么大厂都做多阶段
- **阶段 1（通用对齐）**：大规模、覆盖广，教会"怎么对话"
- **阶段 2（领域/能力）**：注入领域知识、特定能力（如代码、数学）
- **阶段 3（风格/格式）**：极少量但高质量，改语气、改格式、改拒答策略

**面试话术**：「多阶段的本质是**把"学什么"和"学成什么样"分开**。混在一个阶段里，风格数据会被能力数据稀释。」
:::

## 4. 偏好对齐的三条路线（对比表，必背）

| 维度 | **RLHF-PPO** | **DPO** | **RLVR / GRPO** |
|---|---|---|---|
| 需要 reward model | ✅ 先训 RM | ❌ 隐式奖励 | ✅ 但可以是**规则/测试**而非人训模型 |
| 需要 value model（critic） | ✅ 需要 | ❌ | ❌（GRPO 用组内均值） |
| 在线采样 | ✅ 需要 | ❌ 离线 | ✅ 需要（同题采一组） |
| 数据 | prompt + 在线打分 | `(prompt, chosen, rejected)` | prompt + **可判定的奖励** |
| 模型数 | 4（actor/critic/rm/ref） | 2（policy/ref） | 2–3（policy/ref/rm 或规则） |
| 主要风险 | 训不稳、RM 被刷 | off-policy、长度偏置 | 奖励被刷、组内全同则白采 |
| 典型场景 | 通用人类偏好对齐 | 有偏好对、算力有限 | **数学、代码、格式约束、工具调用** |

:::card 三条路线的一句话本质
- **PPO**：训一个"打分老师"，再让模型在被老师打分的过程中学好 —— **在线、贵、强**
- **DPO**：证明"打分老师"可以被**偏好对本身**替代掉 —— **离线、便宜、稳**
- **RLVR**：不要老师了，**用裁判（测试用例 / 答案比对）当奖励** —— **在线、可验证、适合有标准答案的任务**
:::

## 5. RLHF 的四模型与显存账（面试常算）

:::card 四个模型各自干什么
| 模型 | 是否训练 | 作用 |
|---|---|---|
| **Actor**（policy） | ✅ 训练 | 生成回答的模型 |
| **Critic**（value） | ✅ 训练 | 估计 `V(s)`，做 PPO 的 baseline 降方差 |
| **Reward Model** | ❌ 冻结（事先训好） | 给 `(prompt, response)` 打分 |
| **Reference** | ❌ 冻结 | 算 KL 惩罚，防止偏离 SFT 分布太远 |

**为什么必须 reference**：不加 KL 约束，策略会为了刷 RM 分数而"跑飞"（reward hacking），输出变得不像人话。
:::

:::card 显存账：为什么 PPO 这么贵（7B 全参为例）
| 项 | 算法 | 大小 |
|---|---|---|
| 权重（bf16） | 7B × 2B | 14 GB |
| 梯度（bf16） | 7B × 2B | 14 GB |
| Adam 状态（fp32 的 m + v） | 7B × 4B × 2 | 56 GB |
| **单个可训练模型小计** | | **≈ 84 GB** |
| Actor + Critic（都训练） | ×2 | ≈ 168 GB |
| Reward + Reference（只推理，bf16） | 14 × 2 | ≈ 28 GB |
| 激活与临时 | — | 数十 GB |

→ **7B 全参 PPO 至少需要 8×80G 起步**，这就是为什么实践里都用 **LoRA + ZeRO + offload**。

**一句话答法**：「PPO 贵不是因为模型大，而是因为**要同时驻留 4 个模型，其中 2 个还要带梯度和优化器状态**。」
:::

## 6. 决策树：什么场景用什么

:::card 按这个顺序问自己
**Q1：你缺的是"会做"还是"做得更好"？**
- 缺"会做"（模型根本不会这个任务）→ **SFT**（再多偏好数据也没用，基础能力不能靠对齐获得）
- 会做但质量不稳 → 往下

**Q2：你能拿到"成对的好坏比较"吗？**
- 能（人工标注 / 强模型生成 / 规则构造）→ **DPO**（最省）
- 只能拿到"好/坏"的单独标签 → **KTO**
- 拿不到偏好 → 往下

**Q3：这个任务的正确性能自动判定吗？**
- 能（数学答案、代码单测、JSON 格式、工具调用是否成功）→ **RLVR / GRPO**（在线探索 + 可靠奖励）
- 不能 → 往下

**Q4：算力够 + 有可靠 RM + 需要在线探索？**
- 是 → **PPO**
- 否 → 回到 SFT + 数据增强，或迭代式 DPO（用当前模型采样新回答、再用强模型打分构造新偏好对）
:::

:::card 一个常见误区（面试常考）
**误区：模型不会某任务，先做偏好对齐。**
正确顺序永远是：**SFT 学能力 → 偏好对齐学选择 → RL 学超越**。
偏好对齐只能在模型"已经会生成候选"的空间里做选择；**它不能让模型学会它根本不会的东西**。

> 这也是为什么 RLVR 能提升数学能力（模型本来能生成部分正确推理，RL 强化正确路径），而 DPO 很难提升"完全不会的题"。
:::

## 7. 工程细节清单（被问"你调过什么"时用）

:::card SFT / LoRA 的常见配置（可作为答题基准）
| 项 | 典型值 | 说明 |
|---|---|---|
| LoRA rank `r` | 8–64 | 能力注入多就调大；我项目里用 **8** |
| `alpha`（scaling） | 通常 2×r | 我用 **16**（r=8 时 2×） |
| dropout | 0.05–0.1 | 我用 **0.1** |
| target_modules | attention + FFN | 只加 attention 效果弱一些 |
| 学习率 | 1e-4 ~ 2e-4（LoRA） | 全参则 1e-5 ~ 2e-5 |
| epoch | 1–3 | 超过就容易灾难遗忘 |
| batch | 受显存限制，用梯度累积 | 我用 batch 16 + 累积 4（等效 64） |
| max_len | 按数据分布定 | 截断策略要保证不截回答 |
| loss | 只在 answer 上算 | prompt 部分 label = -100 |
:::

:::card 评测：怎么知道后训练有效
1. **目标任务指标**（如 F1、pass@1、单测通过率）
2. **通用能力回归**（防止越训越窄）
3. **偏好/胜率**（用强模型或人工做 A/B）
4. **格式合规率**（结构化输出场景必看）
5. **长度分布**（对齐后模型往往变啰嗦，这是重要信号）
:::

## 8. 【挂点】你的 RePref-Fact 在后训练的哪个位置

:::card 精确定位（这段回答能显示你真的懂后训练）
你的工作是 **③/④ 偏好对齐层**，但做了三处改造：
1. **偏好对不是"两个回答"，而是"同一实例的两个标签"** → 把偏好学习从生成任务搬到**判别任务**
2. **参考模型不是用来做 KL 约束，而是提供"标签间优势的基线"** → 做**实例难度归一化**
3. **在偏好目标之外加了两个表示层目标**（互信息 + 监督对比）→ DPO 只改输出层，你改的是"输出 + 表示"

**诚实边界（很重要）**：
> 「我没有做过 PPO/GRPO 的完整训练 —— 我做过的是**偏好优化的判别式改造**和 LoRA 微调。所以对 RL 那部分，我的理解是原理级的，没有调参经验。」
:::

## 9. 十个面试题预答

:::qa 为什么不能跳过 SFT 直接做 RL / DPO
两个原因：
1. **DPO 需要 π_ref**：参考模型通常就是 SFT 模型，没有 SFT 就没有合理的起点，"相对偏离"无从度量
2. **RL 需要能采样出正确答案**：如果模型对某类题 pass@k 接近 0，RL 的奖励永远为 0，学不到东西（稀疏奖励问题）
所以顺序是：SFT 建立基础分布 → 对齐在分布内做选择 → RL 才能探索。
:::

:::qa SFT 数据要多少？为什么不是越多越好
没有固定数字，取决于任务与模型。但三条规律：
1. **能力类任务**（新技能）需要较多（万级）；
2. **风格/格式类**只需少量（千级甚至百级），多了会挤占能力；
3. **质量比数量重要**：低质数据会给模型建立错误先验，且训练后很难靠更多数据"洗掉"。
**一句话**：「我宁可用 3k 高质量数据训 2 个 epoch，也不用 30 万条清洗过的数据训 3 个 epoch。」
:::

:::qa 灾难性遗忘怎么解决
五条：只训 LoRA、低 lr + 少 epoch、混入 5–10% 通用数据回放、早停盯通用任务、多阶段递减。
**加一句**：「但要注意：**如果领域差异极大，遗忘是必然的**，这时要做的是"能力路由"（多 LoRA / 多专家），而不是硬抗。」
:::

:::qa RLHF 里 reference model 的作用是什么？去掉会怎样
作用是**KL 约束**：不加它，策略会为刷 RM 分数而跑飞（输出偏激、重复、不像人话）。
去掉的后果就是 **reward hacking** —— RM 只知道"打分"，不知道"什么是正常语言"，所以策略会找到 RM 的漏洞。
:::

:::qa PPO 为什么训不稳定
四个来源：
1. **critic 与 actor 互相拖累**：critic 估不准 → 优势估计噪声大 → actor 更新方向错
2. **策略更新幅度难控**：clip 参数敏感，太大崩、太小不学
3. **RM 分布偏移**：策略越训越偏离 RM 的训练分布，打分越来越不可靠
4. **奖励尺度**：不同 prompt 的奖励尺度不一致，需要归一化
:::

:::qa DPO 和 RLHF 的本质关系
DPO 是"把 RLHF 的目标**解析地**求解后再训练"：
- RLHF 的目标是 `max E[r] − β·KL`
- 这个目标对每个 prompt 有**闭式最优解** `π* ∝ π_ref·exp(r/β)`
- 反解出 `r` 用 `π*` 表示（隐式奖励），代入 Bradley-Terry 偏好模型 → 归一化常数 `Z(x)` 相消 → 得到只含 `log(π/π_ref)` 的 loss
**所以 DPO 不是"另一种 RLHF"，而是 RLHF 目标的一个精确重参数化。**（推导见 3.2）
:::

:::qa 什么时候该用 PPO 而不是 DPO
三个条件同时满足时：
1. 有**可靠且难被刷**的奖励信号（人训 RM 或规则）
2. 需要**在线探索**（答案不在偏好数据分布内，例如推理路径优化）
3. 算力充足
否则 DPO 更划算。**实践中很多团队是 DPO 起步，效果不够才上 PPO/GRPO。**
:::

:::qa RLVR 的奖励怎么设计？会有什么问题
奖励通常 = 结果奖励（答案对不对）+ 格式奖励（是否按格式输出）+ 可选的长度惩罚。
**问题**：
1. **reward hacking**：模型学会"只输出答案不推理"来骗格式分
2. **稀疏**：全错时奖励恒 0，没有梯度信号
3. **长度偏置**：不加约束会越写越长（或越写越短）
对策：过程奖励/课程学习、组内归一化、长度惩罚、混合数据集。
:::

:::qa 你怎么判断一个后训练实验是否"真的有效"
三个层面：
1. **指标**：主任务提升 + 通用任务不回退
2. **消融**：把新加的组件去掉，确认收益来自它
3. **分布**：看提升落在哪个子集（难例？长尾？某类任务？）以及**长度/格式有没有异常变化**
**一句话**：「只报一个平均值是最不可信的。」
:::

:::qa 【挂点】你的 RePref-Fact 和 DPO 什么关系
形式上借用 DPO 的 log-sigmoid 结构，但三处不同：偏好对是**标签**不是回答；参考模型做**难度归一化**不是 KL 约束；额外加了两个**表示层**目标。
**边界**：「我没做过完整的 PPO/GRPO 训练。」
:::

## 10. 陷阱：哪些话不能说

| ❌ 别这么说 | ✅ 换成这么说 |
|---|---|
| 「DPO 是 RLHF 的替代方案」 | 「DPO 是 RLHF 目标的**解析解重参数化**，把 RM 消掉了」 |
| 「SFT 就是训练模型学知识」 | 「SFT 主要是**学指令跟随与格式**，知识主要来自预训练」 |
| 「模型不会某任务可以靠对齐解决」 | 「对齐只能在已会生成的候选里做**选择**，学新能力必须靠 SFT/RL」 |
| 「PPO 比 DPO 效果好」 | 「PPO 在线、能探索，但要可靠 RM 和算力；多数团队 DPO 起步」 |
| 「我做过 RLHF」 | 「我做过**偏好优化的判别式改造**和 LoRA 微调，没跑过 PPO/GRPO 训练」 |
| 「SFT 数据越多越好」 | 「质量优先，风格类千级就够，能力类才需要万级」 |

## 11. 自测（7 题）

:::qa 一句话说清后训练五个阶段各修什么问题
PT 给知识和语言能力但**不听指令** → SFT 学指令跟随与格式 → 偏好对齐学"哪个更好" → DPO 把 RM 消掉降低成本 → RLVR/GRPO 用可验证奖励做在线探索。
:::

:::qa SFT 的 loss mask 是什么？为什么必须做
只对 assistant 回复部分算交叉熵，prompt 部分 `label = -100`。否则模型被训练去预测用户提问，浪费容量且削弱指令跟随。
:::

:::qa 灾难性遗忘的三条最实用对策
只训 LoRA、低 lr + 少 epoch（1–3）、混入 5–10% 通用数据回放。
:::

:::qa RLHF 四个模型分别是什么？哪个最贵
actor、critic、reward、reference。**actor 和 critic 都要训练**（带梯度 + Adam 状态），所以是它们最贵；7B 全参下单个可训练模型 ≈ 84GB。
:::

:::qa reference model 去掉会怎样
失去 KL 约束 → 策略为刷 RM 分数而跑飞（reward hacking），输出偏离正常语言分布。
:::

:::qa 模型不会某个任务，能不能靠 DPO 解决
不能。DPO 只能在模型已能生成候选的空间里做选择；学新能力要靠 SFT 或 RL。判断依据是 **pass@k**：如果采样都采不到正确答案，偏好数据再多也没用。
:::

:::qa 你没跑过 PPO/GRPO 训练，被问怎么办
照实说，然后给出你有的：偏好优化的判别式改造（RePref-Fact）+ LoRA 微调 + 完整实验矩阵设计；同时说明你知道 RL 的关键难点（critic 不稳、reward hacking、稀疏奖励）。
:::
