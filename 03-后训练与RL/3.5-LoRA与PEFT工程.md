# 3.5 LoRA 与 PEFT 工程细节（你真正动手过的那块）

> **为什么这篇对你最重要**：LoRA 是你**实际调过的环节**（RePref-Fact 用 Qwen3-8B / Llama-3.1-8B + LoRA r=8），所以面试官会问得比 RL 深得多 —— 他会假设你真的踩过坑。
> **本文目标**：原理能推、参数量能算、显存能估、坑能说出来。
> **标注**：`★★★` 必背 ｜ §10 直接对上你论文里的真实配置

---

## 1. 30 秒口述版

:::card 30 秒版
「LoRA 的出发点是：**微调时权重的更新量本身是低秩的** —— 不需要改整个大矩阵，用两个小矩阵的乘积就能近似。

具体做法：冻结原权重 `W`，加一条旁路 `ΔW = BA`，其中 `A in R^{r×k}`、`B in R^{d×r}`，`r` 远小于 `d,k`。前向变成 `h = Wx + (α/r)·BAx`。
**关键设计是初始化**：`A` 随机、`B` 置零 —— 这样训练开始时 `ΔW = 0`，模型行为与原模型完全一致，不会一上来就被破坏。

参数量从 `d×k` 降到 `r(d+k)`。以 4096×4096、r=8 为例，从 1600 万降到 6.5 万，约 **0.4%**。

再往下就是 **QLoRA**：把冻结的基座量化到 **NF4**（4-bit），再加**双重量化**和对**分页优化器**，让 65B 模型能在单张 48G 卡上微调。」
:::

---

## 2. 为什么 LoRA 能 work（这个追问必须先准备好）

:::card 两个层次的回答
**① 经验依据：内在维度假说（intrinsic dimensionality）**
已有研究发现：预训练模型在下游任务上微调时，**参数更新可以投影到一个很低维的子空间而几乎不掉性能**。也就是说"微调需要改变的东西"没那么多。

**② 机制解释：ΔW 近似低秩**
微调只是把模型从"通用分布"推到"任务分布"，这个偏移在参数空间里往往是**低秩**的 —— 所以用 `BA`（秩 ≤ r）近似它损失很小。

**面试加分句**：
> 「LoRA 的假设不是"模型很小"，而是"**微调的增量很小**"。这也是为什么它对**风格/格式/判别式改造**效果很好，但对**注入大量新知识**效果有限 —— 因为后者需要的是高秩的改动。」
:::

**这个"加分句"直接解释了你的配置为什么合理**（见 §10）：你做的是判别式改造而不是知识注入，所以 r=8 够用。

## 3. 数学形式与初始化（必须能白板写）

### 3.1 前向

```
原始：h = W x
LoRA：h = W x + (α/r) · B A x
      其中  W in R^{d×k}（冻结）,  A in R^{r×k},  B in R^{d×r},  r ≪ min(d,k)
```

### 3.2 初始化（**这是 LoRA 最巧妙的一处**）

:::card 为什么 A 随机、B 置零
- `A` 用随机高斯（或 Kaiming）
- **`B = 0`**

则训练开始时 `ΔW = BA = 0` → **模型输出与原模型完全一致**。

**好处有三个**：
1. **不破坏预训练能力**（起点就是原始模型）
2. **训练稳定**（不会一开始就有大梯度）
3. **可以随时"关掉"LoRA**（把旁路置零就退回原模型，方便 A/B 对比）

**面试话术**：「如果 A、B 都随机初始化，一开始模型就是被扰动的；B 置零保证了 **identity initialization**，这是 LoRA 能"无损起步"的原因。」
:::

### 3.3 缩放系数 `α/r`（这个细节常被考）

:::card 为什么除以 r
因为 `BA` 的**有效幅度随 r 变化**：r 越大，`BA` 能表达的幅度越大。
用 `α/r` 做缩放，可以让**改变 r 时有效学习率保持稳定** —— 否则你把 r 从 8 调到 64，相当于偷偷把学习率放大了 8 倍。

**为什么要讲 rsLoRA**：当 r 很大（比如 256）时，`α/r` 会让更新过小、学不动。**rsLoRA 把缩放改成 `α/√r`**，大 r 时更稳。
:::

## 4. 参数量计算（面试经常让你现算）

:::card 公式
对一个 `d × k` 的权重矩阵，LoRA 引入的参数：
```
r × (d + k)          （A 是 r×k，B 是 d×r）
```
| 场景 | 原参数 | LoRA (r=8) | 占比 |
|---|---|---|---|
| 4096 × 4096 | 16.78 M | 8 × 8192 = **65.5 K** | **0.39%** |
| 4096 × 11008（FFN） | 45.1 M | 8 × 15104 = 120.8 K | 0.27% |
| 一个 8B 模型（约 32 层，每层 q/k/v/o + 3 个 FFN）| ~8 B | 约 **20–40 M** | **0.3%–0.5%** |

**一句话**：「8B 模型的 LoRA 通常只训练 20–40M 参数，约千分之三到千分之五。」
:::

:::card `target_modules` 怎么选（工程判断）
| 选择 | 效果 | 说明 |
|---|---|---|
| 只加 `q, v` | 弱（论文早期做法） | 参数最省，但表达力有限 |
| `q, k, v, o`（attention 全部） | 中 | 常见折中 |
| **attention + FFN**（`gate/up/down`） | **强**（推荐） | FFN 承载大量知识，加它收益明显 |
| 加 embedding / lm_head | 视任务 | 换词表或新语言时才需要 |

**你的配置就是 attention + FFN**，这是当前的推荐做法 —— 面试被问"为什么"时答"FFN 参数量占大头，只改 attention 表达能力不够"。
:::

## 5. 四个超参怎么调

:::card r / α / dropout / lr
| 超参 | 作用 | 经验值 | 什么时候调大 |
|---|---|---|---|
| **r**（秩） | 表达能力上限 | 8 / 16 / 32 / 64 | 任务与原分布差异大（新领域、新语言）、数据量大 |
| **α**（scaling） | 等效学习率缩放 | 通常 **2r** | 一般不动，跟着 r 走 |
| **dropout** | 防过拟合 | 0.05 – 0.1 | 数据少时调大 |
| **lr** | 学习率 | LoRA 常用 **1e-4 ~ 2e-4** | 比全参微调大 10 倍是正常的（可训练参数少） |
:::

:::card 一个常被问的点：为什么 LoRA 的学习率可以比全参大
因为**可训练参数少、更新方向受限**（低秩），所以不容易破坏原模型；同时 `ΔW` 是从 0 开始长的，梯度需要"推动"它，学习率大一点收敛更快。
**但**：lr 太大仍会训崩（表现为 loss 震荡或输出退化）。
:::

## 6. QLoRA：三项技术各解决什么

:::card 三项技术（面试常要求逐一说出）
| 技术 | 解决什么 | 一句话原理 |
|---|---|---|
| **NF4 量化** | 基座权重占显存太多 | 4-bit **NormalFloat**：假设权重近似正态分布，按**分位数**非均匀量化 → 同样 4 bit 下误差更小 |
| **双重量化（DQ）** | 量化常数本身的额外开销 | 对"每块的缩放系数"再量化一次，平均再省约 **0.37 bit/参数** |
| **分页优化器（Paged Optimizer）** | 显存峰值导致 OOM | 用 NVIDIA 统一内存，把优化器状态在显存不足时**换出到 CPU**，峰值过去再换回 |
:::

:::card QLoRA 的代价（要主动说）
1. **速度慢**：4-bit 反量化有开销，训练吞吐通常比 bf16 低
2. **精度损失**：量化误差会影响效果，尤其在需要精细数值的任务上
3. **兼容性**：QLoRA 训出来的 adapter 合并回 bf16 基座时要注意精度差异

**面试话术**：「QLoRA 是"**用速度换显存**"。如果有卡，优先 bf16 LoRA；只有卡不够时才上 QLoRA。」
:::

## 7. 显存估算（**这块必须会算，一面高频**）

:::card 四块显存 + 一个容易忘的
| 项 | 算法 | 说明 |
|---|---|---|
| **① 权重** | `P × bytes_per_param` | bf16 = 2P；NF4 ≈ 0.5P；fp32 = 4P |
| **② 梯度** | 只对**可训练**参数算 | 全参 bf16 = 2P；**LoRA ≈ 0** |
| **③ 优化器状态** | 只对**可训练**参数算 | Adam 的 m、v 各 fp32 → **8 bytes/参数** |
| **④ 激活值** | 与 batch × seq_len × hidden × layers 相关 | 可用梯度检查点大幅降低 |
| ⑤ 临时缓冲 | 框架/CUDA context | 通常 1–2 GB，别忘 |
:::

:::card 8B 模型的三种方案（手算给你看）
**方案 A：全参微调（bf16 + Adam）**
| 项 | 大小 |
|---|---|
| 权重 bf16 | 8B × 2 = **16 GB** |
| 梯度 bf16 | 8B × 2 = **16 GB** |
| Adam 状态（m+v，fp32） | 8B × 8 = **64 GB** |
| **小计** | **≈ 96 GB** |
| + 激活与缓冲 | 数 GB ~ 数十 GB |
→ **至少 2×80G，通常要 ZeRO/多卡**

**方案 B：LoRA（bf16 基座）**
| 项 | 大小 |
|---|---|
| 权重 bf16（冻结） | **16 GB** |
| 梯度 | 只算 LoRA 部分（几十 MB）→ **≈ 0** |
| 优化器状态 | 只算 LoRA 部分 → **≈ 0** |
| **小计** | **≈ 16 GB** |
| + 激活与缓冲 | 取决于 batch × seq（关键变量） |
→ **单卡 24G/40G 可跑**（seq 长或 batch 大时要调梯度检查点）

**方案 C：QLoRA（NF4 基座）**
| 项 | 大小 |
|---|---|
| 权重 NF4 | 8B × 0.5 = **≈ 4–5 GB** |
| 其余同 LoRA | ≈ 0 |
| **小计** | **≈ 5 GB** |
| + 激活 | 同上 |
→ **单卡 24G 轻松跑**，甚至可以 16G

**一句话总结（面试就这么答）**：
> 「全参微调的显存大头**不是权重，是 Adam 的两个 fp32 状态**（每参数 8 字节）。LoRA 省掉的正是**梯度和优化器状态**（因为只训千分之几的参数），而 QLoRA 再进一步把**权重**也压了 4 倍。」
:::

:::card 激活值这块（容易翻车的地方）
- 激活随 **batch × seq_len** 线性增长，长序列是主要杀手
- **梯度检查点（gradient checkpointing）**：不存中间激活，反向时重算 → 显存大降，速度慢约 20–30%
- **FlashAttention**：本身就能省掉 `seq²` 的注意力矩阵存储
- 所以 OOM 的第一个调参顺序是：**降 batch → 开梯度检查点 → 降 seq_len → 上 QLoRA**
:::

## 8. LoRA 的五个局限（被问"有什么缺点"时用）

:::card 逐条
1. **知识容量受限**：低秩改动装不下"大量新知识"。要注入新知识（新领域语料、新语言），需要更大 r 或全参/继续预训练
2. **多任务冲突**：同一个基座挂多个 LoRA 时，简单合并（加权平均）会互相干扰，实践中用**路由**（按任务选 adapter）而不是合并
3. **推理延迟**：不合并时有额外的两个小矩阵乘法（其实很小，但多 LoRA 并发时显存占用上升）
4. **秩选择困难**：r 太小欠拟合、太大接近全参且失去意义（AdaLoRA 就是为自适应分配秩）
5. **与量化的兼容**：QLoRA 训出的 adapter 合并到 bf16 基座时，可能出现精度不匹配（要在同一精度下验证）
:::

## 9. 家族：四个值得知道的变体

| 变体 | 一句话改进 | 什么时候用 |
|---|---|---|
| **AdaLoRA** | 不同层分配不同秩（按重要性自适应） | 不确定 r 该多大时 |
| **DoRA** | 把权重分解成**幅度 + 方向**，只对方向做低秩更新 | 追求接近全参的效果 |
| **LoRA+** | 对 `A` 和 `B` 用**不同学习率**（B 更大） | 收敛慢时的一个低成本改进 |
| **rsLoRA** | 缩放从 `α/r` 改成 `α/√r` | r 很大（≥64）时必须考虑 |

**面试只需能说出"有这些变体、各自改了什么"**，不必深入推导。

## 10. 【挂点】你的真实配置（这段最关键）

:::card 你论文里的 LoRA 配置（要能脱口而出）
| 项 | 值 | 为什么这么说（可讲的理由） |
|---|---|---|
| 骨干 | **Qwen3-8B、Llama-3.1-8B** | 用两个不同骨干验证方法不依赖特定模型 |
| **r** | **8** | 我做的是**判别式改造**（不是注入新知识），低秩足够；而且这个任务的改动集中在输出层附近的偏好结构 |
| **α（scaling）** | **16** | = 2r，常规做法 |
| **dropout** | **0.1** | 数据规模有限，加一点正则 |
| **target_modules** | **attention + FFN** | FFN 承载大量参数，只改 attention 表达力不够 |
| **学习率** | **1e-4**（AdamW） | LoRA 常用区间 1e-4~2e-4 |
| **batch** | **16**，梯度累积 **4**（等效 64） | 显存限制下的常规折中 |
| **epoch** | 最多 **20** + **early stopping** | 早停防止过拟合与灾难遗忘 |
:::

:::card 被追问时的三个标准答法
**Q：为什么 r 只用 8？**
「因为这个任务的本质是**判别边界的调整**，不是知识注入。r=8 在 4096 维上引入约 6.5 万参数/矩阵，足以表达"正确标签相对竞争标签的优势"这个方向性偏移。如果我在做领域继续预训练或新语言适配，r 需要更大。」

**Q：为什么不选 16 或 32？**
（🟡 按你实际做的说）如果有超参敏感性实验：直接报数；如果没有：
「我没有系统性扫 r，是基于"判别式改造 + LoRA 常用 8~16"的惯例选的。真要严谨应该做一个 r in {4, 8, 16, 32} 的对照，这是我复盘时觉得该补的。」

**Q：显存大概多少？**
「8B 基座 bf16 约 16 GB，LoRA 的梯度和优化器状态几乎可以忽略，主要变量是激活 —— 在 batch 16、梯度累积 4、加上梯度检查点的情况下 🟡（按你实际的卡型和显存说）。」

> ⚠️ **如果没有实测显存记录，就说"我没有精确记录峰值显存"** —— 别编数字。

## 11. 十个训练坑（真踩过才知道的）

:::card 顺序按"踩坑概率"排
1. **loss 只在 answer 上算**（prompt 的 label 设 `-100`）—— 忘了这条是最常见的"训了但没用"
2. **梯度累积 + batch 的等效关系**：batch 16 × 累积 4 = 等效 64，学习率要按等效 batch 调
3. **max_len 截断把回答截掉** → 模型学到"话说一半"，非常隐蔽
4. **packing 时 attention 跨样本** → 样本间串味（要用 varlen / 正确 mask）
5. **学习率太大** → loss 震荡或输出退化（LoRA 常用 1e-4，但数据少时可能 5e-5 更稳）
6. **dropout 设成 0** → 小数据上过拟合很快
7. **忘记 `model.eval()` / `inference_mode`** → 评测时还带 dropout，指标不稳
8. **多卡 DDP 下没用 `DistributedSampler`** → 每个卡看到一样的数据（等于没并行）
9. **保存时只存了 adapter 没记基座版本** → 复现时对不上（要记 base model revision）
10. **合并权重时精度不匹配**（fp16 合并 bf16 训练的 adapter）→ 效果下降
:::

## 12. 十个追问预答

:::qa LoRA 为什么能 work？它的假设是什么
两个层次：① **经验依据**：预训练模型的微调更新可投影到很低维的子空间而不掉性能（内在维度假说）；② **机制**：微调只是把分布从"通用"推到"任务"，这个偏移在参数空间里近似低秩。
**加分**：所以 LoRA 适合风格/格式/判别改造，不适合注入大量新知识。
:::

:::qa 为什么 A 随机初始化、B 置零
保证训练开始时 `ΔW = BA = 0`，模型行为与原模型完全一致（identity initialization）→ 不破坏预训练能力、训练稳定、可随时关闭 LoRA 做 A/B。
:::

:::qa α/r 这个缩放是干什么的
`BA` 的有效幅度随 r 变化；用 `α/r` 缩放可以让**改变 r 时等效学习率保持稳定**。r 很大时 `α/r` 会让更新过小，所以有 **rsLoRA** 改成 `α/√r`。
:::

:::qa 8B 模型 LoRA 的参数量占多少
通常 **0.3%–0.5%**（约 20–40M）。单个 4096×4096 矩阵 r=8 时是 `8×(4096+4096)=65.5K`，占原矩阵的 0.39%。
:::

:::qa 全参微调和 LoRA 的显存差在哪
**梯度**和**优化器状态**。全参下 Adam 的 m、v 是 fp32，每参数 **8 字节** —— 8B 模型就是 64GB；LoRA 只对千分之几的参数算这两项，所以几乎是 0。
**一句话**：「全参微调的大头是优化器状态，不是权重。」
:::

:::qa QLoRA 的三项技术分别解决什么
NF4（按分位数非均匀量化 4-bit，适配正态分布权重）、双重量化（对量化常数再量化，再省约 0.37 bit/param）、分页优化器（用统一内存换出优化器状态，削峰值）。
:::

:::qa QLoRA 有什么代价
慢（反量化开销）、精度损失（量化误差）、兼容性（合并到 bf16 基座时要注意精度）。有卡优先 bf16 LoRA。
:::

:::qa target_modules 只加 q、v 行不行
能跑但表达力弱。当前推荐 **attention + FFN**，因为 FFN 参数量占大头、承载大量知识。换词表/新语言时才加 embedding 和 lm_head。
:::

:::qa LoRA 训完之后怎么部署
两种：**merge 到基座**（`merge_and_unload`）→ 推理无额外开销、适合单任务；**不合并 + 多 LoRA 服务**（如 vLLM 的 multi-LoRA）→ 灵活切换、但显存占用上升。
:::

:::qa 多个 LoRA 能不能合并
可以简单加权平均，但**多任务时通常互相干扰**（不同任务学到的方向冲突）。实践用**路由**（按任务选 adapter）而不是合并。如果非要合并，要注意权重归一化和验证。
:::

## 13. 陷阱

| ❌ 别这么说 | ✅ 换成这么说 |
|---|---|
| 「LoRA 是参数量更小的微调」 | 「LoRA 假设**微调增量低秩**，用 `BA` 近似 `ΔW`，并靠 B 置零保证无损起步」 |
| 「LoRA 不改变模型能力上限」 | 「LoRA 受**低秩**限制，注入大量新知识需要更大 r 或全参」 |
| 「QLoRA 和 LoRA 只是精度不同」 | 「QLoRA = **NF4 量化基座 + 双重量化 + 分页优化器**，是"用速度换显存"」 |
| 「α 越大效果越好」 | 「α 是 scaling，通常取 2r；它影响等效学习率，不是"越大越好"」 |

## 14. 自测（7 题）

:::qa LoRA 的前向公式和初始化，为什么 B 要置零
`h = Wx + (α/r)BAx`；A 随机、B=0 → `ΔW=0`，保证起点与原模型一致（无损起步、训练稳定、可关闭）。
:::

:::qa 单矩阵 4096×4096 上 r=8 的 LoRA 参数量是多少
`r(d+k) = 8×8192 = 65,536`，占原矩阵（16.78M）的 **0.39%**。
:::

:::qa 全参微调 8B 的显存大头是什么？为什么
权重 16G + 梯度 16G + **Adam 状态 64G**（每参数 8 字节 fp32 的 m 和 v）≈ 96G。大头是优化器状态。
:::

:::qa QLoRA 的三项技术
NF4 量化、双重量化（DQ）、分页优化器（Paged Optimizer）。
:::

:::qa α/r 缩放的作用，rsLoRA 改了什么
让改变 r 时等效学习率稳定；rsLoRA 在 r 很大时改成 `α/√r` 避免更新过小。
:::

:::qa target_modules 为什么推荐加 FFN
FFN 参数占大头、承载大量知识，只改 attention 表达力不足。
:::

:::qa 你的 RePref-Fact 用了什么 LoRA 配置，为什么 r=8 够
r=8、α=16、dropout 0.1、attention+FFN、lr=1e-4、batch 16 + 累积 4、≤20 epoch + early stopping。r=8 够是因为我做的是**判别边界调整**（低秩改动），不是知识注入。
:::
