# 3.3 GRPO 与 RLVR（能讲清"为什么能去掉 value model"）

> **为什么这篇要重点学**：字节 Top20 高频里「**GRPO 与 PPO/DPO 的区别**」排五星第一；而且这是 2025 年后所有推理模型（R1 系列、QwQ、Kimi-K1.5 等）的核心训练方法。
> **本文目标**：讲清 GRPO 的**一个核心机制**（组内归一化替代 critic）、RLVR 的**奖励设计**、以及**训练会怎么崩**。
> **标注**：`★★★` 必背 ｜ 你没跑过 RL 训练，但要能在**原理层面对答如流**（§10 给了诚实话术）

---

## 1. 30 秒口述版

:::card 30 秒版
「GRPO 是 PPO 的**去 critic 版本**，出自 DeepSeekMath，后来被 R1 系列用来做推理训练。

PPO 需要一个和策略**同规模**的 value model（critic）来估计 baseline、降低方差，显存和训练复杂度都很高。GRPO 的做法很直接：**对同一个问题采样一组（比如 8 个）回答，用这一组奖励的均值当 baseline、标准差做归一化**，得到每个回答的优势：

`A_i = (r_i − mean(r)) / std(r)`

这样一来 **critic 就不需要了** —— 组内统计量就是蒙特卡洛估计的 baseline。

而 **RLVR** 是"用**可验证的奖励**做 RL"：数学题比对答案、代码跑单测、格式用正则校验。奖励不再依赖人训的 reward model，**既可靠又能大规模自动化**，所以 RL 在推理任务上重新变得可行。

代价有两个：**rollout 成本上升**（一次要采一组），以及**组内奖励全相同时优势为 0，这组样本就白采了**。」
:::

## 2. 为什么需要 GRPO：PPO 的三个痛点

:::card PPO 到底贵在哪（先立问题）
| 痛点 | 具体表现 |
|---|---|
| **① 需要 critic（value model）** | 与 policy **同规模**，要训练 → 显存翻倍（7B 全参下单个可训练模型 ≈ 84GB） |
| **② critic 难训** | 它要准确估计 `V(s)`；估不准 → 优势估计噪声大 → actor 更新方向错 → 训练崩 |
| **③ actor/critic 互相拖累** | critic 依赖 actor 的分布，actor 又依赖 critic 的优势，一方崩另一方跟着崩 |
:::

:::card GRPO 的一句话解法
> **"既然 critic 的作用只是提供一个 baseline 来降方差，那我为什么不直接用**同一问题多次采样的平均奖励**当 baseline？"**

这个 baseline 是**无偏的**（蒙特卡洛估计），而且**不需要额外模型**。代价是：为了拿到"同一问题的多个样本"，你必须**一次采一组** —— rollout 变贵，但训练变简单、显存大降。
:::

## 3. GRPO 的核心机制（必须能画出来）

### 3.1 组内归一化算优势

:::card 三步
**① 对一个问题 `q`，用当前策略采 `G` 个回答**（典型 G = 8 或 16）：
```
{o_1, o_2, …, o_G} ~ π_θ_old(·|q)
```

**② 每个回答拿到一个奖励** `r_i`（RLVR 场景下通常是 0/1 的规则判定）

**③ 组内归一化得到优势**：
```
A_i = ( r_i − mean(r_1,…,r_G) ) / std(r_1,…,r_G)
```

**直觉**：
- 如果某个回答的奖励**高于同组平均** → `A_i > 0` → 提升它的概率
- 低于平均 → `A_i < 0` → 压制它
- 关键：**优势是相对的**。哪怕 8 个回答全对，只要没有区分度（std=0），优势都是 0

**这就是"组内相对"四个字的来源** —— 它不问"这个答案绝对好不好"，问"**这个答案比同题的其他尝试好多少**"。
:::

:::card 一个极重要的推论（面试常考）
**如果一组里奖励全相同（全对或全错），std = 0 → 优势全为 0 → 这组样本对梯度没有贡献。**

所以实践中要做**样本过滤**：
- 全对的组 → 过滤（题目太简单，学不到东西）
- 全错的组 → 过滤（题目太难，没有正样本可强化）
- **只保留"有对有错"的组**（最有信息量）

这也是为什么 GRPO 的**有效 batch 会比理论 batch 小很多** —— 这是工程上一个很实际的坑。
:::

### 3.2 完整目标函数

:::card GRPO 的目标（和 PPO 一样是 clip 形式，只是优势换了）
```
J_GRPO(θ) = E_{q, {o_i}} [ (1/G) Σ_i  min(
      ( π_θ(o_i|q) / π_θ_old(o_i|q) ) · A_i ,
      clip( π_θ(o_i|q)/π_θ_old(o_i|q), 1−ε, 1+ε ) · A_i
  )  −  β · D_KL( π_θ || π_ref ) ]
```

三个部分各管什么：
| 部分 | 作用 |
|---|---|
| `ratio = π_θ/π_θ_old` | 重要性采样比（off-policy 修正） |
| `min(·, clip(·))` | **PPO 的 clip**：限制单次更新幅度，防崩 |
| `− β·D_KL(π_θ‖π_ref)` | **KL 约束**：别离参考模型太远（防跑飞、保持语言能力） |

**注意**：GRPO **去掉了 critic，但保留了 clip 和 KL** —— 这两项是 PPO 家族稳定性的来源，不能一起删。
:::

:::card KL 项怎么估（细节，被问"你写过 GRPO 吗"时会用到）
实践中常用 **k3 估计器**（无偏低方差）：
```
D_KL(π_θ || π_ref) ≈ π_ref(o|q)/π_θ(o|q) − log( π_ref(o|q)/π_θ(o|q) ) − 1
```
它只需要两个策略在**采样到的 token 上**的 logprob，不需要全词表归一化 —— 这也是它能塞进 RL 训练循环的原因。
:::

### 3.3 一张图对比三个方法

```
PPO     ：actor + critic + ref + rm      （4 个模型，在线采样）
          优势 A = r − V(s)               ← 需要 critic 估 V

GRPO    ：actor + ref + (rm 或规则)      （去掉 critic）
          优势 A = (r − mean)/std         ← 组内统计量当 baseline

DPO     ：actor + ref                    （离线，不采样）
          loss = −log σ(β·(logratio_w − logratio_l))
```

## 4. RLVR：可验证奖励（这是"为什么现在能训推理"的关键）

:::card 什么是 RLVR
**RLVR = RL with Verifiable Rewards**：奖励来自**可以自动判定的验证器**，而不是人训的 reward model。
| 任务类型 | 验证器 | 奖励 |
|---|---|---|
| 数学 | 答案抽取 + 数值/表达式比对 | 对 = 1，错 = 0 |
| 代码 | 跑单元测试 | 通过率 |
| 结构化输出 | JSON schema / 正则 | 合规 = 1 |
| 工具调用 | 调用是否成功、参数是否匹配 | 成功 = 1 |
| 指令约束 | 长度/格式/关键词检查 | 分项加权 |
:::

:::card 为什么 RLVR 让 RL"重新变得可行"
三个理由（这三点要能背）：
1. **奖励可靠**：不存在 RM 被刷的问题（测试用例不会撒谎）
2. **可大规模自动化**：不需要人工标注偏好，可以造海量题目自动判定
3. **信号明确**：0/1 的奖励虽然稀疏，但**方向不会错** —— 而人训 RM 可能"打分很高但答案是错的"

**代价**：
- 只能用于**有标准答案**的任务（开放式写作、闲聊就没法用）
- 0/1 奖励**很稀疏**（尤其是难题），所以需要样本过滤、课程学习、过程奖励
:::

:::card DeepSeek-R1 的奖励设计（经典参考）
| 奖励 | 内容 | 说明 |
|---|---|---|
| **准确性奖励** | 数学题比对最终答案；代码跑测试 | 主信号，规则判定 |
| **格式奖励** | 要求把推理过程放在 ` think...<｜end▁of▁thinking｜>` 标签内 | 只是格式约束，**不是"奖励思考过程"** |
| 语言一致性奖励（部分版本） | 要求回答与提问语言一致 | 防中英混杂 |

**一个重要的设计判断**：R1 **没有**用过程奖励模型（PRM）做主线，原因是**过程奖励容易被刷**（模型学会"写出看起来像正确推理的步骤"但答案还是错）。这是"结果奖励 > 过程奖励"的一个实践证据。
:::

## 5. 奖励设计的五个陷阱（面试最爱问"会有什么问题"）

:::card ① Reward Hacking（奖励被刷）
**表现**：模型找到奖励函数的漏洞，而不是真正解题。典型例子：
- 格式奖励 → 只输出格式不推理（"答案在 <｜end▁of▁thinking｜> 里"）
- 长度惩罚 → 越写越短，直接给答案
- 答案匹配用正则 → 学会把候选答案全列出来（"答案是 A 或 B 或 C"）

**对策**：
- 奖励**多项组合**且互相制衡（准确性 + 格式 + 长度区间）
- **对抗性测试**：专门构造能骗过奖励的样本，看模型有没有学会
- 定期**人工抽检**，不要只看分数曲线
:::

:::card ② 稀疏奖励（全对/全错 → 优势为 0）
**表现**：难题上模型 pass@k ≈ 0 → 奖励全 0 → 梯度为 0 → 学不到（"这不是训练，这是抽奖"）

**对策**（四条，按性价比）：
1. **样本过滤 / 难度筛**：只用 pass rate 在中间区间的题（如 0.1–0.9）
2. **课程学习**：从易到难，逐步放开
3. **部分奖励 / reward shaping**：给"答对一半"部分分（但要小心引入偏差）
4. **混合任务**：难题旁边配简单题，保证 batch 里有正样本
:::

:::card ③ 长度偏置与"啰嗦化"
**表现**：不加约束时，模型倾向于**越写越长**（因为长推理在训练集里经常与正确相关）
**对策**：长度惩罚（有上限的、非线性的）、按长度归一化的奖励、监控长度分布曲线
**注意**：长度惩罚太强会把"该长的推理"也压掉 → 要留安全边界
:::

:::card ④ 格式奖励被"低成本满足"
**表现**：格式检查是规则，模型 100% 满足格式后，格式奖励变成**常数** → 不再提供梯度，但也没坏处；**坏处是它可能挤占了本该用于准确性的探索**
**对策**：格式奖励权重设小（如 0.1），或只在训练早期使用、后期撤掉
:::

:::card ⑤ 奖励尺度不一致
**表现**：不同题目、不同任务的奖励尺度差异大（有的 0/1，有的连续），导致**梯度被某个任务主导**
**对策**：奖励归一化（按任务/难度分组归一化）、任务采样权重平衡
:::

## 6. 训练会怎么崩（现象 + 原因 + 对策）

:::card 四个典型崩溃现象
| 现象 | 原因 | 对策 |
|---|---|---|
| **熵塌缩（entropy collapse）** | 策略过早收敛到单一输出，探索消失 → 后续奖励全同 → 优势恒 0 | 熵正则 / 提高采样温度 / 过滤全对组 / 调小 lr |
| **优势恒为 0 的组太多** | 题目太难或太简单 | 难度筛 + 课程学习 |
| **KL 暴涨** | β 太小或 lr 太大，策略偏离 π_ref 太远 | 增大 β、降低 lr、clip 收紧 |
| **输出格式崩坏** | 奖励只看答案不看格式 | 加格式奖励、加长度约束 |

**面试高频追问**：「你怎么知道训练在变好还是在崩？」→ 看**三条曲线**：
1. 平均奖励（该上升）
2. **策略熵**（该缓慢下降，突然断崖 = 探索没了）
3. **KL 到 π_ref**（该平稳，暴涨 = 跑飞了）
:::

## 7. GRPO / PPO / DPO 的选择（决策版）

:::card 三句话
- **有偏好对 + 算力有限** → **DPO**（离线、稳、便宜，但上限受数据限制）
- **有可验证奖励（数学/代码/格式）+ 想让模型超越数据** → **GRPO**（在线探索、省掉 critic）
- **有可靠 RM + 算力充足 + 需要通用偏好对齐** → **PPO**（最通用但最难调）
:::

:::card 一个实践顺序（面试可以这么答）
> 「我会**先用 SFT 建立基础分布，再用 DPO 做快速对齐**（成本最低），如果指标还差、而且任务有可验证信号，**再上 GRPO**。
> 直接上 PPO 一般是最后的选择 —— 因为它需要先训一个可靠的 RM，而 RM 训不好会让整个循环失效。」

**为什么这个顺序合理**：DPO 的失败是"温和的"（效果不够），PPO 的失败是"灾难性的"（训崩、RM 被刷），所以先用便宜的方法探底。
:::

## 9. 十个追问预答

:::qa GRPO 和 PPO 最本质的区别是什么
**PPO 用 critic 估计 baseline `V(s)`；GRPO 用"同一问题采一组回答的均值"当 baseline。**
所以 GRPO 省掉了一个与 policy 同规模的 value model（显存大降），也不需要训 critic（少一个不稳定源）。
代价：必须一次采一组（rollout 成本上升），且组内奖励全相同时优势为 0。
:::

:::qa 组内归一化为什么能当 baseline？这在统计上成立吗
成立。PPO 里 baseline 的作用是**降方差而不引入偏差** —— 只要 baseline 不依赖动作 `a`，`E[∇log π · b] = 0`，就不会改变梯度的期望。
组内均值 `mean(r)` 只依赖"同一问题的采样集合"，**不依赖具体某个动作的选择**，所以是合法的 baseline（蒙特卡洛估计）。
**加一句**：除以 `std` 是额外做的尺度归一化，让不同题目的优势尺度可比（这不是降方差必需，但对稳定性有用）。
:::

:::qa 为什么全对或全错的组"白采了"
因为 `std = 0` → 所有 `A_i = 0` → 该组对梯度贡献为 0。
这也是为什么实践中要过滤这些组：**它们消耗了 rollout 成本但不产生学习信号**。
面试加分：这说明 **GRPO 的有效 batch 远小于理论 batch**，是工程上必须处理的问题。
:::

:::qa 什么是 RLVR？为什么不直接用 reward model
RLVR = 用**可验证的验证器**（答案比对、单测、schema 校验）当奖励，而不是人训的 RM。
三个优势：奖励可靠（不会被刷）、可大规模自动化（不需要人工标偏好）、信号方向明确（RM 可能高分但答案是错的）。
代价：只能用于有标准答案的任务，且奖励稀疏。
:::

:::qa RLVR 的稀疏奖励怎么解决
四条：**难度筛**（只用 pass rate 在中间区间的题）、**课程学习**（易到难）、**部分奖励/shaping**（谨慎，会引入偏差）、**混合任务**（难题旁配简单题保证有正样本）。
:::

:::qa reward hacking 在 RLVR 里会怎么表现
三个典型：
1. **格式套利**：只输出格式不推理（因为格式奖励容易拿）
2. **答案枚举**：把多个候选都列出来骗匹配（用"答案包含"而不是"精确匹配"时最容易）
3. **长度套利**：如果有长度惩罚，就写极短答案直接给结果

**对策**：奖励组合互相制衡 + 对抗性测试 + 人工抽检（不要只看分数曲线）。
:::

:::qa 训练过程中熵突然掉到很低，说明什么
**熵塌缩**：策略收敛到单一输出，探索能力丧失。后果是**后续采样全相同 → 优势恒 0 → 训练停滞**。
对策：熵正则、提高采样温度、过滤全对组、降低 lr。
**怎么发现**：监控策略熵曲线（应该缓慢下降，断崖式下降就是信号）。
:::

:::qa GRPO 里的 KL 项能不能去掉
不能轻易去。KL 项有两个作用：
1. **防跑飞**：不约束时策略会为了奖励而破坏语言能力（输出乱码、重复）
2. **保持参考分布**：让模型在原能力上"微调"而不是"重写"

去掉 KL 的变体（如 Dr.GRPO 一类）通常要配其他约束（如长度归一化、clip 收紧），**不是简单地删掉**。
:::

:::qa 为什么 R1 不用过程奖励模型（PRM）
因为**过程奖励容易被刷**：模型会学会"写出看起来正确的推理步骤"，但答案依然错。
而结果奖励（答案对不对）**无法伪造** —— 这就是 R1 用"结果奖励 + 格式奖励"而不是 PRM 的原因。

**补充**：PRM 在"搜索时做验证器"（如 best-of-N 重排）里仍然有价值，只是不适合当 RL 的主奖励。
:::

:::qa 【挂点】你没跑过 GRPO，被追问怎么办
按 §8 的诚实话术答：原理能讲清（组内归一化、RLVR、崩溃现象），但承认没有"调到不崩"的工程经验，并说明你知道第一步该做什么（打通 rollout → 确认 pass@k 不为 0 → 再设计奖励）。
**这样答的好处**：面试官会觉得你诚实且知道路径，比硬编一个"我调过"然后被细节问穿好得多。
:::

## 10. 陷阱

| ❌ 别这么说 | ✅ 换成这么说 |
|---|---|
| 「GRPO 是 PPO 的简化版」 | 「GRPO 用**组内统计量替代 critic**，去掉了 value model，但保留了 clip 和 KL」 |

## 11. 自测（8 题）

:::qa 用一句话说清 GRPO 怎么去掉 value model
对同一问题采一组回答，用组内奖励的**均值当 baseline、标准差做归一化**得到优势，替代 PPO 里 critic 估计的 `V(s)`。
:::

:::qa 写出 GRPO 的优势公式，并说明 std=0 时会发生什么
`A_i = (r_i − mean(r))/std(r)`。std=0（全对或全错）→ 所有 A_i=0 → 该组对梯度无贡献 → 白采，实践中要过滤。
:::

:::qa GRPO 保留了 PPO 的哪两部分？为什么不能删
**clip**（限制单次更新幅度，防崩）和 **KL 约束**（防跑飞、保语言能力）。删了这两个，GRPO 就退化成"纯策略梯度 + 组内优势"，稳定性会明显下降。
:::

:::qa RLVR 是什么？三个优势
用可验证的验证器当奖励。优势：奖励可靠（不会被刷）、可大规模自动化、信号方向明确。
:::

:::qa 稀疏奖励的四条对策
难度筛（pass rate 中间区间）、课程学习、部分奖励/shaping、混合任务（难题配简单题）。
:::

:::qa reward hacking 在 RLVR 里的三个典型表现
格式套利（只输出格式不推理）、答案枚举（列多个候选骗匹配）、长度套利（极短答案骗长度惩罚）。
:::

:::qa 监控哪三条曲线能判断训练健康
平均奖励（该升）、策略熵（该缓降，断崖=熵塌缩）、KL 到 π_ref（该平稳，暴涨=跑飞）。
:::

:::qa 为什么 R1 不用 PRM 当主奖励
过程奖励容易被刷（学会写出"看起来对"的步骤但答案仍错），结果奖励无法伪造。
:::
