# 5.3 Embedding 训练与选型（怎么训一个检索模型）

> **为什么值一篇**：贝壳类 JD 明确写 Embedding；而且面试常问"embedding 怎么训"、"什么时候需要领域微调"。
> **和第 5.2 的关系**：5.2 讲"用哪个检索器"，这篇讲"**怎么造/选这个编码器**"。
> **标注**：`★★☆`

---

## 1. 30 秒口述版

:::card 30 秒版
「训练一个好的检索 embedding，核心是**对比学习 + 难负样本**。

标准目标是 InfoNCE：对一个 (query, 正例文档) 对，把**同 batch 里其他文档当负例**，用 softmax 做分类。温度 `τ` 控制"关注难负例的程度"——`τ` 小则更关注最难的负例。

真正决定效果的是**负例的质量**：
- **batch 内负例**：简单、免费，但大多太容易
- **全库挖难负例**（ANCE 路线）：难，但效果明显更好
- **从 cross-encoder 蒸馏**：用强 reranker 给候选打分，让双塔去拟合 → 这是目前工业界最主流的做法

工程上还要定三件事：**相似度度量**（归一化后余弦）、**维度**（768/1024/1536，越大越贵）、**选型**（MTEB 排行榜 + 自己的评测集，不能只看榜）。

一句话：**通用模型先试，效果不够再领域微调；微调时负例质量比模型结构更重要。**」
:::

---

## 2. 训练目标：InfoNCE 与温度

:::card 公式
$$
\mathcal{L}=-\log\frac{\exp\big(\operatorname{sim}(q,d^+)/\tau\big)}{\exp\big(\operatorname{sim}(q,d^+)/\tau\big)+\sum_{d^-}\exp\big(\operatorname{sim}(q,d^-)/\tau\big)}
$$
- `sim`：通常用**归一化后的点积**（= 余弦相似度）
- `τ`：温度，典型 **0.01–0.05**（比 LLM 采样的温度小得多）
  - `τ` 小 → 分布尖锐 → **更关注最难的负例**
  - `τ` 大 → 平滑 → 所有负例权重接近
:::

:::card 一个必须理解的机制：in-batch negatives 的"免费负例"
一个 batch 有 `B` 个 (query, doc) 对。对第 `i` 个 query 来说，**其他 `B−1` 个 doc 天然是负例** —— 不需要额外标注，也不需要额外前向。

**所以 batch 越大，负例越多，效果越好**（这也是为什么训练 embedding 需要大 batch）。代价是显存。

**面试话术**：「in-batch negatives 是这个任务里最划算的设计 —— **一次前向同时得到 1 个正例和 B−1 个负例**。所以 embedding 训练里 batch size 是重要超参，不是随便设的。」
:::

## 3. 难负样本（效果的最大杠杆）

:::card 三种挖法（和 5.2 的框架一致）
| 方法 | 做法 | 成本 | 效果 |
|---|---|---|---|
| **batch 内** | 免费 | 0 | 基线 |
| **全库 ANN 挖**（ANCE 路线） | 用当前模型检索全库，取高分非正例 | 高（要维护索引） | 好 |
| **cross-encoder 蒸馏** | 用 reranker 对候选打分，取"高分但非正例" | 中（离线跑一次） | **最好（工业主流）** |
:::

:::card 蒸馏的具体做法（这是最实用的路线）
1. 用 BM25/现有模型为每个 query 召回 **top-100** 候选
2. 用 **cross-encoder** 给这 100 个候选打分（这是"教师"）
3. 取出"**分数很高但不是标注正例**"的文档 → 这就是**高质量难负例**
4. 用这些难负例训练双塔（学生）

**为什么有效**：cross-encoder 能看到 token 级交互，判断"这个文档看起来相关但其实答不了这个问题"，这种判断力被蒸馏进双塔。

**一句话**：「**用强模型挑负例、用弱模型学表示** —— 这就是蒸馏式 embedding 训练的核心。」
:::

:::card 难负例的两个坑
1. **假负例（false negative）**：检索出的高分文档里可能有**真正相关的**（只是没被标注）→ 当成负例会教坏模型。对策：用阈值过滤、或多模型投票。
2. **负例太难的早期问题**：训练初期模型很弱，挖出的"高相似"其实是噪声 → 常见做法是**从简单到难逐步引入**（课程式）。
:::

## 4. 什么时候需要领域微调

:::card 判断标准（不要盲目微调）
**先测再决定**：拿通用模型（如 BGE-M3、e5、GTE）在**你自己的评测集**上跑 Recall@10。然后看：

| 情况 | 是否需要微调 |
|---|---|
| Recall@10 已经 > 80% | ❌ 不需要，调 chunking/rerank 更有收益 |
| 明显低，且**领域术语多**（医疗、法律、金融、代码） | ✅ 值得微调 |
| 低但术语不多（通用问答） | ⚠️ 先试查询改写/混合检索 |
| 需要**跨语言** | ✅ 选多语模型或微调 |
:::

:::card 微调的最小可行方案
1. **数据**：几百到几千条 (query, 正例) 就够起步（可以从业务日志/点击构造）
2. **负例**：先用 BM25/现有模型挖 top-100，再用 cross-encoder 过滤
3. **训练**：冻结 encoder 下部、只训上部 + 投影层？ → 通常**全量微调效果更好**（embedding 模型小，7B 以下成本可控）
4. **验证**：必须用**独立评测集**（不要用训练集的重排指标），看 Recall@k 与 MRR
:::

:::card 一个反直觉的经验
**领域微调常常不如"换一个更强的通用模型 + 加 reranker"**。
原因：micro 调容易过拟合到"训练集的 query 表述风格"，遇到真实用户的新表述就退化。所以顺序应该是：**换基座 → 混合检索 → reranker → 最后才微调 embedding**。
:::

## 5. 相似度度量与归一化（细节常被问）

:::card 三种度量与归一化的关系
| 度量 | 公式 | 说明 |
|---|---|---|
| **余弦相似度** | `(a·b) / (‖a‖‖b‖)` | 只看方向，**最常用** |
| **点积** | `a·b` | 同时受方向和模长影响 |
| **L2 距离** | `‖a−b‖` | 与归一化后的点积**等价**（单调对应） |

**关键结论**：
> **如果向量都做了 L2 归一化，那么"余弦相似度 = 点积"，且与"L2 距离"单调等价。**

**这带来两个工程影响**：
1. **归一化后可以用更快的点积/内积索引**（很多向量库的内积索引比余弦快）
2. **不归一化时，模长会偷偷影响排序** → 可能出现"长文档天然分高"的偏差

**面试话术**：「训练时用归一化点积、入库前统一 L2 归一化，这样余弦和点积等价，可以直接用内积索引，也避免了模长带来的偏置。」
:::

## 6. 维度与存储成本

:::card 维度的权衡
| 维度 | 检索质量 | 存储（1 亿条，fp32） | ANN 速度 |
|---|---|---|---|
| 384 | 较低 | 154 GB | 快 |
| 768 | 中 | 307 GB | 中 |
| 1024 | 较高 | 410 GB | 慢 |
| 1536+ | 高 | 614 GB+ | 更慢 |

**降本手段**：
1. **降维**（MRL，Matryoshka Representation Learning）：一个模型输出可截断的前缀维度（如 1536 → 512 仍可用）→ 训练时就支持多维度
2. **量化**（int8 / PQ）：见 4.5，PQ 能把向量压到 1/8~1/32
3. **两级检索**：粗筛用低维/量化，精排用原始维度

**一句话**：「维度不是越高越好 —— 存储和延迟是线性/超线性成本，而质量提升是递减的。」
:::

## 7. 选型（MTEB 怎么用）

:::card 正确的用法
1. **看子榜单而不是总分**：MTEB 有 Retrieval / Reranking / Classification / Clustering 等子任务，你要的是 **Retrieval**
2. **看中文/领域子集**：C-MTEB 或领域子集比总榜更相关
3. **自己测**：拿 50–100 条业务 query 做人工标注，算 Recall@10 —— **这一步不能省**
4. **看工程指标**：模型大小、推理延迟、最大输入长度（chunk 长的话很重要）、是否支持多语

**面试话术**：「MTEB 只用来筛候选，最终选型一定用自己的评测集 —— 因为榜单的 query 分布和业务差很远。」
:::

## 8. 八个追问预答

:::qa 训练 embedding 用什么损失？温度取多少
InfoNCE（归一化点积 + 温度）。`τ` 典型 **0.01–0.05**，比 LLM 采样温度小得多；`τ` 小更关注难负例。
:::

:::qa 为什么 embedding 训练需要大 batch
因为 batch 内负例是"免费负例"，batch 越大负例越多、效果越好。所以 batch size 是重要超参（还要配梯度累积/跨卡 all-gather 实现"虚拟大 batch"）。
:::

:::qa in-batch negatives 有什么风险
**假负例**：batch 里可能有和 query 真正相关的文档（只是没标注）→ 被当负例压制。缓解：去重、用阈值过滤、或混合难负例时做校验。
:::

:::qa 怎么挖难负例最划算
**用 cross-encoder 蒸馏**：现有模型召回 top-100 → cross-encoder 打分 → 取"高分但非正例"作为难负例。比全库 ANN 挖便宜，效果更好。
:::

:::qa 什么时候需要领域微调 embedding
先在自有评测集测 Recall@10：已经 >80% 就不需要（改 chunking/rerank 更有收益）；明显低且领域术语多才微调。
**顺序**：换基座 → 混合检索 → reranker → 最后才微调。
:::

:::qa 余弦、点积、L2 的关系
向量 L2 归一化后，**余弦 = 点积**，且与 L2 距离单调等价。所以归一化后可以用更快的点积索引，也避免模长带来的偏置。
:::

:::qa embedding 维度的取舍
质量随维度递减、成本线性增长。降本手段：MRL 可截断维度、int8/PQ 量化、两级检索（低维粗筛 + 高维精排）。
:::

:::qa 怎么用 MTEB 选型
只看 **Retrieval 子榜**（不要总分）、优先中文/领域子集、再用自己的 50–100 条标注数据算 Recall@10 定稿；同时看模型大小、延迟、最大长度、多语支持。
:::

## 9. 陷阱

| ❌ 别这么说 | ✅ 换成这么说 |
|---|---|
| 「embedding 微调一定比通用模型好」 | 「先测再用；顺序是换基座 → 混合检索 → rerank → 最后微调」 |
| 「batch size 只影响速度」 | 「它决定**免费负例的数量**，是效果超参」 |
| 「难负例越多越好」 | 「要防**假负例**（未标注的真相关），并且从易到难逐步引入」 |
| 「余弦和点积一样」 | 「**归一化后**才等价；不归一化时模长会影响排序」 |
| 「看 MTEB 总分选模型」 | 「看 Retrieval 子榜 + 自己的评测集」 |

## 10. 自测（6 题）

:::qa InfoNCE 的公式和温度的作用
`−log[exp(sim(q,d+)/τ) / Σ exp(sim(q,d-)/τ)]`。`τ` 小 → 分布尖锐 → 更关注难负例；典型 0.01–0.05。
:::

:::qa 为什么 embedding 训练要用大 batch
batch 内其他文档是免费负例，batch 越大负例越多效果越好；可用梯度累积/跨卡 all-gather 做"虚拟大 batch"。
:::

:::qa 蒸馏式 embedding 训练的流程
现有模型召回 top-100 → cross-encoder 打分 → 取"高分但非正例"作难负例 → 训双塔。核心是"用强模型挑负例，用弱模型学表示"。
:::

:::qa 什么时候不该微调 embedding
自有评测集上 Recall@10 已经很高时；此时改 chunking、混合检索、加 reranker 收益更大。
:::

:::qa 归一化的两个好处
① 余弦=点积，可用更快的点积索引；② 避免向量模长影响排序带来的偏置。
:::

:::qa 假负例是什么，怎么缓解
检索出的高分文档里可能有真正相关的（未标注），被当负例会教坏模型。缓解：阈值过滤、多模型校验、去重。
:::
