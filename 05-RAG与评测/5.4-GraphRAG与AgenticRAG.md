# 5.4 GraphRAG 与 Agentic RAG（图谱增强与自适应检索）

> **为什么单独一篇**：GraphRAG 和 Agentic RAG 是 2026 年的高频词（主流题库都单独列章节），而且是"RAG 从简单拼装走向系统化"的体现。
> **本文还有一层价值**：它给你**一个准确的定位** —— 你的多智能体检索到底在学术谱系的哪个位置。
> **标注**：`★★☆`

---

## 1. 30 秒口述版

:::card 30 秒版
「传统 RAG 有两个天花板：

**第一个是"只能答局部问题"**。向量检索是把问题匹配到**相似的片段**，所以它擅长"这段文档里说了什么"，但答不了"**这批文档整体讲了哪些主题**"这类全局性问题。**GraphRAG** 就是为这个设计的：先抽实体和关系建图、再做社区检测、对每个社区生成摘要，回答全局问题时用这些**摘要**而不是原始片段。

**第二个是"一次检索定生死"**。检索不到就完了，没有补救。**Agentic RAG** 把检索变成**可决策的循环**：要不要检索、检索到了够不够、不够就改写重试、还不行就换源。

这条谱系上三个代表：**Self-RAG**（模型自己判断要不要检索、结果好不好）、**CRAG**（评估检索质量并纠正）、**Adaptive-RAG**（按问题难度选策略）。

我的多智能体动态检索就在这条线上 —— 可以概括成 **Adaptive-RAG 的多智能体实现 + 事实依赖图调度**。」
:::

---

## 2. 为什么需要图结构（GraphRAG 的动机）

:::card 向量检索的三个盲区
| 盲区 | 例子 | 为什么向量检索搞不定 |
|---|---|---|
| **全局性问题** | "这批文档的主要议题有哪些？" | 这不是"匹配某个片段"，是要**汇总整个语料** |
| **跨文档多跳** | "A 公司的 CEO 之前在哪家公司？" | 需要 A → CEO → 前公司 两跳，单一片段里没有 |
| **关系型推理** | "哪些供应商同时供给了这两个产品线？" | 需要**实体间的关系结构** |
:::

:::card GraphRAG 的核心洞察
> **把"检索相似片段"换成"检索相关的子图/社区摘要"。**

因为**关系本身**也是知识，而向量空间里没有"关系"这个维度 —— 只有"语义相似"。
:::

## 3. GraphRAG 的四步流程（要能讲出每步的成本）

:::card 四步
**① 实体与关系抽取**
用 LLM 通读每个 chunk，抽出 `(实体, 关系, 实体)` 三元组，并保留出处。
- **成本最高的地方**：每个 chunk 都要一次（或多次）LLM 调用

**② 建图 + 社区检测**
把三元组合成图（实体是节点、关系是边），用 **Leiden 等算法做层次化社区检测**（把图切成若干簇，簇内连接紧密）。

**③ 社区摘要**
对**每个社区**用 LLM 生成一段摘要，描述"这个社区在讲什么"。
- 这也是高成本：社区数量可能上百，每个都要一次调用

**④ 查询时两种模式**
| 模式 | 用什么东西回答 | 适合的问题 |
|---|---|---|
| **Global search** | 用**社区摘要**作为上下文（map-reduce 式汇总） | 全局性/主题性问题 |
| **Local search** | 从问题里的实体出发，取它的**邻域子图 + 相关原文** | 实体中心的具体问题 |
:::

:::card 成本对比（面试常问"值不值得"）
| 方案 | 索引成本 | 查询成本 | 更新成本 |
|---|---|---|---|
| 传统向量 RAG | 低（一次 embedding） | 低 | **低（增删块即可）** |
| **GraphRAG** | **很高**（每个 chunk 抽实体 + 每个社区生成摘要） | 中（global 要 map-reduce 多个摘要） | **很高（改一处可能影响社区）** |

**面试话术**：「GraphRAG 不是"更好的 RAG"，它是"**为另一类问题准备的 RAG**"。代价是索引成本可能高一个数量级、而且**增量更新很麻烦**（社区结构会变）。所以它适合**相对静态、但需要全局理解**的语料（如一批制度文档、一整套研究报告）。」
:::

## 4. 什么时候值得用 GraphRAG

:::card 判断清单（满足越多越值得）
- ✅ 问题里经常出现"**整体 / 主要 / 有哪些类别**"这类全局问法
- ✅ 需要**跨文档关系推理**（实体-关系网络很重要）
- ✅ 语料**相对静态**（不需要频繁增删）
- ✅ 能接受**较高的索引成本**（一次性投入）
- ❌ 如果只是"从文档里找一段话回答"，传统 RAG + reranker 更划算
:::

## 5. Agentic RAG 谱系（三个代表 + 各自解决什么）

:::card 一张表
| 方法 | 核心机制 | 解决什么 | 代价 |
|---|---|---|---|
| **Self-RAG** | 模型生成**特殊反思 token**，自己判断：要不要检索、检索到的片段相不相关、生成是否被支持 | "无脑检索"和"无脑不检索"都不好 | 需要专门微调出反思能力 |
| **CRAG**（Corrective RAG） | 先用**轻量评估器**给检索结果打分；低分就**纠正**（换源/改写查询/退回纯生成） | 检索结果质量差时没有兜底 | 多一次评估成本 |
| **Adaptive-RAG** | 先判断**问题难度**，再选策略：不检索 / 单步检索 / 多步检索 | 简单问题不必多花成本 | 分类器判断错了会走错路 |
:::

:::card 三者的共同思想
> **都不假设"检索一次就一定够"，而是把"要不要检索、检索得够不够、不够怎么办"变成系统里显式的决策。**

这就是"RAG"和"Agentic RAG"的分界：**前者是流水线（pipeline），后者是控制回路（control loop）**。
:::

## 6. 【挂点】你的项目在这条谱系的位置

:::card 准确的一句话定位（面试直接用）
> 「我的多智能体动态检索可以概括成 **Adaptive-RAG 的多智能体实现 + 事实依赖图调度**。」

**更细的对照**：
| 谱系里的机制 | 你项目里的对应物 |
|---|---|
| Self-RAG 的"要不要继续检索" | 你的**证据状态覆盖率 + 边际收益**判断 |
| CRAG 的"检索质量评估 + 纠正" | 你的**冲突消解 Agent** + 策略切换（直接/改写/对抗） |
| Adaptive-RAG 的"按难度选策略" | 你的策略层（但你的选择依据是**状态**，不只是难度） |
| —— **你多出来的** | **事实依赖图决定检索顺序**（谁先查、谁依赖谁的结果） |

**这句话最能体现差异**：
> 「Adaptive-RAG 只看"问题难不难"来决定策略；我是看"**当前证据状态**"——覆盖率、冲突数、边际收益。所以我的决策是**执行过程中动态产生**的，而不是开局一次性判断。」
:::

## 7. 八个追问预答

:::qa GraphRAG 和普通 RAG 的本质区别
普通 RAG 检索**相似的文本片段**；GraphRAG 检索**图结构和社区摘要**。前者擅长局部事实，后者擅长**全局主题汇总和跨文档关系推理**。
:::

:::qa GraphRAG 能解决什么普通 RAG 解决不了的问题
全局性问题（"这批文档的主要议题"）和跨文档多跳（A→CEO→前公司）。因为向量空间里**没有"关系"这个维度**，只有语义相似。
:::

:::qa GraphRAG 的主要代价是什么
① **索引成本高**（每个 chunk 抽实体、每个社区生成摘要，LLM 调用量巨大）；② **增量更新麻烦**（改内容会改变社区结构）；③ global search 是 map-reduce，查询也比普通 RAG 慢。
:::

:::qa 什么时候不该用 GraphRAG
当问题主要是"从文档里找一段话作答"时 —— 传统 RAG + reranker 便宜得多，效果也够。GraphRAG 是为**全局/关系型问题**准备的。
:::

:::qa Self-RAG 的核心机制
训练模型生成**反思 token**：判断"是否需要检索"、"检索片段是否相关"、"生成内容是否被支持"。它把"检索决策"内化进模型，而不是外挂规则。
:::

:::qa CRAG 和 Self-RAG 的区别
CRAG 外挂一个**检索质量评估器**，对结果打分后决定"用/纠正/放弃"；Self-RAG 是**模型自己学会**判断。前者不需要专门训练、易落地；后者需要微调但决策更细。
:::

:::qa Adaptive-RAG 的思路和局限
按**问题难度**分类，选"不检索/单步/多步"。局限是：开局判断错了就一路错；而且"难度"是静态判断，不随执行过程调整。
**这正是我的改进点**：我用**执行中的证据状态**驱动策略，是动态的。
:::

:::qa 你的项目和这三个的关系
Adaptive-RAG 的多智能体实现 + 事实依赖图调度。具体：覆盖率/边际收益 ≈ Self-RAG 的"要不要继续"；冲突消解 + 策略切换 ≈ CRAG 的纠正；策略层 ≈ Adaptive-RAG 的分档。**多出来的是依赖图决定检索顺序**。
:::

## 8. 陷阱

| ❌ 别这么说 | ✅ 换成这么说 |
|---|---|
| 「GraphRAG 比 RAG 更先进」 | 「GraphRAG 是**为全局/关系型问题**准备的另一种检索，代价是索引成本高一个量级」 |
| 「GraphRAG 就是把知识图谱接到 RAG 上」 | 「关键是**实体抽取 + 社区检测 + 社区摘要**，全局查询用的是摘要而不是原文」 |
| 「Agentic RAG 就是多轮检索」 | 「区别在于**显式的控制回路**：要不要检索、够不够、不够怎么纠正」 |
| 「我做的是 Adaptive-RAG」 | 「我是 Adaptive-RAG 的多智能体实现 + **依赖图调度**，且策略由**证据状态**驱动而非难度分档」 |

## 9. 自测（5 题）

:::qa 向量检索的两个根本盲区
① 全局性问题（需要汇总整个语料）② 跨文档关系推理（向量空间没有"关系"维度）。
:::

:::qa GraphRAG 的四步流程
实体关系抽取 → 建图 + 社区检测 → 社区摘要 → 查询（global 用摘要 / local 用邻域子图）。
:::

:::qa GraphRAG 最贵的两步是什么
实体抽取（每 chunk 一次 LLM）和社区摘要（每社区一次）。
:::

:::qa Self-RAG / CRAG / Adaptive-RAG 各解决什么问题
Self-RAG：模型自己判断要不要检索、结果好不好；CRAG：外挂评估器 + 纠正；Adaptive-RAG：按难度分档选策略。
:::

:::qa 用一句话给你的多智能体项目定位
Adaptive-RAG 的多智能体实现 + 事实依赖图调度，且策略由**证据状态**（覆盖率/冲突/边际收益）驱动，而非开局的难度判断。
:::
