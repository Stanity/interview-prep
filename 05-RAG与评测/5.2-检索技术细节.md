## 1. 30 秒口述版

:::card 30 秒版
「检索有两大家族：**稀疏（BM25）** 和**稠密（双塔向量）**。

**BM25** 靠词频和逆文档频率打分，擅长**精确词匹配**（编号、人名、专业术语），不用训练、可解释、是永远打不倒的基线。它的两个关键设计是 **tf 饱和**（同一个词出现 100 次不等于相关 100 倍）和 **长度归一化**（长文档不该因为词多就占便宜）。

**稠密检索** 用双塔把 query 和 doc 编成向量，靠相似度检索，擅长**语义匹配**（同义改写、跨语言）。训练靠对比学习 + 难负样本。

我论文里用的四种：BM25、**Contriever**（无监督对比，用同文档片段造正例）、**Contriever-MS**（多语/多源版本）、**ANCE**（关键创新是**用全库近似最近邻挖难负样本**，并异步刷新索引）。

工程上二者**互补**，所以标准做法是**混合检索 + RRF 融合 + cross-encoder 精排**。」
:::

## 2. BM25（公式要能写出来）

:::card 公式
```
BM25(q, d) = Σ_{t∈q}  IDF(t) · [ tf(t,d) · (k₁ + 1) ] / [ tf(t,d) + k₁ · (1 − b + b · |d| / avgdl) ]
```

其中：
```
IDF(t) = ln( 1 + (N − df(t) + 0.5) / (df(t) + 0.5) )
```
- `tf(t,d)`：词 t 在文档 d 中的频次
- `df(t)`：包含 t 的文档数；`N`：总文档数
- `|d|`：文档长度；`avgdl`：平均文档长度
- `k₁ ≈ 1.2–2.0`：**tf 饱和**强度
- `b ≈ 0.75`：**长度归一化**强度（b=0 关闭，b=1 完全归一）
:::

:::card 三个设计各解决什么（面试要能解释）
| 设计 | 作用 | 不这样做会怎样 |
|---|---|---|
| **IDF** | 罕见词权重高、常见词权重低 | "the" 这种词会主导打分 |
| **tf 饱和**（`k₁`） | 词频增长的边际收益递减 | 关键词堆砌的文档会刷榜 |
| **长度归一化**（`b`） | 惩罚长文档 | 长文档因为词多而系统性占优 |
:::

:::card 为什么 BM25 至今仍是强基线（三个理由）
1. **精确匹配无可替代**：产品型号、人名、编号、缩写 —— 稠密向量容易"语义近似但错误匹配"
2. **零训练成本**：不需要 GPU、不需要标注数据、上亿文档也能建索引
3. **可解释 + 稳定**：分数来源明确，不像向量检索那样"黑箱"

**面试话术**：「BM25 的失效场景很清楚 —— **查询和文档没有词面重叠时**（同义改写、跨语言）。这正好是稠密检索的强项，所以两者要混合。」
:::

## 3. 稠密检索（双塔 + 对比学习）

:::card 基本框架
```
query  → Encoder_q → q_vec  ┐
                            ├→ 相似度（通常余弦或点积）→ top-k
doc    → Encoder_d → d_vec  ┘
```
**为什么用双塔**：doc 向量可以**离线预计算**并建 ANN 索引 → 检索时只编码 query，一次前向 + 一次 ANN 查询 → 能扫百万/亿级文档。

**训练目标**：对比学习（InfoNCE）
```
L = − log [ exp(sim(q, d⁺)/τ) / Σ_{d ∈ {d⁺} ∪ D⁻} exp(sim(q, d)/τ) ]
```
关键在 **`D⁻` 怎么选** —— 这就是不同方法的核心差异。
:::

:::card 难负样本的三种层次（这个框架能串起所有方法）
| 层次 | 负样本来源 | 难度 | 代表 |
|---|---|---|---|
| **① batch 内负样本**（in-batch negatives） | 同一 batch 里其他 query 的正例 | 低（大多是简单负例） | 早期双塔（DPR） |
| **② 全局负样本**（从全库挖） | 用当前模型检索全库，取"高相似但非正例"的 | **高（难负例）** | **ANCE** |
| **③ 人工/模型挖掘的难负例** | 用更强模型（cross-encoder）标注 | 最高 | 蒸馏类方法 |
:::

## 4. Contriever vs ANCE（**必须讲准，你的论文两个都用过**）

:::card Contriever：无监督对比学习
**核心问题**：没有标注的 (query, doc) 对时怎么训？

**做法**：**从文档自身构造伪正例**
- 取一篇文档，用两个**不同的片段/视角**编码，作为正例对（原始论文用的是"逆完形填空"式构造：从同一文档里取两段独立上下文）
- 负例用 **batch 内负样本**
- 用 InfoNCE 训练，**完全不需要标注数据**

**关键特点**：**无监督**、泛化好、是零样本检索的强基线。**缺点**：负样本只有 batch 内的简单负例，学不到"细微区分"。
:::

:::card ANCE：用全库 ANN 挖难负样本
**核心问题**：batch 内负样本太简单 —— 模型只需学会"区分随机文档"，学不会"区分相似文档"。

**做法（一句话）**：
> **用当前模型去检索全库，取"高分但不是正确答案"的文档当负样本。**

具体三个要点：
1. **负样本来自全局**（不是 batch 内）→ 难度高得多
2. **负样本随训练动态变化**：模型变强 → 挖到的负例更难（**难例在"进化"**）
3. **异步索引刷新**：全库 ANN 索引不能每步重建（太贵），所以训练时用**稍旧的索引**异步更新 → 这也是 "A"（Approximate/Asynchronous）的来源

**代价**：需要维护全库索引 + 定期重建 → 工程复杂、显存/存储开销大。
:::

:::card 两者的核心对比表（**这张表要能脱口而出**）
| 维度 | **Contriever** | **ANCE** |
|---|---|---|
| 是否需要标注 | ❌ 不需要（无监督） | ✅ 通常需要（有监督训练） |
| 正例怎么来 | 从**同一文档的两个片段**构造 | 真实 (query, doc) 标注对 |
| 负例怎么来 | **batch 内负样本** | **全库 ANN 挖出的高相似负样本** |
| 负例难度 | 低（简单负例） | **高（难负例，且随训练进化）** |
| 训练开销 | 小（普通对比学习） | 大（要维护/刷新全库索引） |
| 优势 | 零标注可用、泛化好 | 区分细微差异能力强、检索精度高 |
| 一句话 | 「**无监督 + 简单负例**」 | 「**有监督 + 全库难负例**」 |

**你论文里能讲的话**：「我在四个检索器上做了全语料评测 —— BM25（稀疏基线）、Contriever（无监督稠密）、Contriever-MS（多语版本）、ANCE（难负样本稠密）。**这个组合正好覆盖了'稀疏 vs 稠密'和'简单负例 vs 全库难负例'两个维度**，所以能验证方法对检索器不敏感。」
:::

## 5. 混合检索与 RRF

:::card 为什么混合
BM25 和稠密检索的**失效场景互补**：
- BM25 失效：无词面重叠（同义、跨语言）
- 稠密失效：精确匹配（编号、罕见词、专有名词）

**融合方法**：
| 方法 | 做法 | 特点 |
|---|---|---|
| **RRF（Reciprocal Rank Fusion）** | `score = Σ 1/(k + rank_i)`（k 常取 60） | **只用排名不用分数** → 免调参、鲁棒 |
| 分数加权 | `α·s_bm25 + (1−α)·s_dense` | 需要归一化和调参，分数尺度不同时不稳定 |

**为什么 RRF 更常用**：不同检索器的分数**量纲不同**（BM25 是无界正数，余弦是 [-1,1]），直接加权需要归一化且对分布敏感；**只用排名就没有这个问题**。
:::

## 6. Reranker（cross-encoder）

:::card 和双塔的对比（和 5.1 呼应，这里给实现细节）
| | 双塔 bi-encoder | **cross-encoder** |
|---|---|---|
| 输入 | query、doc 分别编码 | **拼接后一起编码** |
| 交互 | 只有最后向量内积 | **每个 token 对都能交互** |
| 可预计算 | ✅ doc 向量离线存 | ❌ 必须在线算 |
| 速度 | 快（ANN） | 慢（每对一次前向） |
| 角色 | **召回** | **精排** |

**标准两段式**：双塔召回 top-100 → cross-encoder 精排取 top-5。

**面试追问准备**：「为什么不直接用 cross-encoder？因为它的成本是 `候选数 × 一次前向`，只能对几十上百个候选做；全库几百万不可能。」
:::

## 7. 查询侧优化（四种，按场景选）

:::card 逐个说清"什么时候用"
| 方法 | 做法 | 什么时候用 | 风险 |
|---|---|---|---|
| **查询改写** | 同义扩展、术语规范化、去掉口语词 | 用户表述与文档表述差异大 | 改错意图 |
| **HyDE** | 先让 LLM 生成一个"假想答案"，用它的向量去检索 | **问题很短、信息量少**（如"X 是什么"） | 假答案引入偏差 |
| **多查询（multi-query）** | 生成 3–5 个变体，各自检索后融合 | 表述歧义、需要覆盖多个角度 | 成本 ×k |
| **查询分解（decomposition）** | 把复杂问题拆成子问题分别检索 | **多跳、多约束**的问题 | 分解错了全歪 |
:::

:::card HyDE 为什么有效（直觉）
短 query 的向量和长文档的向量**分布不对齐**（长度、风格差异大）。HyDE 用 LLM 生成一段"看起来像答案的文档"，让它落在**文档分布**里，从而更容易匹配到真文档。
**一句话**：「HyDE 是"**用生成的假文档去对齐真文档的分布**"。」
:::

## 8. 多跳检索

:::card 两个代表思路
**IRCoT（Interleaved Retrieval with CoT）**
- 做一步推理 → 用推理出的中间结论当新 query 检索 → 再推理
- 本质是**检索与思维链交替**（与 ReAct 同源思路）

**Self-Ask**
- 模型自己提出子问题 → 检索 → 回答子问题 → 组合
- 本质是**显式分解 + 逐步检索**

**共同点**：都不指望"一次 query 拿到所有证据"，而是**用上一跳的结果驱动下一跳**。
**和你的项目的对应**：你的"证据状态驱动多轮检索"就是这条线上的（见 2.3）。
:::

## 9. 十个追问预答

:::qa BM25 的三个关键设计各解决什么
IDF（罕见词权重大）、tf 饱和 `k₁`（防关键词堆砌）、长度归一化 `b`（防长文档系统性占优）。
:::

:::qa BM25 为什么至今打不倒
精确匹配无可替代（编号/人名/术语）、零训练成本、可解释稳定。它的失效场景（无词面重叠）正好是稠密检索的强项。
:::

:::qa Contriever 和 ANCE 的核心区别
- **Contriever**：无监督，正例由**同一文档的两个片段**构造，负例是 **batch 内**简单负例
- **ANCE**：有监督，负例来自**全库 ANN 检索出的高相似非正例**（难负例，且随训练进化），需要异步刷新索引

一句话：「Contriever 是**无监督 + 简单负例**，ANCE 是**有监督 + 全库难负例**。」
:::

:::qa 为什么难负样本重要
batch 内负例大多和 query 毫不相关，模型只需学会"区分随机文档"；真正难的是"区分语义相近但不对的文档"。ANCE 的贡献就是系统性地挖这类负例。
:::

:::qa ANCE 的"全库索引"为什么贵
每个训练步都要用当前模型检索全库来挖负例，而全库 ANN 索引重建成本高，所以只能异步刷新（用稍旧的索引）→ 引入 staleness，也带来工程复杂度。
:::

:::qa RRF 是什么？为什么比分数加权稳
`score = Σ 1/(k + rank)`，只用排名。因为不同检索器分数量纲不同（BM25 无界、余弦 [-1,1]），加权需要归一化且对分布敏感；用排名免调参。
:::

:::qa 双塔和 cross-encoder 的本质区别
双塔**分别编码**（可预计算、快、只需向量内积），交互信息少；cross-encoder **拼接后编码**（token 级交互、精度高），但每对都要一次前向，只能精排。
:::

:::qa HyDE 的原理和风险
用 LLM 先生成"假想答案"，用它编码去检索 —— 目的是让 query 向量落在**文档分布**里（短 query 与长文档分布不对齐）。风险是假答案带来偏差，问题很具体/事实性强的场景可能更差。
:::

:::qa 什么时候该用查询分解
多跳问题（答案依赖中间实体）、多约束问题（同时问两件事）。分解错误会让后续检索全歪，所以要有"分解后自检"（每个子问题是否能独立检索）。
:::

:::qa 你的论文为什么选这四个检索器
覆盖两个维度：**稀疏 vs 稠密**（BM25 vs Contriever/ANCE）、**简单负例 vs 全库难负例**（Contriever vs ANCE），外加 Contriever-MS 的多语版本。这样能验证方法对检索器选择不敏感。
:::

## 10. 陷阱

| ❌ 别这么说 | ✅ 换成这么说 |
|---|---|
| 「BM25 是过时技术」 | 「BM25 在**精确匹配**上无可替代，是必须保留的基线/互补召回路」 |
| 「稠密检索全面优于 BM25」 | 「两者失效场景**互补**，所以要混合检索 + RRF」 |
| 「Contriever 和 ANCE 都是对比学习所以差不多」 | 「差别在负例：**batch 内 vs 全库难负例**；ANC E 还要异步刷索引」 |
| 「top-k 越大越好」 | 「越大噪声越多；要配合 rerank 与去重，用**信噪比**判断」 |
| 「混合检索要调权重」 | 「用 RRF 只用排名，**免调参且更稳**」 |

## 11. 自测（6 题）

:::qa 写出 BM25 的核心结构，说明 k₁ 和 b 的作用
`Σ IDF(t)·tf·(k₁+1)/(tf + k₁(1−b+b·|d|/avgdl))`。k₁ 控 tf 饱和（防堆砌），b 控长度归一化（防长文档占优）。
:::

:::qa 稠密检索为什么必须用双塔
因为 doc 向量要**离线预计算**并建 ANN 索引；cross-encoder 无法预计算，扫全库成本不可接受。
:::

:::qa Contriever 怎么在没有标注的情况下训
从**同一文档的两个片段**构造伪正例 + batch 内负例，用 InfoNCE 做无监督对比学习。
:::

:::qa ANCE 的两个关键点
① 负样本来自**全库 ANN 检索**（高相似非正例，难负例随训练进化）；② **异步刷新索引**（全库索引太贵，不能每步重建）。
:::

:::qa RRF 公式和它相对分数加权的优势
`Σ 1/(k+rank_i)`。只用排名 → 免调参、不受各检索器分数量纲差异影响。
:::

:::qa 你的四检索器组合覆盖了哪两个维度
稀疏 vs 稠密（BM25 vs Contriever/ANCE）、简单负例 vs 全库难负例（Contriever vs ANCE）。
:::
