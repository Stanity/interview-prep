## 1. Scaled Dot-Product Attention（含 mask 与数值稳定）

```python
import math, torch

def attention(q, k, v, mask=None):
    """q: (B,H,Lq,D)  k,v: (B,H,Lk,D)  mask: (B,1,Lq,Lk) bool，True=可见"""
    d = q.size(-1)
    scores = q @ k.transpose(-2, -1) / math.sqrt(d)      # (B,H,Lq,Lk)
    if mask is not None:
        scores = scores.masked_fill(~mask, float("-inf"))  # 关键：用 -inf 而不是 0
    attn = torch.softmax(scores, dim=-1)                  # softmax 内部会减 max，天然数值稳定
    return attn @ v
```

:::card 3 个常见写错点
1. **mask 用 0 而不是 `-inf`**：softmax(0)=1 反而会给被遮位置**很大权重**。必须 `masked_fill(-inf)` 或 `-1e9`。
2. **忘了除 `sqrt(d)`**：导致 softmax 饱和、梯度消失（见 4.1）。
3. **`masked_fill` 用了 `mask` 而不是 `~mask`**：取决于 mask 的语义（True=可见 还是 True=遮住），这是最容易反的地方 —— **面试时先说明你的约定**。
:::

**追问**：`-inf` 会不会导致 NaN？→ 如果**整行都被 mask**（全 `-inf`），softmax 就是 NaN。所以要么保证每行至少一个可见位置，要么用 `-1e9`（有限值）更稳。

## 2. 多头注意力 + KV Cache（含形状推导）

```python
import torch, torch.nn as nn

class MHA(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        assert d_model % n_heads == 0
        self.h, self.dh = n_heads, d_model // n_heads
        self.wq = nn.Linear(d_model, d_model)
        self.wk = nn.Linear(d_model, d_model)
        self.wv = nn.Linear(d_model, d_model)
        self.wo = nn.Linear(d_model, d_model)

    def forward(self, x, kv_cache=None):
        B, L, _ = x.shape
        q = self.wq(x).view(B, L, self.h, self.dh).transpose(1, 2)   # (B,H,L,dh)
        k = self.wk(x).view(B, L, self.h, self.dh).transpose(1, 2)
        v = self.wv(x).view(B, L, self.h, self.dh).transpose(1, 2)

        if kv_cache is not None:            # decode 阶段：拼上历史
            k = torch.cat([kv_cache[0], k], dim=2)   # (B,H,L_past+L,dh)
            v = torch.cat([kv_cache[1], v], dim=2)

        out = attention(q, k, v, mask=causal_mask(L, k.size(2), x.device))
        out = out.transpose(1, 2).reshape(B, L, -1)                  # (B,L,d_model)
        return self.wo(out), (k, v)         # 返回新的 cache
```

:::card 3 个常见写错点
1. **`view` 与 `transpose` 顺序错**：必须先 `view(B,L,H,dh)` 再 `transpose(1,2)` → `(B,H,L,dh)`；直接 `view(B,H,L,dh)` 会把数据切错（因为内存布局是按 `(B,L,H,dh)` 排的）。
2. **KV cache 只存当前步**：应该 `cat` 上历史，且**返回更新后的 cache**。
3. **有 cache 时 causal mask 算错**：`Lq=1`（decode）时 mask 应全为可见；`Lq=L`（prefill）时是下三角。
:::

:::card KV cache 形状与大小（会被追问）
```
cache_k / cache_v : (B, n_kv_heads, L_total, d_head)
单序列字节数 = 2 × layers × n_kv_heads × d_head × L × bytes
```
**GQA 就是把 `n_kv_heads` 从 `h` 降到 `g`** —— 代码上体现在 `wk/wv` 的输出维度是 `g*dh` 而不是 `h*dh`，`q` 仍然按 `h` 分头，然后在 attention 前把 k/v **repeat 到 h 组**。
:::

**追问**：decode 时为什么要 cache？→ 因为 K/V 只依赖历史 token，算过就不该重算；不 cache 的话每生成一个 token 都要把前面全部重算一遍（O(L²) → O(L)）。

## 3. RMSNorm + 残差

```python
import torch, torch.nn as nn

class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.w = nn.Parameter(torch.ones(d))     # 只有缩放，没有平移
        self.eps = eps

    def forward(self, x):
        # x: (..., d)
        rms = x.pow(2).mean(dim=-1, keepdim=True).add(self.eps).rsqrt()
        return x * rms * self.w

class Block(nn.Module):          # Pre-LN 结构
    def __init__(self, d, attn, ffn):
        super().__init__()
        self.n1, self.n2 = RMSNorm(d), RMSNorm(d)
        self.attn, self.ffn = attn, ffn
    def forward(self, x):
        x = x + self.attn(self.n1(x))     # 注意顺序：先 norm 再进子层
        x = x + self.ffn(self.n2(x))
        return x
```

:::card 3 个常见写错点
1. **写成 `self.n1(x + attn(x))`**：那是 **Post-LN**（归一化在残差之后），训练更不稳定。
2. **忘了 `keepdim=True`**：`mean(-1)` 会把最后一维消掉，广播时维度对不上。
3. **把 `eps` 加在 sqrt 外面**：应该是 `sqrt(mean + eps)`，且用 `rsqrt()`（即 `1/sqrt`）。
:::

**追问**：为什么 RMSNorm 不减均值也能工作？→ LLM 隐状态均值接近 0（尤其残差累加后），中心化贡献小；关键是"按幅度归一化"。效果相当但更快、参数更少（见 4.1）。

## 4. LoRA 层（前向 + 初始化）

```python
import torch, torch.nn as nn

class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, r=8, alpha=16, dropout=0.0):
        super().__init__()
        self.base = base
        for p in self.base.parameters():
            p.requires_grad = False                     # 冻结原权重
        d_out, d_in = base.weight.shape
        self.A = nn.Parameter(torch.empty(r, d_in))     # (r, d_in)
        self.B = nn.Parameter(torch.zeros(d_out, r))    # (d_out, r) ← 置零！
        nn.init.kaiming_uniform_(self.A, a=5 ** 0.5)
        self.scaling = alpha / r
        self.drop = nn.Dropout(dropout)

    def forward(self, x):
        return self.base(x) + self.scaling * (self.drop(x) @ self.A.T @ self.B.T)
```

:::card 3 个常见写错点
1. **A、B 都随机初始化** → 训练起点就扰动了模型。**B 必须置零**（`ΔW = BA = 0`）。
2. **忘了 `requires_grad_(False)`** → 基座也被训练，显存/效果都不是 LoRA 了。
3. **scaling 写成 `alpha` 而不是 `alpha / r`** → 改 r 时等效学习率跳变。
:::

**追问**：参数量怎么算？→ 单个 `d×k` 矩阵引入 `r(d+k)`。4096×4096、r=8 → 65.5K，占 0.39%。

## 5. 增量 decode 的 KV Cache 更新

```python
@torch.no_grad()
def generate(model, input_ids, max_new=100, eos_id=None):
    past = None                       # None 表示 prefill
    cur = input_ids                   # (B, L)
    for _ in range(max_new):
        logits, past = model(cur, kv_cache=past)   # prefill: L个token；decode: 1个token
        next_id = logits[:, -1:].argmax(-1)        # (B,1)
        cur = next_id                              # 下一步只喂 1 个 token
        if eos_id is not None and (next_id == eos_id).all():
            break
    return cur
```

:::card 3 个常见写错点
1. **decode 时还喂全序列** → 每步重算历史，复杂度回到 O(L²)，加速完全失效。
2. **忘了把更新后的 cache 接回去**（`past = new_past`）→ 每次都从零开始。
3. **位置编码位置错**：decode 第 t 步的位置应该是 `past_len + 1`，用错会导致 RoPE 角度错位（长文本下表现明显）。
:::

**追问**：为什么 decode 是 memory-bound？→ 每步只算 1 个 token，却要把全部权重和 KV 从显存读一遍，算术强度 ≈1 FLOP/byte（见 4.4）。

## 6. Top-k / Top-p 采样

```python
import torch

def sample(logits, temperature=1.0, top_k=0, top_p=0.0):
    """logits: (V,) 或 (B,V)"""
    logits = logits / max(temperature, 1e-6)

    if top_k > 0:
        kth = torch.topk(logits, top_k).values[..., -1, None]
        logits = logits.masked_fill(logits < kth, float("-inf"))

    if top_p > 0:
        sorted_logits, idx = torch.sort(logits, descending=True)
        probs = torch.softmax(sorted_logits, dim=-1)
        cum = torch.cumsum(probs, dim=-1)
        # 保留"累积首次达到 p"的最小集合：把 cum - prob > p 的（即超出部分）删掉
        sorted_logits = sorted_logits.masked_fill(cum - probs > top_p, float("-inf"))
        logits = torch.full_like(logits, float("-inf")).scatter(-1, idx, sorted_logits)

    probs = torch.softmax(logits, dim=-1)
    return torch.multinomial(probs, num_samples=1)
```

:::card 3 个常见写错点
1. **top-p 的边界写错**：应该是 `cum - prob > p` 才删（保留让累积刚好跨过 p 的那一个 token）。写成 `cum > p` 会把关键的边界 token 也删掉。
2. **先 softmax 再排序**（等价但要注意 dtype/精度）；更稳的是**在 logits 域做 mask，最后再 softmax**。
3. **顺序错**：temperature 必须在 top-k/top-p **之前**（先缩放分布形状再截断）。
:::

**追问**：top-k 和 top-p 能同时用吗？→ 能，取交集（先按个数限，再按概率质量限）。

## 7. DPO Loss

```python
import torch, torch.nn.functional as F

def dpo_loss(policy_chosen_logps, policy_rejected_logps,
             ref_chosen_logps, ref_rejected_logps, beta=0.1):
    """入参都是 (B,) 的序列 logprob 之和"""
    pi_logratio = policy_chosen_logps - policy_rejected_logps        # 当前策略的标签间优势
    ref_logratio = ref_chosen_logps - ref_rejected_logps             # 参考模型的优势（基线）
    logits = beta * (pi_logratio - ref_logratio)                     # ← 核心
    loss = -F.logsigmoid(logits).mean()
    # 附带的指标：隐式奖励
    chosen_rewards = beta * (policy_chosen_logps - ref_chosen_logps).detach()
    rejected_rewards = beta * (policy_rejected_logps - ref_rejected_logps).detach()
    return loss, chosen_rewards, rejected_rewards
```

:::card 3 个常见写错点
1. **忘了减 `ref` 项** → 变成普通 pairwise ranking，失去 DPO 的 KL 约束含义。
2. **`beta` 放错位置**（比如放到 sigmoid 外面）→ 与推导不符。
3. **logprob 把 prompt 也算进去** → 应只累计 response 部分（和 SFT 的 loss mask 一个道理）。
:::

**追问 1**：为什么不需要 reward model？→ 因为最优策略有闭式解，反解出隐式奖励后 `Z(x)` 在相减时抵消（见 3.2）。
**追问 2**：你的 RePref-Fact 和这个什么关系？→ **数学同构**：`δθ(x)` 就是隐式奖励的差，只是把序列 logprob 换成了标签分数。

## 8. 简化 ReAct Loop

```python
def react_loop(task, tools, llm, max_steps=10, max_tokens=50_000):
    """
    tools: {name: {"fn": callable, "schema": dict}}
    llm(messages, tool_schemas) -> {"type": "tool"|"final", ...}
    """
    messages = [{"role": "user", "content": task}]
    used_tokens = 0

    for step in range(max_steps):
        if used_tokens > max_tokens:
            return {"status": "budget_exhausted", "messages": messages}

        out = llm(messages, [t["schema"] for t in tools.values()])
        used_tokens += out.get("tokens", 0)
        messages.append({"role": "assistant", **out})

        # ① 终止：模型给出最终答案
        if out["type"] == "final":
            return {"status": "done", "answer": out["content"], "messages": messages}

        # ② 校验：工具必须存在（防工具名幻觉）
        name = out.get("name")
        if name not in tools:
            messages.append({"role": "tool", "content": f"unknown tool: {name}. "
                             f"available: {list(tools)}"})
            continue

        # ③ 执行：归一化错误，让模型有机会自愈
        try:
            result = tools[name]["fn"](**out.get("args", {}))
            obs = {"ok": True, "data": str(result)[:2000]}
        except Exception as e:
            obs = {"ok": False, "error": type(e).__name__, "detail": str(e)[:500]}
        messages.append({"role": "tool", "content": str(obs)})

    return {"status": "max_steps", "messages": messages}   # ④ 预算/步数终止
```

:::card 3 个常见写错点
1. **没有预算/步数上限** → 死循环烧 token（真实事故）。
2. **错误直接抛出去** → 整个流程崩；应**归一化成结构化观察**回传给模型（这是"自愈"的关键）。
3. **不校验工具名/参数** → 模型幻觉出 `delete_all` 这种工具，如果没有白名单就可能出事。
:::

**追问**：还缺什么？→ 缺 ① 动作去重（防振荡）② 状态快照（断点恢复）③ trace 记录 ④ 高危工具人工确认。**主动说出这四个缺口，比写一个"完美"的 loop 更可信。**

## 自测（不看代码，说出每题的关键点）

:::qa attention 为什么 mask 要用 -inf 而不是 0
softmax(0)=1，会给被遮位置很大权重；`-inf` 才能让它变 0。且要注意整行全 `-inf` 会产生 NaN。
:::

:::qa MHA 里 view/transpose 的顺序为什么重要
内存布局是 `(B,L,H,dh)`，必须先 `view(B,L,H,dh)` 再 `transpose(1,2)` 得到 `(B,H,L,dh)`；直接 `view(B,H,L,dh)` 会把数据切错。
:::

:::qa LoRA 为什么 B 要置零
保证训练开始 `ΔW = BA = 0`，模型行为与原模型一致（无损起步、训练稳定、可关闭）。
:::

:::qa decode 时喂错输入会发生什么
如果仍喂全序列，每步都重算历史 → 复杂度回到 O(L²)，KV cache 的收益完全消失。
:::

:::qa top-p 的边界为什么是 `cum - prob > p`
保留让累积概率**刚好跨过 p** 的那个 token；用 `cum > p` 会把边界 token 删掉导致候选过少。
:::

:::qa DPO loss 里减 ref 项的作用
提供基线（参考模型的标签间优势），使目标变成"相对参考模型扩大间隔"，同时隐含 KL 约束。
:::

:::qa ReAct loop 最少要有哪四样东西
步数/token 上限（预算）、工具白名单校验、错误归一化回传、终止判定。
:::
